# Events emitted at `warn`+ that no test reads. **It only shrinks.** A line
# removed is a cell filled; a line added is a regression argued in review, never
# absorbed by a flag.
#
# What is left is no longer a work list. Every line below has been *tried* and is
# recorded with the fact that makes it unreachable, because
# `.claude/rules/testing.md` asks that a cell whose emptiness is a decision be
# written down as one — and because "impossible" and "not yet done" are two
# different sentences.
#
# **Each reason names something a reader can check**, and that is the standard
# this file is held to rather than a nicety: four of these once named a type or
# a function that does not exist in the repo, which is a claim a reviewer cannot
# refute and therefore cannot trust. If a refactor makes one of these reachable,
# the claim is wrong and the cell is owed a test — re-reading this file at review
# time is what that is for.

# ── nest_rs::orm
# The boundary hands out its opened `Arc<DatabaseTransaction>` through exactly
# one accessor, `LazyTransaction::into_opened`, and that accessor **consumes the
# boundary** — so a live handle and a `finalize` that could report on it cannot
# coexist. (It is public and called from outside the crate; "never lends it out"
# was the wrong fact. Reaching this branch takes the private `cell` field, which
# is cloned nowhere.) The shape a handler *can* produce — leaking the `Executor`
# — is caught one branch earlier as `executor escaped into a spawned task`, and
# `interceptor::an_escaped_transaction_fails_an_otherwise_successful_response`
# covers it.
nest_rs::orm :: transaction escaped into a spawned task

# ── nest_rs::authn
# The challenge is built from the resource URI, the metadata URL and
# `scopes_supported`, and `into_metadata` — the one production path — rejects
# `is_ascii_control() || '"' | '\' | ' '` in each (`validate_canonical_uri` and
# its scope twin in `resource/config.rs`). That is exactly the set
# `HeaderValue::from_str` refuses; every non-ASCII character encodes to bytes
# ≥ 0x80, all accepted. Checked by sweeping U+0000..U+2FFFF through both the
# resource and an advertised scope: none reaches the branch. Its
# insufficient-scope twin *is* covered, because a scope there arrives from a
# guard rather than from config.
nest_rs::authn :: protected resource challenge is not a valid header value
# `ProtectedResourceMetadata` is `String`s and `Vec<String>`s, and `serde_json`
# is built without `arbitrary_precision`: no manual `Serialize`, no `flatten`,
# no non-string key, nothing that can fail.
nest_rs::authn :: protected resource metadata failed to serialize
# Not a serialization — the odd one out in this file, filed here because the
# outcome is the same. `argon2 0.5.3` returns `Err` for six reasons, and the
# call hashes a 19-byte compile-time constant with the crate's defaults: too
# long (> 4 GiB), a salt outside 4..64 (`SaltString::generate` gives 22), a
# secret (none passed), an output length outside 4..=64 (32), and too little
# memory (19456 KiB).
nest_rs::authn :: timing dummy hash failed to initialize — absent-account burn degrades to no-op

# ── nest_rs::layers
# `serde_json::to_vec` over a `serde_json::Value`. The type cannot hold a state
# that fails to serialize — `Number::from_f64` refuses NaN and ±Inf at
# construction, object keys are always `String` — and the `Value` here came from
# `from_slice`, whose recursion limit is 127, so a hostile body cannot even
# build a deep one (and that failure takes the `debug` "not valid JSON" branch
# instead).
nest_rs::layers :: global pipe: failed to re-serialize the transformed body

# ── nest_rs::ws
# The same shape: `WsEnvelope { event: String, data: serde_json::Value }`. This
# is the *connection loop* serializing the outgoing frame, whose two members are
# a `String` and a `Value` the dispatcher already built.
#
# Its **reachable** twin — `WsReply::reply`, which serializes a handler's own
# return type — was a live gap when this line landed, and is closed: it routes
# through `Opaque` like every other failure on the edge, so the operator gets
# the cause and the client gets `OPAQUE_CLIENT_MESSAGE`. It never appeared in
# this population and could not have, since the join indexes `warn!`/`error!`
# and the seam it now calls owns the macro. Asserted by
# `envelope::tests::a_reply_that_cannot_be_serialized_tells_the_operator_and_not_the_client`.
nest_rs::ws :: failed to serialize reply
# Fires only on `JoinError::is_panic` from the writer task, whose whole body is
# `rx.recv()`, `Arc<str>::to_string()` and `sink.send()`. No panicking site of
# its own; only an internal panic in poem or tungstenite reaches it.
nest_rs::ws :: writer task failed

# ── nest_rs::app
# `tokio::signal::unix::signal` returns `Err` for one reason a process can
# arrange — a refused signal number — and the call sites hard-code
# `SignalKind::terminate()`. The other misconfiguration, a runtime built without
# the signal driver, **panics** rather than returning `Err`.
nest_rs::app :: failed to install SIGTERM handler
# Stronger than an environment claim: this line sits under `#[cfg(not(unix))]`,
# so it is never compiled here at all. It appears in the population because the
# scan reads the source with `syn`, which is blind to `cfg` — a limit of the
# join worth knowing, and the reason a `cfg`-gated event cannot simply be
# filtered out of the family.
nest_rs::app :: failed to install ctrl-c handler

# ── nest_rs::health
# `ProbeReport` is an `IndicatorStatus` plus three `BTreeMap<&'static str,
# IndicatorReport>`; `IndicatorReport` is a status and two `Option<String>`s.
# All `serde`-derived, all string-keyed.
nest_rs::health :: health report failed to serialize
