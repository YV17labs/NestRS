import { Aside } from '@astrojs/starlight/components';

If NestJS shaped how you think about backends, most of NestRS will read like
home. You still write a module, a service, a thin controller, and let
decorators carry the wiring. This page maps the vocabulary you already know
onto its NestRS equivalent; [what runs
differently](/coming-from-nestjs/what-runs-differently/) is where the machine
underneath diverges.

```rust title="crates/features/src/users/http/controller.rs"
#[controller(path = "/users")]
#[use_guards(AuthnGuard, AuthzGuard)]
pub struct UsersController {
    #[inject]
    svc: Arc<UsersService>,
}

#[routes]
impl UsersController {
    #[get("/{id}")]
    #[authorize(Read, bind = UsersService)]
    async fn get(&self, user: Authorized<Read, UserEntity>) -> Json<User> {
        Json(User::from(&*user))
    }
}
```

A `@Controller('users')` with an injected service and a `@Get(':id')` — the
shape survives the port to Rust. The decorators changed spelling, not meaning.

## The equivalence table

Each row is a reflex you already have on the left and its NestRS spelling on
the right. The layer vocabulary — module, provider, controller, guard,
resolver — carries across intact.

| NestJS | NestRS |
|---|---|
| `@Module({ imports, providers })` | `#[module(imports = [...], providers = [...])]` |
| `@Module({ controllers: [...] })` | the same `providers` list, which holds the controllers too |
| `@Injectable()` | `#[injectable]` |
| `@Controller('users')` | `#[controller(path = "/users")]` |
| `@Get()` / `@Post()` methods | `#[get("/")]` / `#[post("/")]` in a `#[routes] impl` |
| `@Get(':id')`, `@Get('files/*path')` | `#[get("/{id}")]`, `#[get("/files/{*path}")]` — OpenAPI's [path templating](/http/controllers/#route-templates), the spelling the document prints |
| `CanActivate` guard | `Guard` trait (`check`, and `check_http` where the request differs) + `#[use_guards(...)]`; `ExecutionContext` is the `UnitContext` both entries take |
| DTO + `class-validator` | entity `#[expose]` + `validate(...)` (the `validator` crate) |
| `@Param('id')` / `@Query()` / `@Body()` | the parameter type: `Path<Uuid>`, `Query<F>`, `Json<T>` |
| `@ApiProperty()` / `@Field()` per property | one `#[expose]` on the column, schemas derived |
| `@Inject('TOKEN')` provider token | inject `Arc<dyn Trait>`, provider listed `as dyn Trait` |
| `@UseGuards(...)` | `#[use_guards(...)]` |
| `@UseInterceptors(...)` | `#[use_interceptors(...)]` |
| `@UseFilters(...)` (binds `@Catch(...)` classes) | `#[use_exception_filters(...)]`; `@Catch(T)` is `type Exception = T`, and `@Catch()` with no argument is `type Exception = dyn Error + Send + Sync` |
| `APP_GUARD` | `GlobalGuards<(RequireApiKey,)>` in the providers of the module the app boots |
| `APP_INTERCEPTOR` | `GlobalInterceptors<(…)>` in the module the app boots; around the guards, `#[interceptor(stage = unit)]`, which its module's import brings |
| `APP_FILTER`, `APP_PIPE` | `GlobalExceptionFilters<(…)>`, `GlobalPipes<(…)>` in the module the app boots |
| an `HttpException` whose body carries an error code | a `nest_rs::core::Problem` and its `Code`, which every edge renders in its own form |
| `AsyncLocalStorage`, `nestjs-cls` | the [ambient context](/fundamentals/execution-context/#what-a-unit-carries): `cx.attach(value)` in a layer, `ambient::<T>()` anywhere the unit reaches |
| `@Resolver()` operation | `#[operations]` + per-op `#[authorize(Action, Entity)]` / `#[public]` |
| `OnModuleInit` interface | `#[hooks] impl` + `#[on_module_init]` on the method |
| Hooks run by DI level, each level at once (`Promise.all`) | dependencies first, one hook at a time, and shutdown in exact reverse ([order](/fundamentals/lifecycle/#ordering-and-failure)) |
| `onModuleDestroy()` / `beforeApplicationShutdown(signal)`, run before the server closes | `#[on_module_destroy]` / `#[before_application_shutdown]`, run once every transport has drained; work due at the signal waits on `stopping()` on an injected `Arc<AppLifecycle>` ([why](/fundamentals/lifecycle/#the-five-phases)) |
| `onApplicationShutdown(signal)` | `#[on_application_shutdown]`; the signal is `cause()` on an injected `Arc<AppLifecycle>` (`StopCause::Terminate`, `Interrupt`, …) |
| `ConfigModule.forRoot()` + `registerAs` | `#[config(namespace = "…")]` + `<PREFIX>_<NS>__<KEY>` |
| `XModule.forRootAsync({ useFactory })` | a config from `for_root`, the environment or a `_FILE`; a resource computed from another provider is a factory [reading `ConfigModule::resolved`](/extending/package/#a-resource-it-opens) |
| `ServeStaticModule.forRoot({ rootPath })` | `StaticFilesModule::for_root(StaticFilesConfig { root, .. })` — or `for_root(Embedded::of::<WebAssets>())` for a folder embedded in the binary |
| `@nestjs/resilience` | `#[resilient(field)]` under a [resilience policy](/fundamentals/resilience/) per dependency, and [`ResilienceMiddleware`](/fundamentals/resilience-middleware/) on your reqwest client; every capability is mapped [below](#resilience-capability-by-capability) |
| `Test.createTestingModule(...)` | `TestApp` booting the real `ApiModule` |
| `NestFactory.createApplicationContext(...)`, then `app.close()` | `App::builder()…build()`, `init()`, then `close()` ([running without serving](/fundamentals/app-state/#running-without-serving)) |
| `nest g resource users` | `nestrs g resource users` |
| Runtime DI resolution | access graph checked at boot, with a named error |

The rows are close, but four of them carry a design change worth reading in
full: what a module lists, provider visibility, when wiring is verified, and
where configuration comes from.

## A controller is a provider

`@Module({ controllers: [...], providers: [...] })` keeps two lists because a
NestJS controller is a different kind of citizen — not injectable, never
exported. NestRS keeps one. `#[module]` accepts exactly two keys, `imports` and
`providers`, and an unknown key is a compile error naming the two.

```rust title="crates/features/src/users/http/module.rs (from the demo)"
use nest_rs::core::module;

use super::controller::UsersController;
use crate::authz::AuthzModule;
use crate::users::UsersModule;

#[module(
    imports = [UsersModule, AuthzModule],
    providers = [UsersController],
)]
pub struct UsersHttpModule;
```

A controller, a resolver, a gateway, a queue processor and an MCP tool are all
providers: built by the same container, holding the same `#[inject]` fields,
resolved by the same access-graph check. What makes one an HTTP route table is
`#[controller]` + `#[routes]` — the decorator carries the transport, so the
module list has nothing left to say about it.

The payoff is per-binary composition. A transport mounts only when its module is
reachable from the running app's root — a listed host brings it, as
`UsersController` brings `HttpModule` — so one feature crate serves an API that
imports `UsersHttpModule` and `UsersGraphqlModule` and a worker that imports
neither. Dropping the import unmounts the routes, and there is no second list to
keep in sync with the first.

## Visibility is Rust's

In NestJS a provider is private to its module until you add it to `exports`,
and a consumer imports the whole module to reach it. In NestRS a provider
becomes shareable by exposing a `pub trait` and binding it in the module's
`providers` as `SomeProvider as dyn Trait`; a consumer then injects
`Arc<dyn Trait>`.

Visibility is Rust's job: the container is flat, and `pub` with the orphan and
coherence rules decides what a crate can name, the one gate.

## Wiring is checked at boot

NestJS resolves the dependency graph as the app instantiates. NestRS records
every module's imports and every provider's dependencies at compile time, and
at startup `App::builder().build()` walks that graph.

A provider that injects something its module cannot reach fails startup with an
error naming the missing dependency and the fix. If it **boots**, it's wired —
and it boots in milliseconds, so you find out immediately.

<Aside type="note">
  This is [property 5 in *Why NestRS*](/why/#5-wiring-verified-at-boot). The
  access graph and the exact boot error live on
  [Providers](/fundamentals/providers/).
</Aside>

## Every config field has an environment variable

In NestJS a knob lives in a `forRoot` literal in code or is read through
`configService.get('SOME_KEY')`, as each module chooses. In NestRS it is a
framework rule: every field of every `nest-rs-*` module config is reachable
both ways:

1. **Pinned in code** — `Module::for_root(MyConfig { .. })`, type-checked by
   the compiler.
2. **`<PREFIX>_<NAMESPACE>__<FIELD>`** — each field read under its own name,
   the overlay `#[config]` writes from the struct, so the struct lists exactly
   which variables exist.

The two compose **per field, not per struct**: the pinned struct is the *base*
the environment overlays. Pinning `compression` in `HttpConfig` leaves
`<PREFIX>_HTTP__PORT` free to move, and neither path erases the other.

"The environment" here is the **real process environment only**. A `for_root`
pin outranks every `.env` file committed beside the code — for its whole
namespace, and the boot names each key it shadows; it does not outrank a
variable actually present in the environment at startup — the full chain is on
[Pinning a config](/configuration/pinning/#the-dual-path-rule).

That is what pays off in a container. The image ships one binary with sane pins. The deployment then moves any
knob through the `env` block of a Compose file or a Kubernetes Deployment,
or through a Secret: no rebuild, no config file baked into a layer, no
override mounted at a path the process has to go find. A
malformed value is boot-fatal and names the variable, so a bad ConfigMap fails
the readiness probe instead of surfacing as a mystery three requests later.

<Aside type="note">
  The rule lives on [Pinning a config](/configuration/pinning/#the-dual-path-rule)
  and the struct-as-contract on
  [Configuration](/configuration/#why-the-struct-is-the-contract); every variable
  the framework reads is in the [env reference](/configuration/env-reference/).
</Aside>

## Resilience, capability by capability

`@nestjs/resilience` gathers its capabilities as decorators and a service;
NestRS carries them as keys of one decorator, `#[resilient(field, …)]`, on the
method making the call, under a policy per dependency. The field names the
policy, an `Arc<ResiliencePolicy<I>>` that `ResilienceModule<I>` builds, so an
app that forgets the import does not boot. The policy's settings are the
variables `<PREFIX>_RESILIENCE__<INSTANCE>__<KEY>`, `<PREFIX>_RESILIENCE__<KEY>`
for the default instance, or a `for_root` value; the keys below are written as
the variable's last segment. [Resilience](/fundamentals/resilience/), [Failures and fallbacks](/fundamentals/failures-and-fallbacks/)
and [Resilience events and reads](/fundamentals/resilience-events/) are the pages
to read in full.

The method's shape, with its keys written, is the first block of
[Failures and fallbacks](/fundamentals/failures-and-fallbacks/).

### The policy and its order

| `@nestjs/resilience` | NestRS | What NestRS does |
|---|---|---|
| `@Resilience(preset)`, `@Retry`, `@Timeout`, `@CircuitBreaker`, `@Bulkhead`, `@Fallback`, on a handler or a class | `#[resilient(field, …)]` on the method making the call: a provider's, or a handler of every edge but a WebSocket connection hook, which calls a decorated method | One decorator, on each method making a call, which names its policy. |
| `ResilienceService.preset(name)` / `create(options)`, `policy.execute(fn, { source })` | an injected `Arc<ResiliencePolicy<I>>`; `run` and `run_idempotent` for a call that is part of a method | A policy is named by a type and built from its variables or `for_root`, never inline. A call run by hand is told with no `host` and no `method`; a decorated method is told with its own, so a method that wants its name in an event is decorated. |
| `ResiliencePolicy.wrap(…)`, in any order | the one order: a call out of time or meeting an open breaker is refused before any wait for a slot, and the rate is read there too; then the bulkhead's slot, held for the whole run; then each attempt under the unit's deadline, the breaker, the rate and the timeout; the fallback answers once the run is over | One order. |
| `ResilienceContext.run(scope, fn)` | the unit's ambient `Deadline` | The deadline bounds every attempt and every wait; no attempt is ambient. |
| `ResilienceModuleOptions.defaults`, merged under every preset and decorator | `ResilienceConfig`'s defaults, and `ResilienceModule::for_root((Upstream, config))` for a base per instance | Each policy reads its own variables over its own base. |
| `name` on a breaker, a bulkhead or a limiter, and its name in a preset; unnamed, a decorator's breaker or bulkhead is its handler's | the policy | Its breaker, its bulkhead and its bucket are shared by every method naming it, and by those alone. A quota two dependencies share is a policy of its own, whose `run` goes around each call. |
| `ExecuteOptions.signal`, the caller's own cancellation | the caller drops the run's future | An attempt in flight is dropped with it and counts in neither direction; under a unit's deadline (a request, a job, a tick), one dropped past its bound counts as a timeout. A slot, a token or a probe's turn it held is given back. |

### Retries

| `@nestjs/resilience` | NestRS | What NestRS does |
|---|---|---|
| `retry.attempts` (the total, 3 by default, `Infinity`) | `RETRIES`, or `retries = N` on an `idempotent` method | Counts the sends after the first: `RETRIES` from 1 to 10, `0` for none, 2 by default; `retries` from 1 to 10. |
| `retry.backoff` (`delay`, `factor`, `maxDelay`, `jitter`, or a function) | `BACKOFF_FIRST_MS`, `BACKOFF_CEILING_MS` | One curve: doubling, with ±20 % of jitter. A `Retry-After` the dependency asks is waited whole; one past `BACKOFF_CEILING_MS` ends the run. |
| `retry.retryIf(error, attempt)` | `retry_if = F`, with `F: Fn(&E) -> bool`, on an `idempotent` method | Every `Err` is sent again unless `F` says no, a client error included, whatever its status. A timeout is sent again and read by no predicate. A refusal an inner policy answers, carried by the `Err` of an enclosing decorated method, is an `Err` like any other: an idempotent method sends it again, after the whole `Retry-After` an `Open` or a `Limited` carries and not at all past `BACKOFF_CEILING_MS`, and `retry_if` refuses it with a `matches!` on the error's own variant holding the `ResilienceError`, such as `\|error\| !matches!(error, PostError::Upstream(_))`. |
| `retry.retryOnResult(result, attempt)` | `retry_ok_if = F`, with `F: Fn(&T) -> bool`, on an `idempotent` method | A key of any `idempotent` method, a handler included. Once the retries are spent, the last `Ok` is the answer. |
| `idempotent`, else `GET`, `HEAD`, `OPTIONS` and GraphQL queries | `idempotent` on the decorator | Always written by the developer, for every method. `ResilienceMiddleware` reads RFC 9110 §9.2.2's methods, `QUERY` and `Idempotency-Key`. |
| a retry re-runs the pipes, the inner interceptors and the handler | a retry re-runs the method's body; inside a transaction, each attempt of an `idempotent` method, or of one naming a `fallback`, runs in a savepoint of it | The unit is not replayed. The writes of an attempt sent again, or ending on an error, are rolled back; a savepoint the database cannot settle ends the run on `ResilienceError::Unsettled`. |
| `@Timeout(d)`, per attempt | `TIMEOUT_MS`, or `timeout = "2s"` on a method, from `"1ms"` to `"10m"` | Every policy has a timeout, 5 seconds by default; the unit's deadline ends an attempt sooner. An attempt that an enclosing policy's timeout cuts counts as a timeout in its own breaker. |
| `@Signal()`, `AttemptContext.signal`, `ResilienceContext.signal` | `cancel = token` in a decorated method; the closure's argument in `run` and `run_idempotent` | The attempt's future is dropped at its bound, so the token is for work handed to another task. |
| `AttemptContext.attempt`, `ResilienceContext.attempt` | a count the call keeps itself | A body, a predicate and a fallback read the method's arguments, and no attempt number; the closure `run_idempotent` takes is an `FnMut`, which counts its own calls. |

### The circuit breaker

| `@nestjs/resilience` | NestRS | What NestRS does |
|---|---|---|
| `slidingWindow` of a `count` | `BREAKER_WINDOW` | The same count of outcomes, 20 by default; `0` turns the breaker off. |
| `slidingWindow` of a `time` of `A` | `BREAKER_AGE_SECS` of `A`, over a `BREAKER_WINDOW` of twice `minimumCalls` or more | An outcome is forgotten at its own age. The variable takes whole seconds; an age under a second is pinned through `for_root`. |
| `failureRateThreshold` `T` and `minimumCalls` `M` | `BREAKER_FAILURES`, of `⌈T × M / 100⌉` | The threshold is a count of failures, read when a failure is counted: the breaker opens at that many failures, whatever the answers between them. A threshold of 50 % after ten calls is a `BREAKER_FAILURES` of 5. The default, ten failures of twenty, is not that mapping: set `BREAKER_FAILURES` to carry a default breaker over. |
| `openDuration` | `BREAKER_OPEN_SECS` | The variable takes whole seconds, an hour at most. |
| `halfOpenMaxCalls`, sent together and judged by their rate | `BREAKER_PROBES`, in a row | Probes go one at a time; one failed probe opens the breaker again. |
| `recordIf(error)` | `record_if = F`, with `F: Fn(&E) -> bool` | An `Err` it refuses is counted in neither direction, and a probe hands its turn on. A refusal an inner policy answers, carried by the `Err` of an enclosing decorated method, is an `Err` like any other and counts as a failure; `record_if` refuses it with a `matches!` on the error's own variant holding the `ResilienceError`. |
| `breaker.state`, `breaker.stats` | `breaker_state()`, `breaker_stats()` (`outcomes`, `failures`, `failure_rate()` from 0 to 1) | The age is applied at the read. |
| `breaker.trip()`, `breaker.reset()` | `open_breaker(duration)`, `close_breaker()` | An opening says for how long. |
| `isClientError()` as the default filter | every `Err` a failure, unless `record_if` says otherwise | A client error is one too: the developer classifies. `ResilienceMiddleware` reads statuses. |

### The bulkhead and the rate

| `@nestjs/resilience` | NestRS | What NestRS does |
|---|---|---|
| `bulkhead.maxConcurrent`, `maxQueue`, `queueTimeout` | `CONCURRENCY`, `CONCURRENCY_WAITERS`, `CONCURRENCY_WAIT_MS` | Off by default. The slot is held for the whole run, its retries included. A call waits for a slot only where `CONCURRENCY_WAIT_MS` is set, from a millisecond to a minute, none by default, and `CONCURRENCY_WAITERS` bounds how many wait, `0` for no bound. `maxQueue: 0`, no queue, is `CONCURRENCY_WAIT_MS` left unset or `0`: a call finding every slot taken is refused at once. A `queueTimeout` is a `CONCURRENCY_WAIT_MS`, which bounds every wait for a slot. |
| `bulkhead.active`, `bulkhead.queued` | `concurrency_running()`, `concurrency_waiting()` | A call is in one of the two at any instant. |
| a rejection's `reason`, `active` and `queued` | the `Full` variant of `ResilienceError` | The error names neither a cause nor a count; the `debug` line's `waiters` and the two reads do. |
| `outboundRateLimit.limit`, `interval`, `maxWait`, a token bucket | `RATE_LIMIT`, `RATE_WINDOW_SECS`, `RATE_WAIT_MS`, a token bucket | Off by default. Counts attempts, a retry included. A token is waited for only when it comes within `RATE_WAIT_MS` and before the unit's deadline. A bucket left idle sends its whole limit at once, then a token at a time: up to twice the limit within one window's length. |
| `limiter.available` | `rate_available()` | The same. |

### The fallback

| `@nestjs/resilience` | NestRS | What NestRS does |
|---|---|---|
| `@Fallback(method or fn, { handleIf })` | `fallback = method`, `fallback_if = F`, with `F: Fn(&ResilienceError<E>) -> bool` | The method is one of `Self`, its signature checked: the decorated method's arguments, then the error by value, answering what the method answers. It answers every error, a client error and the policy's refusals included, unless `fallback_if` says no, and runs under no policy. The last attempt's savepoint is rolled back first; `ResilienceError::Unsettled` is never handed to it. A free function or a closure answers through a method of `Self` that calls it. |
| `preset.fallback` for `execute()` | `.or_else(…)` on the `Result` a run answers | The fallback is written at each call, against the `Result` that `run` answers, and its filter is a `match`. No line, event or counter says that a fallback answered. |
| `executeObservable`, committed once a value is emitted | `#[sse]` and `#[subscription]` | The policy runs the call that opens the stream, never the items it yields later. |

### Events, reads and errors

| `@nestjs/resilience` | NestRS | What NestRS does |
|---|---|---|
| `ResilienceEvents.events$`, the `nestjs:resilience:<type>` channels | `ResiliencePolicy::events()`, read with `next().await` | A subscription per policy, holding 256 events unread: one further behind is told how many it missed (`Lag`), and a send never runs a subscriber. The lines on `nest_rs::resilience` and the counters each say their own fact. |
| `retry`, `timeout`, `circuit-open`, `circuit-half-open`, `circuit-closed`, `circuit-rejected`, `bulkhead-rejected`, `rate-limited`, `fallback` | `ResilienceEvent`'s `Retry`, `Timeout`, `Transition`, `Refusal` and `Fallback` | One `Transition` and one `Refusal`, each saying which; an error is its chain as text, never its value. |
| `ResilienceService.circuitBreaker(name)`, `bulkhead(name)`, `circuitBreakers()` and `bulkheads()`, for an app to export | each policy injected by its type | A policy is reached by its type wherever it is injected; under the `opentelemetry` feature its reads are observed on the meter, by instance. |
| `mapErrors`: `504`, `503`, `RpcException`, `WsException`, `GraphQLError`; `TIMEOUT`, `CIRCUIT_OPEN`, `BULKHEAD_FULL`, `RATE_LIMITED` | `ResilienceError`, through `ToProblem` | A refusal of the policy's is one `503` with the code `UNAVAILABLE` on every edge, and `Retry-After` where known; the variant tells the causes apart in code. `Failed` answers as the call's own error says. |
| `mapErrors: false` | a method answering an error of its own | It maps the `ResilienceError` it holds, as it maps any error of its own. |

A policy's state lives in its process: each replica keeps its own breaker,
bulkhead and rate, and no store shares them. [The middleware](/fundamentals/resilience-middleware/)
puts the same policy on your reqwest client.

## What runs differently

Beyond the vocabulary, the machine underneath diverges: security holds by
composition, a forgotten guard refuses the boot, there is no `forwardRef` and no
runtime reflection, and the parameter's type is the decorator.
[What runs differently](/coming-from-nestjs/what-runs-differently/) takes each,
and what NestRS does where you reach for a NestJS tool.

## What the port changes

The same slice — a users controller with an injected service and one guarded
route. The NestJS sketch:

```ts title="users.controller.ts"
@Controller('users')
@UseGuards(AuthnGuard, AuthzGuard)
export class UsersController {
  constructor(private readonly svc: UsersService) {}

  @Get(':id')
  async get(@Param('id') id: string): Promise<User> {
    return this.svc.findInOrg(id);
  }
}
```

The NestRS equivalent is the snippet that opened this page. The guard binding,
the injected service and the route decorator each have a direct counterpart —
the lines with no counterpart are the posture and the parameter.
`@Param('id') id: string` hands you a string to look up;
`#[authorize(Read, bind = UsersService)]` hands you the row, as an
`Authorized<Read, UserEntity>`.

The org scoping is not an argument you thread through by hand. The guard
established the principal, and the bound load resolves the id to a row the
caller is authorized to read — outside the caller's org is a 403, absent is a
404.
