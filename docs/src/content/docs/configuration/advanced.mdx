The derive covers per-field rules and `FromStr` covers scalar parsing.
Two things push a config past them: a field carrying a **structured
payload** (a JSON blob in one variable) and a **rule spanning the whole
struct**. `OAuthServerConfig<P>` — the clients an authorization server
registers, which the demo's `apps/auth` issues tokens to — needs both. Its
namespace is read off its path, as every config's is:
`nest-rs-oauth-server/src/config.rs` reads `<PREFIX>_OAUTH__SERVER__*`.

```rust title="nest_rs::oauth::server::OAuthServerConfig (abridged)"
#[config(namespace = "oauth__server", validate = "manual")]
#[derive(Clone, Debug)]
pub struct OAuthServerConfig<P> {
    pub clients: Vec<RegisteredClient<P>>,
}

impl<P: DeserializeOwned + Clone + Send + Sync + 'static> Config for OAuthServerConfig<P> {
    fn from_env(env: &ConfigService, base: Self) -> nest_rs_config::Result<Self> {
        Ok(Self {
            clients: env.json("CLIENTS")?.unwrap_or(base.clients),
        })
    }
}

impl<P> Validate for OAuthServerConfig<P> {
    fn validate(&self) -> Result<(), ValidationErrors> {
        let mut errors = ValidationErrors::new();
        if self.clients.is_empty() {
            errors.add("clients", ValidationError::new("at_least_one_client"));
        }
        let mut seen = HashSet::new();
        for client in &self.clients {
            let mut refuse = |field: &str, code: &'static str| {
                errors.errors_mut().insert(
                    format!("clients[{}].{field}", client.client_id).into(),
                    ValidationErrorsKind::Field(vec![ValidationError::new(code)]),
                );
            };
            if client.client_id.is_empty() {
                refuse("client_id", "required");
            } else if !seen.insert(client.client_id.as_str()) {
                refuse("client_id", "duplicate");
            }
            // … an empty secret, a client registered for no resource
        }
        if errors.is_empty() { Ok(()) } else { Err(errors) }
    }
}
```

- **`base` supplies the fallback, even for the structured field.** An unset
  `<PREFIX>_OAUTH__SERVER__CLIENTS` keeps `base.clients` rather than resetting
  to an empty list, so a registry a `for_root` pinned in code survives a
  deployment that sets nothing.
- **`clients` is a JSON array in a single variable.** `env.json("CLIENTS")`
  decodes it as the field's type, inline or through
  `<PREFIX>_OAUTH__SERVER__CLIENTS_FILE`, and a value that does not decode
  fails the boot with `ConfigError::Decode`, naming whichever spelling was
  set, where the value failed, the kind of value found and the type expected —
  never the value, since a mistyped list of clients holds their secrets.
  Decoding it with `serde_json` in the `from_env` would quote it back. The
  element is `RegisteredClient<P>`; the app fills the generic `payload` — the
  demo's `ClientPayload`, the org each client acts as and its roles — so the
  framework owns the credential shape and the app owns only what it
  authorizes on.
- **"At least one client" and "no id twice" are struct-level rules**, so
  `impl Validate` is written by hand, building the same `ValidationErrors`
  the derive would. They run after the load and abort the boot exactly like a
  derived rule, naming each refusal by the client's id, never its secret.

The app registers it with the payload type it owns, and reads it like any
config:

```rust title="crates/features/src/sign_in/module.rs (from the demo)"
use nest_rs::config::ConfigModule;
use nest_rs::core::module;
use nest_rs::oauth::server::OAuthServerModule;
use nest_rs::social::SocialModule;

use super::config::{ClientPayload, SignInConfig};
use super::service::SignInService;
use crate::users::UsersModule;

#[module(
    imports = [
        ConfigModule::for_feature::<SignInConfig>(),
        OAuthServerModule::for_root::<ClientPayload>(None),
        UsersModule,
        SocialModule,
    ],
    providers = [SignInService],
)]
pub struct SignInModule;
```

`SignInConfig` beside it is the product's own — the resources a sign-in may
ask for and the org a first social sign-in joins — read from
`<PREFIX>_SIGN_IN__*`, the feature's own word: a product stem never takes a
family's (`oauth`), whose first level is the framework members'.

### Run it

```bash frame="terminal"
$ NESTRS_OAUTH__SERVER__CLIENTS='[{"client_id":"web","client_secret":"...","payload":{"org_id":"00000000-0000-0000-0000-000000000000","roles":["user"]},"scopes":["posts:read"],"resources":["http://localhost:3003"]}]' \
  nestrs run dev auth
2026-06-03T10:42:11Z INFO nest_rs::routes: mounted route controller="SignInController" method="POST" path="/token" handler="token"
```

A bad value fails the boot before any port opens, naming the config's
factory first and the variable below it:

```bash frame="terminal"
$ NESTRS_SIGN_IN__DEFAULT_ORG_ID=not-a-uuid nestrs run dev auth
Error: the factory for `features::sign_in::config::SignInConfig` failed

Caused by:
    invalid value for NESTRS_SIGN_IN__DEFAULT_ORG_ID: invalid character: found `n` at 0
```

A failed validation runs after the load:

```bash frame="terminal"
$ nestrs run dev auth   # no clients configured
Error: the factory for `nest_rs_oauth_server::config::OAuthServerConfig<features::sign_in::config::ClientPayload>` failed

Caused by:
    configuration validation failed for 'oauth__server'
      - clients: at_least_one_client
```

What only the product knows — a registered scope outside the set its rules
gate on, a client id a UUID parses, which would read as a user — it refuses
from its service's module-init hook, in the same words:

```bash frame="terminal"
$ NESTRS_OAUTH__SERVER__CLIENTS='[{"client_id":"web",…,"scopes":["admin"]}]' nestrs run dev auth
Error: …
    configuration validation failed for 'oauth__server'
      - clients[web].scopes: unknown_scope
```

A refusal line says the field and the rule's code, never the rule's
parameters, so it names the client and not the accepted set. That set is
`authz::constants::ALL` — `posts:read`, `posts:write` and
`audio:transcode`, the scopes the app's rules gate on — and the demo's `.env`
lists it beside the variable.


## A profile-dependent baseline

`from_env` overlays the environment onto a **base**, and that base is
`Config::defaults()` when nothing was pinned at the import site. `Default` is
the production-safe value, in every profile; a development convenience — plain
HTTP, public documentation, a committed artifact's emit, a seed — lives in
`defaults()`, armed only by a declared development or test profile. A process
that declares no `<PREFIX>_ENV` runs as production, so it gets `Default`. The
framework does this for its own storage, OpenAPI, GraphQL and Server-Timing
configs:

```rust title="crates/nest-rs-graphql/src/config.rs (abridged)"
use nest_rs::config::Environment;

impl Config for GraphqlConfig {
    fn defaults() -> Self {
        let environment = Environment::from_env();
        let open = !environment.is_deployed();
        Self {
            playground: open,
            introspection: open,
            emit: environment == Environment::Development,
            ..Self::default()
        }
    }

    fn from_env(env: &ConfigService, base: Self) -> Result<Self> { /* … */ }
}
```

An address or a credential is never one, in any profile: no `defaults()` names
a database, a Redis, a store or the pair to reach it. The profile's `.env` file
does — `nestrs new` writes `compose.yml`'s services into `.env.development` and
`.env.test` — and a deployment names its own.

It belongs here rather than inside `from_env`: `from_env` also runs over a
value pinned in code, and a profile rule there would silently rewrite a
deliberate choice. So a pin chooses its base in sight — `..T::defaults()` for
the profile's, `..Default::default()` for the production-safe value — and
`Default` holds no opening for a pin to inherit.
