Every framework module reads its config from a namespaced env prefix
**and** from a pinned struct — the framework-wide **dual-path rule**
([Configuration](/configuration/#the-dual-path-rule)). The variable name is
`NESTRS_<NAMESPACE>__<KEY>` (double underscore between namespace and key). This
page lists the variables; each maps one-to-one to a field on the module's
config struct, so anything here is also settable in code — and, because the
override is per field, setting one here works even when the app pins its
neighbours in `module.rs`.

`NESTRS` is the default prefix. An app that declared its own
([Your own prefix](/configuration/#your-own-prefix)) reads every name below
with that prefix instead — `ACME_HTTP__PORT`, `ACME_LOG` — and the `NESTRS_`
spellings resolve nothing.

**Every namespaced variable can also be given as a file.**
`NESTRS_<NAMESPACE>__<KEY>_FILE` names a file whose content is the value — the
form a mounted secret takes, [read the same way for every key](/configuration/#configservice-api).
The tables below name the `_FILE` spelling only where a key is usually given
that way.

**The namespace is the path of the crate that parses it — never chosen.** It is
the same stem the config type is named from: the crate's word, then the
binding folder's when the config sits in one, joined by `__`. `HttpConfig` reads
`NESTRS_HTTP__*`; `SeaOrmConfig` reads `NESTRS_SEAORM__*`; `RedisQueueConfig`
(in `nest-rs-redis`'s `queue/` folder) reads `NESTRS_REDIS__QUEUE__*`;
`GithubSocialConfig` reads `NESTRS_SOCIAL__GITHUB__*`. A crate in a family puts
the family first: `OAuthClientConfig`, in `nest-rs-oauth-client`, reads
`NESTRS_OAUTH__CLIENT__*` — the same string as its path,
`nest_rs::oauth::client`. So from any variable on
this page you can name the type and the file that parse it, and from any
`<X>Module::for_root` in a composition root you can name its variables: the
vendor is in the variable exactly when it is in the type. That is also why there
is no `NESTRS_DATABASE__URL` — the universal convention, but a word that names
neither the crate nor the type, so a reader could not find the code from it.

## Logging — `NESTRS_LOG*`

The baseline console logger is part of `nest-rs-core` — no module to
import, no config struct. It reads two process-level variables:

| Key | Meaning |
|---|---|
| `NESTRS_LOG` | tracing filter (e.g. `info`, `debug,hyper=warn`); falls back to `RUST_LOG`, default `info` |
| `NESTRS_LOG_FORMAT` | `json` (the release default) or `text` (the dev default) |
| `NESTRS_LOG_SOURCE_LOCATION` | append the emitting `file:line` to each event — default `false` |

An app that installs its own subscriber first (e.g. through
[OpenTelemetry](/opentelemetry/)) keeps it — the baseline logger only
activates when none is set. The same three variables drive the console
layer of the [OpenTelemetry](/opentelemetry/) subscriber too, so log
config survives adopting or dropping the observability stack.

## `http` — `NESTRS_HTTP__*`

| Key | Meaning |
|---|---|
| `HOST` | listen address (default `0.0.0.0`) |
| `PORT` | listen port |
| `GLOBAL_PREFIX` | path prefix for every route (unset ⇒ none) |
| `MAX_BODY_BYTES` | request body cap |
| `REQUEST_TIMEOUT_SECS` | per-request timeout — default `30`; whole seconds from `1` to `3600`, or `0` ⇒ no timeout. An overrun answers `503` with a `Retry-After`, not `504`: this transport is the origin, not a gateway |
| `SHUTDOWN_TIMEOUT_SECS` | how long open connections may finish after a shutdown signal — default `20`, so the window, the half second what it stopped takes to unwind, the shutdown hooks' 5 s and OpenTelemetry's 3 s flush end inside the 30 s a Kubernetes pod gets before `SIGKILL`; whole seconds from `1` to `3600`, refused outside, and `0` is refused rather than read as off. What is still open when it closes is cut — a running request goes unanswered, a download is cut — and one `warn` counts it. What has no end of its own — an event stream, a gateway's WebSocket, a graphql-ws socket — ends at the signal instead: see [Shutdown](/http/configuration/#shutdown) |
| `FAIL_SECURE_STRICT` | fail boot (vs warn) on an unguarded self-mount under global guards — default `true` |
| `SECURITY_HEADERS` | master switch for the secure-by-default response headers |
| `HSTS` · `FRAME_OPTIONS` · `CONTENT_TYPE_OPTIONS` · `SERVER_HEADER` | individual security-header controls |
| `REFERRER_POLICY` · `CROSS_ORIGIN_OPENER_POLICY` · `CROSS_ORIGIN_RESOURCE_POLICY` | the rest of the default-on set — `strict-origin-when-cross-origin`, `same-origin`, `same-origin`; `off` drops one, a blank value fails the boot, and an empty one keeps the default |
| `CONTENT_SECURITY_POLICY` · `CROSS_ORIGIN_EMBEDDER_POLICY` · `PERMISSIONS_POLICY` | settable, off by default — each governs a *document* whose sources the framework cannot speak for; see [HTTP configuration](/http/configuration/) |
| `TLS_CERT` / `TLS_KEY` | PEM cert + key for HTTPS (inline); `TLS_CERT_FILE` / `TLS_KEY_FILE` read from a path instead. One half without the other fails the boot, and so do both spellings of one half in the same tier. Unset ⇒ plain HTTP |
| `TLS_RELOAD_SECS` | how often a file-sourced pair is re-read, so a renewal swaps in without a restart — default `60`; from `1` to `86400` (a day), or `0` disables |
| `VERSIONING` | how a caller selects an API version — `uri` (default), `header`, `media_type` |
| `VERSION_HEADER` | the header the `header` strategy reads — default `X-API-Version` |
| `DEFAULT_VERSION` | the version served to a caller that states none; unset ⇒ the unversioned routes |
| `CORS_ORIGINS` | comma-separated allowed origins; unset ⇒ no CORS layer |
| `CORS_METHODS` | comma-separated allowed request methods |
| `CORS_HEADERS` | comma-separated allowed request headers |
| `CORS_EXPOSED` | comma-separated response headers exposed to the browser |
| `CORS_CREDENTIALS` | allow credentialed requests — default `false` |
| `CORS_MAX_AGE` | preflight cache lifetime in seconds |
| `COMPRESSION` | negotiate response compression from `Accept-Encoding` — default `false` (leave it to the proxy unless the app terminates responses) |
| `SSE_MAX_CONNECTION_SECS` | how long an [`#[sse]` stream](/http/streaming/) may stay open before the server ends it and the client reconnects — default `14400` (4 h); from `1` to `86400` (a day), or `0` ⇒ unlimited. A security control: the stream authenticates once, at the request |
| `SSE_KEEP_ALIVE_SECS` | keep-alive comment interval on an `#[sse]` stream, so an idle feed is not dropped by an intermediary — default `15`; from `1` to `3600`, or `0` ⇒ none sent |
| `ACCESS_LOG` | emit one access-log event per request on `nest_rs::operation` — default `true`. Owned by the HTTP transport, so it needs no observability crate; `trace_id` joins the line only when one is mounted |
| `TRUSTED_PROXIES` | comma-separated reverse-proxy IPs whose `Forwarded` (RFC 7239) / `X-Forwarded-For` / `X-Real-IP` / `traceparent` / `X-Request-Id` are believed. Empty (the default) ⇒ none is read, every caller is its transport peer, and every inbound trace is [restarted](/fundamentals/correlation/). Shared by [`ClientIp`](/http/extractors/), the [throttler](/rate-limiting/) and the trace context; an unparseable entry aborts the boot |

## `seaorm` — `NESTRS_SEAORM__*`

The one pool every SeaORM binding shares, opened by `SeaOrmModule::for_root`.
The engine is in the URL's scheme (`postgres://`, `mysql://`, `sqlite://`) —
sea-orm picks it, the variable does not change.

| Key | Meaning |
|---|---|
| `URL` | database connection string |
| `MAX_CONNECTIONS` | pool maximum connections (unset ⇒ SeaORM default) |
| `MIN_CONNECTIONS` | pool minimum connections (unset ⇒ SeaORM default) |
| `CONNECT_TIMEOUT_SECS` | connection-acquire timeout in seconds, from `1` to `3600` (unset ⇒ SeaORM default) — `0` fails the boot rather than time out every acquire, and past an hour the request that asked for a connection has long been abandoned |
| `SQLX_LOGGING` | log SQL statements |
| `OBSERVE_SERIALIZATION_CONFLICTS` | tag commit-time serialization conflicts at `warn` |

## `redis` — `NESTRS_REDIS__*`

The one Redis connection every Redis binding shares — the queue's producer and
consumer, the rate-limit store and the schedule's occurrence lock — opened by
`RedisModule::for_root`. One connection, one variable: a throttler-only app sets
the same `URL` a queue app does. The TLS material is read at boot, so a renewed file takes effect at the
next restart.

| Key | Meaning |
|---|---|
| `URL` | Redis connection string — `rediss://` connects over TLS and verifies Redis's certificate for the URL's host; `#insecure`, which skips that, fails the boot |
| `TLS_CA_CERT` | PEM certificates of the authorities Redis's certificate must chain to, replacing the authorities of Mozilla's root program compiled into the client — a private CA's, or the system's bundle to trust the system's; `TLS_CA_CERT_FILE` reads them from a path instead. Beside a `redis://` URL, fails the boot |
| `TLS_CERT` / `TLS_KEY` | PEM client certificate chain, leaf first, and its private key, presented to a Redis that requires one — its default under TLS (`tls-auth-clients yes`); `TLS_CERT_FILE` / `TLS_KEY_FILE` read them from a path instead. Both or neither |
| `CONNECT_TIMEOUT_SECS` | boot budget for reaching Redis before failing with a named error, then the most any command a caller waits on may take from end to end — a push, a rate-limit check, a command of your own — past which it fails as a timeout — and how long the socket waits, a second at the least, before it probes an idle Redis or gives up on bytes Redis never acknowledged. A queue worker's blocking read, on a connection of its own, waits its one second plus this budget; defaults to `10`; whole seconds from `1` to `3600` — an hour, past which a Redis silent that long is gone rather than slow — refused outside, and in code anything above zero up to an hour, a sub-second budget included. An app importing the queue or the rate limiter binding keeps it under their net, 20 seconds, which would otherwise give up on a command still answering: the boot refuses one at or past it. Each boot attempt warns on `nest_rs::redis`, so an unreachable backend is a bounded boot failure rather than a process that never becomes healthy and never crashes. Refused credentials and an ACL denying the connection's `PING` fail at once, and so does a database the server will not select — an index it does not have, an ACL user without `+select`, a server in cluster mode — named by the index the URL ends in; a Redis loading its dataset, busy running a script or failing over is retried within the budget, and one still not ready when it runs out fails naming its last answer |

## `redis__queue` — `NESTRS_REDIS__QUEUE__*`

The Redis queue binding's own settings, read by a bare `RedisQueueModule` import
or pinned through `RedisQueueModule::for_root`. Two segments because the config
sits in the crate's `queue/` folder: the crate's word, then the binding's —
exactly the stem `RedisQueueConfig` is named from.

| Key | Meaning |
|---|---|
| `LEASE_SECS` | how long a delivery holds its job without a renewal. The worker renews it every third of this while the attempt runs; once it lapses, the next worker that asks takes the job, so it is also how long a crashed replica's job waits before another runs it. Defaults to `30`; below `1` or above `3600` is rejected, and so is a lease of no more than one and a half times `<PREFIX>_REDIS__CONNECT_TIMEOUT_SECS`: a renewal sent a third into the lease may wait out the whole budget, and would land after the lease lapsed |

## `queue` — `NESTRS_QUEUE__*`

The queue port's worker settings, read once `QueueModule` is imported, and
pinned through `QueueModule::for_root`. The port's own word, so the window
survives a swap of the backend underneath.

| Key | Meaning |
|---|---|
| `SHUTDOWN_TIMEOUT_SECS` | the drain window after a shutdown signal: running attempts finish inside it, less a reserve, and one still running as it closes is interrupted and its job handed back to the queue before it ends. Defaults to `20`, so the way down fits Kubernetes' default grace period; below `1` or above `3600` is rejected |

## `storage` — `NESTRS_STORAGE__*`

| Key | Meaning |
|---|---|
| `ENDPOINT` | S3 endpoint (empty ⇒ real AWS S3) |
| `REGION` | region |
| `ACCESS_KEY` / `SECRET_KEY` | static credentials |
| `BUCKET` | target bucket |
| `FORCE_PATH_STYLE` | path-style vs virtual-hosted addressing |
| `ALLOW_HTTP` | reach the endpoint over plain `http://` — default `true` in dev/test, `false` in staging/production so credentials never travel unencrypted by omission. `false` + an `http://` `ENDPOINT` **fails boot**, naming the variable; the refusal covers presigned URLs, which are signed locally and would otherwise ship a working plaintext URL |

## `opentelemetry` — `NESTRS_OPENTELEMETRY__*`

| Key | Meaning |
|---|---|
| `SERVICE_NAME` | service name; overrides the name passed to `OpenTelemetry::init` |
| `OTLP_ENDPOINT` | collector endpoint (unset ⇒ no export) |
| `SAMPLE_RATIO` | trace sampling ratio, `0.0`–`1.0` (default `1.0`) |
| `METRIC_INTERVAL_SECS` | metric export period, from `1` to `3600` (default `60`; `0` is refused). Traces and logs export immediately — metrics wait for this flush |
| `SERVICE_VERSION` · `SERVICE_ENVIRONMENT` · `SERVICE_INSTANCE_ID` | resource attributes |

The console layer reads the [`NESTRS_LOG*` family](#logging--nestrs_log)
above — there are no OTel-specific log variables.

## `authn` — `NESTRS_AUTHN__*`

JWT key material and validation for `nest-rs-authn`. A resource server sets only
the verification side (`SECRET` **or** `PUBLIC_KEY`); the issuer app also sets the
signing side. The key material is read at boot, so a rotated file takes effect
at the next restart.

| Key | Meaning |
|---|---|
| `SECRET` | HS256 shared secret (≥ 32 bytes) — signs and verifies. Beside either key it fails the boot |
| `PRIVATE_KEY` | EdDSA private key (PEM) — issuer only, to sign; `PRIVATE_KEY_FILE` reads it from a path instead. Without `PUBLIC_KEY`, or beside the public key of another pair, fails the boot |
| `PUBLIC_KEY` | EdDSA public key (PEM) — to verify; `PUBLIC_KEY_FILE` reads it from a path instead |
| `ISSUER` | expected `iss` claim (unset ⇒ no issuer check) |
| `AUDIENCE` | expected `aud` claim. Set ⇒ the claim is **mandatory** and must name this app. Unset does *not* disable the check: a token carrying an `aud` this app is not named in is refused either way (RFC 7519 §4.1.3) |
| `ALLOW_ANY_AUDIENCE` | opt out of that clause and accept a token minted for another service (default `false`). Refused beside `AUDIENCE`, and reported at `warn` once per boot |
| `LEEWAY_SECS` | clock-skew leeway in seconds, `0` to `300` (default `30`) — RFC 7519 §4.1.4's "no more than a few minutes"; past it an expired token still verifies |
| `EXPIRES_IN_SECS` | minted-token lifetime in seconds, `1` to `2592000` — thirty days (default `3600`) |
| `EXPLICIT_TYPING` | require the JWT `typ` header to name the token's type (default `true`) |

## `oauth__client` — `NESTRS_OAUTH__CLIENT__*`

The login flow's provider endpoints, read by `OAuthClientConfig` in
`nest-rs-oauth-client`. Every field is required, so an unconfigured app fails
boot naming the field:

| Key | Meaning |
|---|---|
| `CLIENT_ID` / `CLIENT_SECRET` | the registered OAuth2 client credentials |
| `AUTH_URL` | provider authorization endpoint (where the user consents) |
| `TOKEN_URL` | provider token endpoint (code → tokens) |
| `REDIRECT_URL` | this app's callback the provider returns to |
| `USERINFO_URL` | provider endpoint the profile is fetched from |
| `SCOPES` | comma-separated scopes requested at authorization (empty by default) |

## `oauth__resource` — `NESTRS_OAUTH__RESOURCE__*`

`OAuthResourceModule` is what turns the app into a conformant OAuth 2.1
resource server (RFC 9728) and what an MCP server needs. Importing it makes
`NESTRS_AUTHN__AUDIENCE` **mandatory**: the boot fails without it rather than
leaving the app unable to say which tokens are its own. (A token minted for
*another named* audience is refused with or without the module — that is
RFC 7519 §4.1.3. What the module adds is that a token carrying no `aud` at all
is refused too.)

| Key | Meaning |
|---|---|
| `RESOURCE` | this deployment's canonical resource URI — the value tokens must carry as `aud`. **Required** under the module |
| `AUTHORIZATION_SERVERS` | comma-separated issuer identifiers allowed to mint tokens for it. **At least one required** |
| `SCOPES_SUPPORTED` | comma-separated minimal scope set, advertised in the metadata document and the `WWW-Authenticate` challenge |
| `BEARER_METHODS_SUPPORTED` | how a token may be presented — defaults to `header`, the only form accepted |
| `RESOURCE_NAME` | human-readable name for a consent screen |
| `RESOURCE_DOCUMENTATION` | URL of developer documentation for this resource |
| `RESOURCE_POLICY_URI` | URL of this resource's privacy policy, advertised in the metadata document |
| `RESOURCE_TOS_URI` | URL of this resource's terms of service, advertised in the metadata document |

## `mcp` — `NESTRS_MCP__*`

| Key | Meaning |
|---|---|
| `ALLOWED_HOSTS` | comma-separated `Host` authorities accepted (anti-DNS-rebinding). Defaults to loopback, so a public deployment **must** name itself; an empty list disables the check and is reported at `warn` |
| `LEGACY_SESSION_MODE` | keep sessions alive for protocol revisions older than `2026-07-28` — default `true` |
| `JSON_RESPONSE` | answer simple operations with `application/json` instead of an SSE stream — default `false` |
| `SSE_KEEP_ALIVE_SECS` | SSE keep-alive ping interval, from `1` to `3600` (`0` ⇒ none) — default `15` |
| `SSE_RETRY_SECS` | `retry:` interval advertised on SSE priming events, from `1` to `3600` (`0` ⇒ none) — default `3` |
| `MAX_REQUEST_BODY_BYTES` | cap on a single POST body, enforced while streaming — default 4 MiB |
| `STATELESS_PROTOCOL_METADATA_REQUIRED` | require per-request protocol metadata on stateless POSTs (SEP-2243) — default `false` |

## `social` — `NESTRS_SOCIAL__<PROVIDER>__*`

One sub-namespace per provider (`GITHUB`, `GOOGLE`). Credentials decide the
provider's fate: complete ⇒ active, absent ⇒ inert with a boot `warn`,
partial ⇒ the boot fails naming the provider.

| Key | Meaning |
|---|---|
| `CLIENT_ID` / `CLIENT_SECRET` | the provider's OAuth app credentials |
| `REDIRECT_URL` | the registered callback this app is returned to |
| `SCOPES` | comma-separated scopes; each provider has a sensible default when unset |

The endpoint URLs are provider constants, not config — see
[Social login](/security/authentication/social-login/).

## A variable nothing reads

A variable under the prefix that no config reads used to cost the deployment
its value in silence: a misspelled key, or a name a release renamed, left the
default in place and nothing said so. The boot now does, once per variable, at
`warn` on `nest_rs::config`, by name and never by value:

| Message | When | Fields |
|---|---|---|
| `config variable read by no config` | a config of this binary read the variable's namespace, and none read its key | `variable`, `namespace`, and `suggestion` — the nearest key that was read, when one is close enough |
| `config variable under a misspelled namespace` | the variable's namespace is a near miss of one this binary read — other separators (`NESTRS_OAUTH_RESOURCE__RESOURCE` for `oauth__resource`, `NESTRS_SEAORM_URL` for `seaorm`), another case, the prefix's included, since the loader folds none (`NESTRS_Seaorm__URL`, `nestrs_seaorm__url`), or one misspelled segment of six letters or more, a family member's included (`NESTRS_SEAROM__URL`, `NESTRS_OAUTH__RESOURSE__RESOURCE`) — **and its key is one that namespace reads**, or one edit from one | `variable`, `namespace` (the linked spelling), and `suggestion` — the name that is read |

Everything else stays silent, and that is the design. One `.env` serves several
binaries, so a namespace this binary does not read, and that is no near miss of
one it does, is another binary's — and a near miss is held to both halves of the
variable for that reason. A namespace under six letters has no room for a typo
that is not also a word (`auth` and `authz` beside `authn`, `es` beside `ws`), so
only its separators and its case count; and a misspelled namespace still carries
the key the deployment meant, which the near namespace reads, while another
binary's variable carries its own — `NESTRS_OPENAI__API_KEY` beside a linked
`openapi` names no key `openapi` reads, and stays silent. The framework's own
namespaces are held apart from each other by the conformance suite. A key holding
`__` under a namespace it does read is a sub-namespace another binary links —
`redis__queue` under `redis` — reported only when it is a near miss of a key
read here. The framework's process-level names, `NESTRS_LOG*`,
`NESTRS_ENV` and `NESTRS_ENV_PREFIX`, are never reported.

The check runs where each config is read, against the keys its `from_env`
actually asked for — the namespace's misspellings included, at that same read,
ended by an error or not, so a renamed required variable is named before the
boot error its absence causes. A key read only behind a branch — `HttpCors` reads its other
keys only when `CORS_ORIGINS` is set — is therefore reported exactly when the
deployment did not take the branch, which is when it does nothing. A read made
before any subscriber listens waits for the first read that has one, and a
deployment that filters `nest_rs::config` out pays nothing for the scan.
[Upgrading from 6.x](/upgrading/#what-fails-if-you-get-it-wrong) shows what it
prints for a boot that kept a renamed variable.

## The `.env` cascade

Values resolve highest-first: real env > pinned in `module.rs` >
`.env.<NESTRS_ENV>.local` > `.env.local` > `.env.<NESTRS_ENV>` > `.env`. See
[the env cascade](/configuration/env-cascade/) for the files and
[the dual-path rule](/configuration/#the-dual-path-rule) for where a pinned
value sits.
