An entity is a SeaORM model decorated with `#[expose]`. You declare the columns, their types, the relations, and which fields cross
the wire — **once**. The macro emits everything downstream:

- the wire DTO, and the create/update inputs;
- the `validator` wiring;
- the JSON schema the HTTP and OpenAPI layers read;
- the GraphQL object and its relation dataloaders;
- the lifecycle behaviour — timestamps, soft delete.

The entity *is* the wire contract. There is no separate DTO to keep in
sync — a column reaches a transport only when it carries `#[expose]`,
and silence means hidden. That is the deliberate posture: a column a
later migration adds never leaks by omission.

Building your first entity? Start with the
[tutorial walkthrough](/tutorial/entity/) — it grows a minimal `Post`
step by step. This page is the **reference**: every header flag, every
field attribute, relations, validation, lifecycle, and the columns we
recommend on every entity.

## Anatomy

The reference entity lives at `crates/features/src/posts/entity.rs`.
Copy it before inventing a second shape.

```rust title="crates/features/src/posts/entity.rs"
use nest_rs::seaorm::expose;
use sea_orm::entity::prelude::*;

#[expose(
    name = "Post",
    service = super::service::PostsService,
    graphql,
    soft_delete,
    timestamps
)]
#[sea_orm::model]
#[derive(Clone, Debug, DeriveEntityModel)]
#[sea_orm(table_name = "post")]
pub struct Model {
    #[sea_orm(primary_key, auto_increment = false)]
    #[expose]
    pub id: Uuid,
    #[expose]
    pub org_id: Uuid,
    #[expose]
    pub author_id: Uuid,
    #[expose(input(create, update), validate(length(min = 1)))]
    pub title: String,
    #[expose(input(create, update), validate(length(min = 1)))]
    pub body: String,
    #[expose]
    pub created_at: DateTimeWithTimeZone,
    #[expose]
    pub updated_at: DateTimeWithTimeZone,
    pub deleted_at: Option<DateTimeWithTimeZone>,
    #[sea_orm(belongs_to, from = "org_id", to = "id")]
    #[expose]
    pub org: HasOne<crate::orgs::Entity>,
    #[sea_orm(belongs_to, from = "author_id", to = "id")]
    #[expose]
    pub author: HasOne<crate::users::Entity>,
}
```

[SeaORM](https://www.sea-ql.org/SeaORM/docs/index/) owns the column
types and the `#[sea_orm(...)]` attributes — `#[expose]` only **reads**
them and decides what crosses the wire. The two decorators compose:
`#[sea_orm::model]` builds the `Entity`, `Column`, `ActiveModel`, and
`Relation` machinery; `#[expose]` builds the transport surface on top. The
`Model` derives no serde: `#[expose]` writes the wire type and the round
trip a mask reads a row through, so the row serializes nowhere but as
`Post`, and a hidden column has no way onto a wire.
For everything about columns, types, relations, and migrations, the
[official SeaORM 2 documentation](https://www.sea-ql.org/SeaORM/docs/index/)
is the source of truth.

## The header

`#[expose(...)]` takes one required value, one near-required path, and
a set of bare flags.

| Flag | Kind | Effect |
|---|---|---|
| `name = "Post"` | **required** | The wire DTO / GraphQL object / OpenAPI schema name. The entity names it as `<Entity as Exposed>::Wire`, which is what a `#[crud]` operation answers; only `#[expose]` implements `Exposed`. |
| `service = …` | path | The service that owns the entity. Required as soon as the entity exposes a relation or another feature needs its PK loader — it's where the macro emits the loaders. |
| `graphql` | flag | Emit the GraphQL object + input objects, and auto-resolve exposed relations through dataloaders. An exposed relation **without** `graphql` is a compile error. |
| `timestamps` | flag | Emit an `ActiveModelBehavior` that stamps `created_at` on insert and, when the entity has one, `updated_at` on every save. Requires `created_at`: an append-only entity has no `updated_at`. |
| `soft_delete` | flag | Deletes set `deleted_at`, and every `Repo` read hides a tombstoned row. Requires a `deleted_at: Option<…>` column. |
| `complex` | flag | Force `#[graphql(complex)]` on the wire DTO. Auto-enabled when `graphql` is set and the entity has auto-resolved relations — you rarely set it by hand. |

## Recommended standard columns

Every product entity in this repo (`org`, `user`, `post`) carries the
same four columns. Follow the convention unless you have a reason not
to:

| Column | Type | Role |
|---|---|---|
| `id` | `Uuid` | Primary key, `auto_increment = false`. Every insert through `Repo` that leaves it unset gets `Uuid::now_v7()` — time-ordered, index-friendly. |
| `created_at` | `DateTimeWithTimeZone` | Stamped once on insert by `timestamps`. Read-only on the wire. |
| `updated_at` | `DateTimeWithTimeZone` | Stamped on every save by `timestamps`. Read-only on the wire. |
| `deleted_at` | `Option<DateTimeWithTimeZone>` | The soft-delete tombstone. **Left unexposed** — it's server-side state, never a wire field. |

```rust title="crates/features/src/posts/entity.rs"
#[sea_orm(primary_key, auto_increment = false)]
#[expose]
pub id: Uuid,
// …
#[expose]
pub created_at: DateTimeWithTimeZone,
#[expose]
pub updated_at: DateTimeWithTimeZone,
pub deleted_at: Option<DateTimeWithTimeZone>,   // no #[expose] — hidden
```

`id`, `created_at`, and `updated_at` are exposed **read-only** (bare
`#[expose]`, no `input(...)`) — the client reads them, never writes
them. `deleted_at` stays off the wire entirely.

## Read side — exposure is opt-in

A field crosses HTTP, GraphQL, and WS **only** when it carries
`#[expose]`. No attribute means the field is hidden from every
transport.

| Field attribute | On the wire | In inputs |
|---|---|---|
| `#[expose]` | yes (read-only) | no |
| `#[expose(input(create))]` | yes | `Create<Name>` only |
| `#[expose(input(update))]` | yes | `Update<Name>` only |
| `#[expose(input(create, update))]` | yes | both |
| *(no `#[expose]`)* | **hidden** | no |

`input(...)` implies read — a writable field is always readable. The
ordering of `create` / `update` is free.

Hidden columns are the security-load-bearing case. A `password_hash`,
a `role` set from a JWT, an internal flag — none of these should ride a
response. Because exposure is opt-in, they stay off the wire by
default, and a column a future migration adds never leaks until someone
deliberately exposes it.

The wire is not the only place a secret prints: the `Model` and the
`ActiveModel` derive `Debug`, and a reply or a log line can serialize a row.
Type a secret column as `nest_rs::core::Secret` — its `Debug` and its
serialization both say `<redacted>`, and the column stores and reads its
value's own type:

```rust title="crates/features/src/users/entities/user.rs (from the demo, abridged)"
use nest_rs::core::Secret;
// …
#[derive(Clone, Debug, DeriveEntityModel)]
// …
pub struct Model {
    // …
    pub password_hash: Option<Secret<String>>,
    // …
}
```

The service that verifies the hash reads it with `expose_secret()`, and
`#[expose]` refuses a `Secret` column at compile time: a secret never crosses
the wire.

<Aside type="caution">
Response masking rebuilds the full row from the wire body to judge it,
which needs a placeholder for every unexposed column. The macro provides
one for the trivial scalar types (`String`, `Option`, `bool`, numbers),
and a `Secret` column takes its value's. A hidden column of a type it
can't default — `Uuid`, a timestamp, `Decimal`, a custom enum, a
`Secret<Vec<u8>>` — takes `#[wire_default]` (its type's `Default`) or
`#[wire_default(expr)]`; without one, `#[expose]` refuses the column at
compile time. A rule reading a hidden column is decided by the `Repo`
read on a reply, and decides no pushed row.
See [Response masking](/security/authorization/response-masking/#what-the-mask-cannot-see).
</Aside>

### Enum columns

An exposed column whose type is your own enum passes through to the wire
**verbatim**, so the enum is what has to carry the wire traits.
`#[wire_enum]` is the enum mode of `#[expose]` and emits all of them —
`Serialize`, `Deserialize`, `JsonSchema`, and under `graphql`
`async_graphql::Enum`, plus the `Clone`/`Copy`/`Eq` shape those require:

```rust title="crates/features/src/posts/entities/post.rs"
use nest_rs::seaorm::{expose, wire_enum};

#[wire_enum(graphql)]
#[derive(EnumIter, DeriveActiveEnum)]
#[sea_orm(rs_type = "String", db_type = "String(StringLen::None)")]
#[serde(rename_all = "lowercase")]
pub enum PostStatus {
    #[sea_orm(string_value = "draft")]
    Draft,
    #[sea_orm(string_value = "published")]
    Published,
}
```

Each of those derives expands against the **call site's** prelude, so
hand-writing them put `schemars` and `async-graphql` in your manifest for
code you never wrote. The decorator routes them back through
`nest-rs-seaorm` with a `crate = ` override, so your manifest names
neither.

It deliberately emits **nothing from SeaORM**: `EnumIter`,
`DeriveActiveEnum`, `#[sea_orm(rs_type, db_type)]` and the per-variant
`string_value` stay yours, because how the column is *stored* is your
decision, not the wire's. Your own `#[serde(rename_all = …)]` and
`#[derive(Default)]` sit beside it untouched. Drop `graphql` for an enum
that only crosses HTTP.

An enum a **hidden** column holds never crosses a wire, so it takes no
`#[wire_enum]`: SeaORM's derives are its own, and the column names the
placeholder a masked reply rebuilds it with —
`#[wire_default(UserRole::User)]`, as the `users` exemplar's `role` does.

## Write side — inputs and validation

`input(create)` / `input(update)` place a field in the generated
`Create<Name>` / `Update<Name>` structs. These entity-derived inputs are
**bare** — no `Dto` or `Input` suffix — because one struct serves the
service (`type Create`), the REST body, and the GraphQL input at once, so no
single boundary suffix fits. `validate(...)` attaches a
[`validator`](https://docs.rs/validator) rule, re-emitted verbatim onto the
input field:

```rust title="crates/features/src/posts/entity.rs"
#[expose(input(create, update), validate(length(min = 1)))]
pub title: String,

#[expose(input(create, update), validate(email))]
pub email: String,
```

The input structs derive `Validate`. Validation runs at whichever edge
decodes one — a `Json<CreatePost>` body, a GraphQL `CreatePost` argument —
so the service never sees an invalid input. The full rule set
(`length`, `email`, `range`, `url`, custom validators, …) is the
`validator` crate's; see its docs for the catalogue.

A **relation** field cannot carry `input(...)` — only scalar columns
are writable. Set the foreign-key column (`org_id`) as the input, not
the relation (`org`).

A column the server decides is no input. The tenant and the author come from
the caller's grants, which a create fills ([CRUD](/database/crud/#the-tenant-comes-from-the-grant));
a constant takes `default`, which every insert through `Repo` leaving the
column unset stores:

```rust title="crates/features/src/posts/entities/post.rs (from the demo, abridged)"
#[expose(default = PostStatus::Draft)]
pub status: PostStatus,
```

`default` belongs to a column the create input does not carry, never to the
primary key, and never to a column `timestamps` stamps; each is a compile
error.

## Relations

A SeaORM `belongs_to` / `has_many` field, typed `HasOne<E>` /
`HasMany<E>` and marked `#[expose]`, becomes a GraphQL field
**auto-resolved by a dataloader** — no `#[field_resolver]` to write:

```rust title="crates/features/src/users/entity.rs"
#[sea_orm(belongs_to, from = "org_id", to = "id")]
#[expose]
pub org: HasOne<crate::orgs::Entity>,

#[sea_orm(has_many)]
#[expose]
pub posts: HasMany<crate::posts::Entity>,
```

This needs `graphql` **and** `service` on the header. The macro emits
the PK loader (`<Service>ById`) and, per `belongs_to`, the FK loader
(`<Service>By<FkCol>`) on the owning side's service, plus the
`PkLoadable` / `RelatedTo<Parent, Via>` impls that let the inverse side
reach the loader without naming the other service. The `has_many` side
is a paged connection (`first` / `after`), one page **per parent**.
Every batch goes through `Repo::scoped(Action::Read)`, so the ambient
ability filters relation reads row-level, exactly as on any other query.
Drop `#[expose]` on a single relation to opt that one field out, and add
`#[expose(via = "author_id")]` when the child reaches this parent through
more than one foreign key.

See [GraphQL relations](/graphql/relations/) and
[Dataloaders](/database/dataloaders/) for the full mechanics, and
[Query limits](/graphql/query-limits/) for the per-relation complexity
cost the macro attaches.

## Virtual and computed fields

There is no `#[expose]` "virtual column" attribute — `#[expose]` only
surfaces real SeaORM columns and relations. For a value computed at
query time (a derived total, a formatted label, a filtered subset of a
relation), leave the source unexposed and write a
`#[field_resolver]` on the resolver instead. Cost it with
`#[expose(complexity = …)]` on an exposed field, or
`#[graphql(complexity = …)]` directly on a hand-rolled resolver.

SeaORM itself offers two lower-level mechanisms underneath, neither of
which `#[expose]` reads — wire them through a `#[field_resolver]` (or a
hand-shaped HTTP response) if you want them on the wire:

- **A non-persisted field on the `Model`** — `#[sea_orm(ignore)]` keeps
  a field on the struct but out of the table and every query (set to
  `Default::default()` on load). Useful for transient state carried on
  the model.
- **A value computed by the database** — a `DerivePartialModel` with
  `#[sea_orm(from_expr = "…")]` selects a SQL expression into a result
  struct; a plain method on `impl Model` covers values computed in Rust.

See the [official SeaORM 2 documentation](https://www.sea-ql.org/SeaORM/docs/index/)
for both.

<Aside type="caution">
async-graphql allows at most **one** `#[ComplexObject]` per wire type.
An auto-resolved relation already occupies it, so a custom
`#[field_resolver]` cannot live next to an auto-resolved relation on
the same entity — pick one source of `ComplexObject` fields per entity.
</Aside>

## Lifecycle behaviour

Every exposed entity registers its column defaults — the `Uuid` key's v7
UUID and each column's `default` — and every insert through `Repo` fills the
ones the row left unset, `Creatable::create` and `Repo::insert_unscoped`
alike, after what the caller's grants pin. `timestamps` and `soft_delete` are
independent flags that emit SeaORM-level behaviour:

- **`timestamps`** emits `ActiveModelBehavior::before_save`, stamping
  `created_at` on insert and `updated_at`, when the entity has one, on every
  save, with `chrono::Utc::now().fixed_offset()` — one instant, so a fresh
  row's two columns are equal.
- **`soft_delete`** emits `impl SoftDeletable for Entity` and registers
  the entity, with or without a `service`. `SoftDeletable` is sealed: only
  the decorator implements it, so the trait never goes without the
  registration. That is the whole wiring:
  `Deletable::delete` sets the tombstone instead of erasing the row, and
  every `Repo` read and update ANDs `deleted_at IS NULL`, so a soft-deleted
  row is invisible — in lists, by-id loads, relation batches and your own
  queries alike. `Repo::with_tombstones` is the one read that keeps it. See
  [CRUD](/database/crud/#soft-delete-and-timestamps).

<Aside type="caution">
SeaORM requires exactly **one** `ActiveModelBehavior` per entity. The
macro emits it for you when `timestamps` is set — do not also write
your own, or the impls collide. With **no** `timestamps`, supply it
yourself: the empty `impl ActiveModelBehavior for ActiveModel {}`, or one
carrying your own hooks, which the column defaults never touch. A table no
transport exposes writes its own too, and its migration gives the key
`DEFAULT uuidv7()`.
</Aside>

## The migration

`#[expose]` builds the wire surface; it does **not** create the table.
The columns it reads must exist in a migration — including the
lifecycle columns, with their database-side defaults:

```rust title="crates/migrations/src/m20260101_000001_create_post.rs"
.col(ColumnDef::new(Post::CreatedAt)
    .timestamp_with_time_zone().not_null()
    .default(Expr::current_timestamp()))
.col(ColumnDef::new(Post::UpdatedAt)
    .timestamp_with_time_zone().not_null()
    .default(Expr::current_timestamp()))
.col(ColumnDef::new(Post::DeletedAt)
    .timestamp_with_time_zone().null())
```

See [Migrations](/database/migrations/) for writing and running them
(`nestrs run db up`).

## Field attribute reference

| Attribute | Where | Effect |
|---|---|---|
| `#[expose]` | any column | Read-only on the wire. |
| `#[expose(input(create, update))]` | scalar column | Adds to wire + the named input(s). |
| `#[expose(validate(…))]` | input column | Attaches a `validator` rule to the input field. |
| `#[expose(complexity = …)]` | exposed field / relation | Overrides the GraphQL complexity cost (literal or expression string). |
| `#[expose]` on `HasOne`/`HasMany` | relation | Auto-resolved GraphQL field (needs header `graphql` + `service`). |
| `#[expose(via = "…")]` | `HasMany` | Names which of the child's foreign keys the relation follows — required when it has two to this parent. |
| `#[wire_enum]` / `#[wire_enum(graphql)]` | a column's enum type | Emits the wire derives (serde, schemars, async-graphql `Enum`) routed through the framework. |
