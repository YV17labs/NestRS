One paginator ships in the box: **keyset**, a cursor over the primary key.
It is O(1) on the index, stable under concurrent inserts, and pairs
naturally with UUID-v7 keys. Every `#[crud]`-generated list is
keyset-paginated unless you opt out.

[SeaORM](https://www.sea-ql.org/SeaORM/)'s `Cursor` API drives it.

## Pagination is the default

A `#[crud]` list — REST or GraphQL — is keyset-paginated out of the box:

```rust title="crates/features/src/posts/http/controller.rs"
#[crud(
    service = svc,
    entity = PostEntity,
    output = Post,
    create = CreatePost,
    update = UpdatePost,
)]
impl PostsController {}
```

No `paginate` knob needed — `paginate = cursor` is the default. The one
other value is `paginate = none`, which opts out into the full
(ability-scoped) collection in one response. Even then the backstop holds:
`CrudService::list` never returns more than `LIST_CAP` (1 000) rows, and
logs a `warn` when it truncates. Reserve `none` for small, finite
collections.

## Keyset, the REST shape

The generated `GET /posts` returns a plain `Vec<Post>` body and, when more rows
remain, the next page as an RFC 8288 `Link`. The body stays a flat array so
response masking works unchanged. The link is in the
[OpenAPI document](/openapi/) and, under CORS, exposed to a browser on another
origin without being listed.

```bash frame="terminal"
$ curl -si '/posts?first=20'
HTTP/1.1 200 OK
link: </posts?first=20&after=0193f1b2-...>; rel="next"

[ { "id": "...", "title": "..." }, ... ]

$ curl -si '/posts?first=20&after=0193f1b2-...'
```

Following the link is the whole protocol: it keeps the page size, carries the
cursor, and is built on the path the caller addressed, global prefix and
version included. The last page has no `Link`.

The query carries `first` (page size, defaulting to 20, clamped to
`1..=100`) and `after` (the cursor the previous page's link carries, passed
back as given; absent or empty for the first page). A cursor no page issued
is a `400`, never the first page — a sync loop following `next` never
restarts the collection silently:

```bash frame="terminal"
$ curl -si '/posts?first=20&after=0193f1b2'
HTTP/1.1 400 Bad Request
content-type: application/problem+json

{"type":"about:blank","title":"Bad Request","status":400,"detail":"after is not a cursor this endpoint issued","code":"INVALID_ARGUMENT"}
```

The refusal names the parameter, never the value it was sent.

## Keyset, the GraphQL shape

The generated list query takes the same two cursor arguments and returns a
plain list — the body stays maskable, exactly like REST:

```graphql title="the query a client sends"
query {
  posts(first: 20) {
    id
    title
  }
}
# next page: posts(first: 20, after: "<last id of the previous page>")
```

UUID-v7 keys are time-ordered, so the cursor is the previous page's last
`id`, as its text — no opaque encoding. An `after` that is not one is a
field error naming `after`, never the first page; its `extensions.code` is
`INVALID_ARGUMENT`, as for a malformed `id`. An empty page means you reached
the end.

## What `Page<M>` carries

The keyset shape, before serialization:

```rust title="nest_rs::seaorm::Page"
pub struct Page<M> {
    pub items: Vec<M>,
    pub next_cursor: Option<PageCursor>,
    pub has_more: bool,
}
```

The implementation fetches `limit + 1` rows, truncates the probe row from
`items`, and uses its presence to set `has_more` and `next_cursor`. The
cursor is the last visible row's primary key — present only when there is
more to fetch.

`PageCursor` is that key as a type. It writes the key's own text
(`Display`), reads any spelling of a UUID back (`FromStr`), and refuses
anything else with a `PipeError` that names `after` — the refusal every
edge answers as its native client error. `PageParams::cursor()` reads the
query's `after` that way, an empty one as the first page.

`CrudService::page(first, after)` returns a `Page<E::Model>` directly;
callers paginating a query of their own reach for `Repo::<E>::page(first,
after, extra)`.

## A custom paginated query

When the auto-emitted list does not match — say you want only one author's
posts — pass the filter to `Repo::page` as its `extra` condition. It is
ANDed onto the ability scope, so the keyset, the clamp and the over-fetch
stay the framework's:

```rust title="crates/features/src/posts/service.rs"
impl PostsService {
    pub async fn page_by_author(
        &self,
        author_id: Uuid,
        first: u64,
        after: Option<PageCursor>,
    ) -> Result<Page<entity::Model>, ServiceError> {
        let by_author = Condition::all().add(entity::Column::AuthorId.eq(author_id));
        Ok(Repo::<Posts>::page(first, after, by_author).await?)
    }
}
```

The route reads the query as `PageParams`, and answers a cursor no page
issued with the `400` every list answers, through `pipe_error`:

```rust title="crates/features/src/posts/http/controller.rs"
#[get("/by-author/{author_id}")]
#[authorize(Read, PostEntity)]
#[api(response = Vec<Post>)]
async fn by_author(
    &self,
    req: &Request,
    author_id: Path<Uuid>,
    params: Query<PageParams>,
) -> Result<Response> {
    let after = params.cursor().map_err(|refused| pipe_error(&refused))?;
    let page = self.svc.page_by_author(author_id.0, params.limit(), after).await?;
    let posts: Vec<Post> = page.items.iter().map(Post::from).collect();
    let mut res = Json(posts).into_response();
    if let Some(cursor) = page.next_cursor {
        set_next_link(&mut res, caller_path(req), params.limit(), cursor);
    }
    Ok(res)
}
```

`Repo::page` runs under `scoped(Action::Read)` — the ability filter
applies, and a request without one denies every row (fail-closed).

## Limits

Keyset buys stability under concurrent inserts and O(1) reads on the PK
index by giving up two things: **no total count**, and **no jump-to-page**.

There is no offset paginator in the framework, and no `paginate = page`
mode — one pagination story, one wire shape per surface. A consumer that genuinely needs page numbers and a total — typically an
admin table — writes that operation by hand: a `Repo::scoped(Action::Read)`
query with `.offset()`/`.limit()` plus a `.count()`, returning a shape you
own. The cost is `OFFSET n`, which makes the database walk and discard `n`
rows, so past a few thousand it is a scan.
