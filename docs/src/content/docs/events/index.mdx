import { Aside } from '@astrojs/starlight/components';

An event listener is **a method** on any `#[injectable]` provider, tagged
with `#[on_event]` inside a `#[listeners]` impl block. Importing
`EventsModule` in the app's `AppModule` subscribes every discovered listener
from the fully-assembled container as the boot ends, before the first
lifecycle hook — so an event an `#[on_module_init]` hook emits reaches its
listeners.

An event is any `Clone + Send + 'static` type. Dispatch is in-process and
awaited: `bus.emit(event)` clones the event for each listener registered
on that type and runs them in registration order — **once the emitter's
transaction has committed** when it emits inside one, and never for a write
that rolled back. There is no broker, no retries — for cross-process or
durable work, push a job on the [Queue](/queue/) instead.

## Install

```bash frame="terminal"
cargo add nest-rs --features events
```

## A first listener

A regular `#[injectable]` provider with one decorated method. The
`#[listeners]` attribute marks the impl block; `#[on_event]` marks the
method as a listener for the event type read from its parameter. Here the
`posts` slice fans a post it published out to its GraphQL subscribers:

```rust title="crates/features/src/posts/events/listener.rs (from the demo)"
use std::sync::Arc;

use nest_rs::core::injectable;
use nest_rs::events::listeners;

use crate::posts::{PostFeed, PostPublishedEvent};

#[injectable]
pub struct PostsListener {
    #[inject]
    feed: Arc<PostFeed>,
}

#[listeners]
impl PostsListener {
    #[on_event]
    async fn on_post_published(&self, event: PostPublishedEvent) {
        self.feed.publish(event.post);
        tracing::debug!(
            target: crate::posts::TARGET,
            post_id = %event.post_id,
            org_id = %event.org_id,
            "fanned a published post out to subscribers",
        );
    }
}
```

- **`#[injectable]`** makes `PostsListener` a regular DI provider.
  It is a plain provider, not a service: it reacts to a fact, it is not an
  entity's DB gateway.
- **`#[listeners]`** on the impl block orchestrates the per-method
  `#[on_event]` attributes and submits one listener per decorated method.
- **`#[on_event]`** reads the event type from the method's first parameter
  after `&self`. The bus enforces `Clone + Send + 'static` on it through the
  call site. The method returns `()`, as here, or a `Result<(), E>` whose
  error converts into `Box<dyn Error + Send + Sync>` — `anyhow::Result<()>` or
  a crate's own error type. Its two keys, `timeout` and `transactional`, shape
  the call's unit of work: [Event dispatch](/events/dispatch/).

A listener reacts in process, and a reaction lost to a crash is lost. Work
that must survive one — the org's notification of the same publish — is a
[queue](/queue/) job, and the service pushes it inside its own transaction
rather than from a listener: the job is
[written into that transaction](/queue/producing-jobs/#a-push-inside-a-transaction)
and filed once it commits, so a crash after the commit loses nothing and a
refused push fails the request that made it.

## Several listeners on the same provider

The pattern the framework is built for: one `#[injectable]` declares the
deps once, multiple decorated methods share them. Two methods can even
listen to the *same* event; both run, in registration order:

```rust title="crates/features/src/posts/events/listener.rs"
#[injectable]
pub struct PostsListener {
    #[inject]
    feed: Arc<PostFeed>,
}

#[listeners]
impl PostsListener {
    #[on_event]
    async fn on_post_published(&self, event: PostPublishedEvent) {
        self.feed.publish(event.post);
    }

    #[on_event]
    async fn index_for_search(&self, event: PostPublishedEvent) {
        // reindex `event.post_id` for full-text search
    }
}
```

Two inventory entries — `PostsListener::on_post_published` and
`PostsListener::index_for_search` — both pointing at the same instance. Same
`Arc<PostFeed>`, two subscriptions to `PostPublishedEvent`; both run, in
registration order.

<Aside type="caution">
A single `#[listeners]` impl block per struct. Put every listener of a
provider in the same block — same convention as `#[routes]`,
`#[scheduled]`, and `#[processor]`.
</Aside>

## Define an event

The payload is a plain `Clone` struct at the producer's port
(`event.rs`) — the same feature that emits it owns its definition:

```rust title="crates/features/src/posts/event.rs (from the demo)"
use uuid::Uuid;

use super::entities::post::Post;

#[derive(Clone)]
pub struct PostPublishedEvent {
    pub post_id: Uuid,
    pub org_id: Uuid,
    pub post: Post,
}
```

That is the whole event surface — any plain `Clone + Send + 'static`
type. No trait, no derive macro beyond `Clone`. Any listener method whose
parameter is `PostPublishedEvent` subscribes to it.

## Emit an event

The emitter injects `Arc<EventBus>` like any other dep and calls `emit`
once the work is done:

```rust title="crates/features/src/posts/service.rs (from the demo, abridged)"
#[injectable]
pub struct PostsService {
    #[inject]
    bus: Arc<EventBus>,
    #[inject]
    queue: Arc<dyn JobProducer>,
}

impl PostsService {
    pub async fn publish(&self, model: Model, actor_id: Uuid) -> Result<Post, PostError> {
        // …
        let receipt = self.queue.push(NotifyQueue, notification, None).await?;
        // …
        let post = Post::from(&published);
        self.bus
            .emit(PostPublishedEvent {
                post_id,
                org_id,
                post: post.clone(),
            })
            .await;
        Ok(post)
    }
}
```

`publish` writes the post, its notification job and its publication row
inside the request's transaction, so the listeners wait for it: `emit` hands
the dispatch to the unit of work, which runs it once the transaction has
committed and drops it if the transaction rolls back. Subscribers hear of a
post that is published, never of one a failed request un-published — and the
service did not have to say so. The job takes the same road through the
outbox: filed after the commit, never after a rollback. Where nothing is
waiting to commit — a safe request, a job running on the pool, an app with
no database — `emit` returns once every listener has run. Emitting an event
with no subscriber is a no-op (not an error), so adding a listener later does
not require touching the emitter.

## Wire it in

The producer's `PostsModule` lists `imports = [EventsModule]` to inject
`Arc<EventBus>`, and the listener's `events/` adapter imports its port, so the
bus arrives with it — a shared singleton, built once however many modules
import it:

```rust title="crates/features/src/posts/events/module.rs (from the demo)"
use nest_rs::core::module;

use super::listener::PostsListener;
use crate::posts::PostsModule;

#[module(
    imports = [PostsModule],
    providers = [PostsListener],
)]
pub struct PostsEventsModule;
```

The listener feeds the GraphQL subscription, so the GraphQL adapter imports
it, and an app serving that adapter wires the listener with it:

```rust title="crates/features/src/posts/graphql/module.rs (from the demo)"
use nest_rs::core::module;

use super::resolver::PostsResolver;
use crate::authz::graphql::AuthzGraphqlModule;
use crate::orgs::OrgsModule;
use crate::posts::{PostsEventsModule, PostsModule};
use crate::users::UsersModule;

#[module(
    imports = [PostsModule, PostsEventsModule, OrgsModule, UsersModule, AuthzGraphqlModule],
    providers = [PostsResolver],
)]
pub struct PostsGraphqlModule;
```

## Run it

As the boot ends, each wired listener logs one line at `debug`, target
`nest_rs::events`:

```text frame="terminal"
DEBUG nest_rs::events: wired event listener listener="PostsListener::on_post_published"
```

Each listener call then runs as a unit of work of its own, `events.dispatch`,
and files one operation line naming the event and the listener.
[Event dispatch](/events/dispatch/) covers that unit — its transaction, its
deadline, the order the bus keeps and what a failure changes.

<Aside type="caution">
Without `EventsModule` anywhere in the tree, the `EventBus` is absent —
every `#[listeners]` provider compiles in but stays inert (no
subscription is wired). This is the same "linked but unreachable"
property the rest of the framework relies on: an app that does not want
the bus omits the module.
</Aside>

## Module-gated, even when the crate is shared

A worker app that links `features` for the data layer but only imports
`PostsModule` keeps `PostsListener` inert: the inventory entry is
present in the binary but skipped at boot because the provider is not reachable
from the worker's module tree. The skip is said once on `nest_rs::events` — at
`debug`, since a listener in a shared crate whose module this app does not import
is another binary's, and at `warn` with a `hint` naming the remedy when it is the
app's own code. Same property as queue processors and scheduled jobs.
