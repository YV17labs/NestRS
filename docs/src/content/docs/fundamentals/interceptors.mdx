An interceptor wraps a unit: an HTTP request a route serves, today, and every
other edge's unit as each moves onto the same pipeline. It sees the unit before
the handler runs, holds the outcome after, and in between calls
`next.run(cx)` to run whatever sits inside it — another interceptor, and
eventually the handler. One call, both sides of the boundary.

`Interceptor` is a [`Layer`](/fundamentals/request-lifecycle/) sub-trait in
`nest_rs::core`, edge-neutral: it reads the unit through its
[`UnitContext`](/fundamentals/guards/), the same context a guard reads, and
reaches the HTTP request and reply through `HttpView::of(cx)`.

```rust title="nest_rs::core::Interceptor"
#[async_trait]
pub trait Interceptor: Layer {
    async fn intercept(&self, cx: &mut UnitContext<'_>, next: Next<'_>) -> Outcome;
}
```

`Outcome` says whether the unit ran or was answered, and only running the rest
of the unit or answering it mints one: an interceptor that does neither does
not compile. `next.run(cx)` consumes `next`, so the rest of the unit runs once.

<Aside type="caution">
**HTTP routes run them today.** GraphQL, WebSocket, MCP and the job edges move
onto the same pipeline during 7.0; until an edge has, `#[use_interceptors]`
beside its decorator is a compile error naming the edge, and the app's global
interceptors do not reach its units.
</Aside>

Same vocabulary as a guard, different shape:

- A **guard** runs *before* the handler and admits or refuses.
- An **interceptor** runs *around* it — it can time the call, add response
  headers, read what was answered, or answer in the handler's place.

## Install

```bash frame="terminal"
cargo add nest-rs
```

The trait, `#[interceptor]` and the specs live in `nest_rs::core`, which every
build has: no feature turns them on.

## A minimal interceptor

```rust title="apps/api/src/interceptor.rs"
use nest_rs::core::{Interceptor, Layer, Next, Outcome, UnitContext, async_trait, injectable};
use nest_rs::http::{HeaderValue, HttpView};

#[injectable]
#[derive(Default)]
pub struct Tracer;

impl Layer for Tracer {}

#[async_trait]
impl Interceptor for Tracer {
    async fn intercept(&self, cx: &mut UnitContext<'_>, next: Next<'_>) -> Outcome {
        let outcome = next.run(cx).await;
        if let Some(resp) = HttpView::of(cx).ok().and_then(HttpView::response_mut) {
            resp.headers_mut().insert("x-trace", HeaderValue::from_static("hit"));
        }
        outcome
    }
}
```

A plain `#[injectable]` provider that implements `Interceptor`, listed in a
module's `providers = [...]` and then bound for the whole app, per controller
or per handler.

`async_trait` comes from `nest_rs::core`, as it does for guards: the trait is
declared under `#[async_trait]`, and an `async fn` written without the same
macro no longer matches it (`E0195`).

## The three scopes

| Scope | Binding | Runs |
|-------|---------|------|
| **Global** | `App::builder().use_interceptors_global([interceptor::<Tracer>()])` in `main` | around every route's handler, after its guards |
| **Controller** | `#[use_interceptors(Tracer)]` on the struct | around each of its handlers |
| **Per-handler** | `#[use_interceptors(Tracer)]` beside a verb | around that handler |

```rust title="crates/features/src/api/http/controller.rs"
#[controller(path = "/api")]
#[use_interceptors(Tracer)]
pub struct ApiController {
    #[inject] svc: Arc<ApiService>,
}

#[routes]
impl ApiController {
    #[get("/cache")]
    #[use_interceptors(CacheControl)]
    async fn cached(&self) -> Json<Snapshot> { /* ... */ }
}
```

Several interceptors in one attribute run outermost-first: the first listed
sees the unit before the second, and its outcome wraps the second's. The app's
global list runs outside the controller's, which runs outside the handler's.

## TypeId dedup — redeclaration is free

Like every other [`Layer`](/fundamentals/request-lifecycle/), an `Interceptor`
declared globally and redeclared on the controller or method runs **exactly
once** per unit, at the broadest scope that declares it. See
[Guards / Declare on the provider](/fundamentals/guards/#declare-on-the-provider)
for the worked example and the defense-in-depth argument.

## Brought by a module: `#[interceptor]`

For infrastructure a module brings with its import, write `#[interceptor]` on
the struct instead of `#[injectable]`. The struct is a singleton provider like
any other, and importing its module adds it to every route's handler stage —
after the app's global list, in import order, no `#[use_interceptors]`
anywhere.

```rust title="crates/features/src/audit/interceptor.rs"
#[interceptor]
#[derive(Default)]
pub struct Audit;
```

## The unit stage: `#[interceptor(stage = unit)]`

Every interceptor above runs **after** the guards and the posture's class
gate: a caching interceptor can never answer a caller the route refuses. The
one opening is an interceptor its module declares at the unit stage, around
the guards:

```rust
#[interceptor(stage = unit)]
#[derive(Default)]
pub struct Timing;
```

It runs on every HTTP unit — a route, a self-mount's request (`/graphql`,
`/mcp`, a gateway's upgrade, the OpenAPI document) and what the router answers
itself (a `404`, a `405`) — and observes what the guards refused. It is the
place for what must see every answer: `Server-Timing` and the RFC 9728
challenge `nest-rs-oauth-resource` adds to a `401` sit there. Writing
`stage = unit` is the visible line that opens it; an app-listed global
interceptor never runs before the access decision.

## What an interceptor cannot change

The data unit of work wraps the whole pipeline, guards included, and commits
on the unit's own outcome. An interceptor changes what the client reads,
never whether the unit failed: once the rest of the unit failed, an `Ok` an
interceptor returns stays a failure — answered with its reply, the original
error kept, one `warn` naming the interceptor — so a failed request still
rolls its writes back.

## Common things an interceptor does

- **Decorate the reply** — headers (`Server-Timing`, `X-Cache-Status`), read
  through `HttpView::of(cx)?.response_mut()` once `next.run(cx)` returned. The
  request is still there beside it, its head and extensions whole: only its
  body is gone once the handler read it.
- **Time the call** — measure latency by route, emit a metric.
- **Answer instead** — a cache answers through `HttpView::of(cx)?.respond(..)`
  and returns its `Settled` without running the rest of the unit.
- **Audit** — record what the unit answered, as the demo's posts controller
  does.

The trace, the `actor_id` and the request scope are not on that list: the edge
installs them before any layer runs, see
[Correlation](/fundamentals/correlation/).
