A slow upstream holds every request that calls it, and a down one is hammered by
every retry. Decorate the method making the call: its body runs under a
resilience policy that bounds each attempt, sends an idempotent call again, and
stops calling the dependency while it fails or past the rate it allows. Your
client is then answered `503` with a `Retry-After` instead of a hung request.

```rust title="crates/features/src/posts/service.rs"
use std::sync::Arc;

use nest_rs::core::injectable;
use nest_rs::resilience::{ResilienceError, ResiliencePolicy, resilient};
use uuid::Uuid;

use crate::posts::{config::PostsConfig, error::UpstreamError, upstream::Upstream};

#[injectable]
pub struct PostsService {
    #[inject]
    upstream: Arc<ResiliencePolicy<Upstream>>,
    #[inject]
    config: Arc<PostsConfig>,
}

impl PostsService {
    #[resilient(upstream, idempotent)]
    pub async fn preview(&self, post: Uuid) -> Result<String, ResilienceError<UpstreamError>> {
        let url = format!("{}/previews/{post}", self.config.upstream_url);
        Ok(reqwest::get(url).await?.text().await?)
    }
}
```

## Install

```bash frame="terminal"
cargo add nest-rs --features resilience
cargo add reqwest@0.13 thiserror@2.0 uuid@1.29
```

The second line is there because the client, the call's error and the post's id
are yours, as [calling another service](/fundamentals/calling-another-service/#install) says.

## Wire it in

A policy is named by an instance marker, one per dependency, and the module
whose provider injects it imports `ResilienceModule<Upstream>` bare. Every
module importing one instance shares its one policy, so one breaker counts the
failures of every caller.

```rust title="crates/features/src/posts/upstream.rs"
use nest_rs::core::instance;

#[instance]
pub struct Upstream;
```

```rust title="crates/features/src/posts/module.rs"
use nest_rs::core::module;
use nest_rs::resilience::ResilienceModule;

use crate::posts::service::PostsService;
use crate::posts::upstream::Upstream;

#[module(imports = [ResilienceModule<Upstream>], providers = [PostsService])]
pub struct PostsModule;
```

The bare import reads `<PREFIX>_RESILIENCE__UPSTREAM__*`, the default instance's
`<PREFIX>_RESILIENCE__*`, and a root pins a base they overlay with
`ResilienceModule::for_root((Upstream, ResilienceConfig { .. }))`. The upstream's
address is the deployment's, [`PostsConfig`](/configuration/)'s `upstream_url`:
`preview` calls that one host, whatever post it is asked for.

## Run a call

`#[resilient(upstream)]` runs the method's body once. `#[resilient(upstream,
idempotent)]` runs it again after a failure or a timeout, up to the policy's
retries, each retry waiting a jittered backoff first. The choice is yours to
make, and nothing else makes it: replaying a call that is not idempotent would
charge a card twice.

The field is the method's own `#[inject]`, so a boot whose modules do not import
`ResilienceModule<Upstream>` is refused, naming the import. The method answers
`Result<T, ResilienceError<E>>`, an alias included. Its body is written as the
undecorated method's, as if it answered `Result<T, E>`. A `?` converting your
error, `Ok(..)`, `Err(e)` and an early `return` each end one attempt, run once
or again alike. Each answer is coerced as that method would coerce it — a
`&String` into the `&str` it returns, a box into its `Box<dyn …>`.

It goes on a provider, a struct you build, a trait impl, a route, a socket
message, a queue job, a scheduled tick, a listener, a health indicator, a
lifecycle hook, an MCP tool, prompt, resource or listing, and a GraphQL query,
mutation, field resolver or entity. `#[operations]` puts an operation's other
attributes on the field it generates; in a build where any crate enables
`resilience` — Cargo unifies a package's features across a build — it reads one
named `resilient`, by any path, as this decorator, kept on your method, so an
attribute of yours by that name is imported under another. On an `#[sse]` route
or a `#[subscription]`, it runs the call opening the stream, never the items it
yields: a stream calling the dependency per item calls a decorated method each.

A method pins its own `timeout`, and an idempotent one its own `retries`, in
place of the policy's: `#[resilient(upstream, idempotent, timeout = "2s",
retries = 3)]`. The unit's deadline still ends every attempt. Every other
setting — the backoff's, the breaker's, the bulkhead's, the rate limit's — is
the policy's, shared by every method calling the dependency: a key naming one,
before the field or after it, is refused with the variable and the
`ResilienceConfig` field that set it. An idempotent body reads its arguments
again at every attempt, so it binds none `mut` and takes no `&mut`, both refused
at compile time, and clones what an attempt consumes: a consumed argument is
rustc's `E0507`, whose help writes the clone. Every attempt borrows them, so its
future is `Send` only where each argument it takes by value is `Sync`.

**No attempt outlives its unit.** Each attempt ends at its timeout or at the
deadline of the unit it runs in — the request timeout on HTTP, a message's on a
socket, a job's on the queue — whichever comes first, and counts as a timeout,
in the breaker too. No retry starts whose wait would end past that deadline.

A call that is part of a method, or needs its attempt's `CancellationToken`,
takes the policy's own `run` or `run_idempotent`:
`self.upstream.run_idempotent(|cancel| async move { … }).await`. The token is
cancelled when the policy gives the attempt up, reaching work the call handed to
another task, which dropping the attempt's future does not.

## What counts as a failure

**Every `Err` counts as the dependency failing**, for the retry and for the
breaker. An answer the dependency gave is the call's `Ok` — `Ok(None)` for a
page it does not have, `Ok(Err(declined))` for a card it declined — neither
attempted again nor counted as a failure. Written so, `preview` answers `None`
for a post the upstream has no preview of:

```rust title="crates/features/src/posts/service.rs"
#[resilient(upstream, idempotent)]
pub async fn preview(&self, post: Uuid) -> Result<Option<String>, ResilienceError<UpstreamError>> {
    let url = format!("{}/previews/{post}", self.config.upstream_url);
    let page = reqwest::get(url).await?;
    if page.status() == reqwest::StatusCode::NOT_FOUND {
        return Ok(None);
    }
    let page = page.error_for_status()?;
    Ok(Some(page.text().await?))
}
```

A `404` is the upstream's answer; a `503` is `error_for_status`'s `Err`,
attempted again and counted as a failure. An error whose chain carries a
`Problem` with a `Retry-After` — an upstream's `429` passed on — holds its retry
back at least that long. One asking past `BACKOFF_CEILING_MS` ends the run.

**The `Result` is the fallback.** The decorator takes no `fallback` key: a body
run once has consumed the arguments a fallback would need. The code calling the
method chooses what stands in for what. `link_card` answers what `preview` does,
but no card while the policy refuses the call: its breaker open, its rate spent,
its bulkhead full, its attempt out of time. It files that refusal at `warn` with
its chain, so the default is never silent, and answers the upstream's own
failure as the service's error:

```rust title="crates/features/src/posts/service.rs"
pub async fn link_card(&self, post: Uuid) -> Result<Option<String>, UpstreamError> {
    self.preview(post).await.or_else(|error| match error {
        ResilienceError::Failed(failed) => Err(failed),
        refused => {
            let error = nest_rs::core::error_message(&refused);
            tracing::warn!(target: crate::posts::TARGET, %error, "link preview refused; answering no card");
            Ok(None)
        }
    })
}
```

## What the client is told

A refusal of the policy is a `ResilienceError` every edge answers `503`, `UNAVAILABLE`:

| Variant | When | Retry-After |
|---|---|---|
| `TimedOut` | the last attempt ended at its timeout or at the unit's deadline | none |
| `Open` | the breaker is open; the call was not sent | the time until it lets a call through, rounded up |
| `Full` | every slot of the bulkhead stayed taken for as long as the call waits, or as many calls as may wait were waiting; the call was not sent | none |
| `Limited` | the rate limit's window is spent, and its reset lies past what the attempt may wait; the call was not sent | the time to the window's reset, rounded up |
| `Failed` | the call answered its own error on its last attempt | what that error's `ToProblem` says, else a `Problem` its chain carries; opaque `500` otherwise |

The call's error says what its own failure tells a client, so it implements
`ToProblem` — answering nothing, for a failure no client should read — and
keeps reqwest's error without the URL that error quotes:

```rust title="crates/features/src/posts/error.rs"
use nest_rs::core::{Problem, ToProblem};

#[derive(Debug, thiserror::Error)]
#[error("the upstream failed")]
pub struct UpstreamError(#[source] reqwest::Error);

impl From<reqwest::Error> for UpstreamError {
    fn from(error: reqwest::Error) -> Self {
        // A URL can carry a token, and no payload value reaches a line.
        Self(error.without_url())
    }
}

impl ToProblem for UpstreamError {
    fn to_problem(&self) -> Option<Problem> {
        None
    }
}
```

A route, a resolver, a gateway's message or a tool then returns
`ResilienceError<UpstreamError>` as it is; a domain error of your own wrapping it
hands its problem on with `self.0.to_problem()`. A queue job refused by an open
breaker or a spent rate waits at least the refusal's `Retry-After`, up to an hour.

## The circuit breaker

The breaker opens once `BREAKER_FAILURES` of the latest `BREAKER_WINDOW` attempts
failed, ten of twenty by default, and refuses every call unsent, its client answered
`503` at once, until its probes close it: [Circuit breaker](/fundamentals/circuit-breaker/).

## The bulkhead and the rate limit

`CONCURRENCY` bounds the calls running inside the policy at once, and
`RATE_LIMIT` the attempts it sends per window, a retry included, both off by
default; a call past either waits or is refused `Full` or `Limited`, unsent:
[Bulkhead and rate limit](/fundamentals/bulkhead-and-rate-limit/).

## Logs and counters

Every line is on `nest_rs::resilience` and names the policy's `instance`, every
duration in whole milliseconds rounded up; a `debug` line adds the `host` and
`method` of the decorated method that ran it. A retry files
`attempt failed; retrying the call` at `debug`, with its `attempt` and `wait_ms`,
and so does a retry left but not made:
`no time left before the unit's deadline; not attempted again` with its `wait_ms`,
or `the dependency asked a wait past the backoff's ceiling; not attempted again`
with its `asked_ms` and `ceiling_ms`. Each mechanism's own lines are on its page.
Once telemetry exports, every policy counts its breaker's transitions, its retries
and the refusals its runs end on: [the counters](/opentelemetry/metrics/#resilience-policies).

## Configuration

Each key is read under `<PREFIX>_RESILIENCE__` for the default instance and
`<PREFIX>_RESILIENCE__<INSTANCE>__` for a named one, and pinned through the
`ResilienceConfig` field it names, its unit left off: `timeout` for `TIMEOUT_MS`.
These four bound an attempt and its retries. The breaker's five keys are on
[Circuit breaker](/fundamentals/circuit-breaker/#configuration), the bulkhead's and
the rate limit's six on [Bulkhead and rate limit](/fundamentals/bulkhead-and-rate-limit/#configuration).

| Key | Meaning |
|---|---|
| `TIMEOUT_MS` | how long one attempt waits for its answer, the unit's deadline permitting — default `5000`; from `1` to `600000` (ten minutes) |
| `RETRIES` | how many times an idempotent call is attempted again — default `2`; from `1` to `10`, `0` for none |
| `BACKOFF_FIRST_MS` | about how long the first retry waits; each after it waits twice the last, jittered by ±20 % — default `200`; from `1` to `300000`, at most `BACKOFF_CEILING_MS` |
| `BACKOFF_CEILING_MS` | the longest a retry's wait grows to, before its jitter, and the longest `Retry-After` honoured — default `2000`; from `1` to `300000` (five minutes) |

A value out of its range fails the boot naming the variable, and so does a first
wait above the ceiling. A duration set in code is held to its key's ceiling, and
takes at least a millisecond for a `_MS` key, as from the variable, and anything
above zero for a `_SECS` key. Where a key's `0` turns something off, its field's
off is `None`.

## Limits

- **The state lives in the process.** Each replica keeps its own breaker, its
  switch by hand included, bulkhead and rate, as each mechanism's page says.
- **A decorated method answers the policy's error.** One answering an error of its
  own, `Result<T, PostsError>`, calls a decorated one and maps its error.
- **An `async fn` under `#[async_trait]` is a `fn` by the time `#[resilient]`
  reads it**, and is refused: write the trait's method as a native `async fn`.
- **A WebSocket connection hook answers `()`**, so it carries no `#[resilient]`: it
  calls a decorated method — the gateway's own, or a service's — and handles its error.
- **A GraphQL field writes its `Result` out.** `#[operations]` reads a field's
  `Result` by its spelling, so a decorated field answering one through an alias
  is refused, saying to write it out.
