import { Aside } from '@astrojs/starlight/components';

A slow upstream holds every request that calls it, and a down one is hammered by
every retry. Decorate the method making the call: its body runs under a
resilience policy that bounds each attempt, sends an idempotent call again, and
stops calling the dependency while it fails, so your client is answered `503`
with a `Retry-After` instead of a hung request.

```rust title="crates/features/src/posts/service.rs"
use std::sync::Arc;

use nest_rs::core::injectable;
use nest_rs::resilience::{ResilienceError, ResiliencePolicy, resilient};

use crate::posts::error::UpstreamError;
use crate::posts::upstream::Upstream;

#[injectable]
pub struct PostsService {
    #[inject]
    upstream: Arc<ResiliencePolicy<Upstream>>,
}

impl PostsService {
    #[resilient(upstream, idempotent)]
    pub async fn preview(&self, url: &str) -> Result<String, ResilienceError<UpstreamError>> {
        let page = reqwest::get(url).await.map_err(UpstreamError)?;
        page.text().await.map_err(UpstreamError)
    }
}
```

## Install

```bash frame="terminal"
cargo add nest-rs --features resilience
```

## Wire it in

A policy is named by an instance marker, one per dependency, and the module
whose provider injects it imports `ResilienceModule<Upstream>` bare. Every
module importing one instance shares its one policy, so one breaker counts the
failures of every caller.

```rust title="crates/features/src/posts/upstream.rs"
use nest_rs::core::instance;

#[instance]
pub struct Upstream;
```

```rust title="crates/features/src/posts/module.rs"
use nest_rs::core::module;
use nest_rs::resilience::ResilienceModule;

use crate::posts::service::PostsService;
use crate::posts::upstream::Upstream;

#[module(imports = [ResilienceModule<Upstream>], providers = [PostsService])]
pub struct PostsModule;
```

The bare import reads `<PREFIX>_RESILIENCE__UPSTREAM__*`. A root pins a base those
variables overlay with `ResilienceModule::for_root((Upstream, ResilienceConfig { .. }))`,
and the default instance, `ResiliencePolicy`, reads `<PREFIX>_RESILIENCE__*`.

## Decorate the call

`#[resilient(upstream)]` runs the method's body once. `#[resilient(upstream,
idempotent)]` runs it again after a failure or a timeout, up to the policy's
retries, each retry waiting a jittered backoff first. The choice is yours to
make, and nothing else makes it: replaying a call that is not idempotent would
charge a card twice.

The field is the method's own `#[inject]`, so a boot whose modules do not import
`ResilienceModule<Upstream>` is refused, naming the import. The method answers
`Result<T, ResilienceError<E>>`, an alias included, and its body is written as if
it answered `Result<T, E>`: a `?` on your error, `Ok(..)`, `Err(e)` and an early
`return` end one attempt. Everything else on the method stays as written, on any
host: a provider, a struct you build, a trait impl, a route, a field, a message, a
tool, a queue job, a listener or a hook.

A method pins its own `timeout`, and an idempotent one its own `retries`, in
place of the policy's — `#[resilient(upstream, idempotent, timeout = "2s",
retries = 3)]` — and the unit's deadline still ends every attempt. The breaker
and the bulkhead take no pin: their state is the dependency's, shared by every
method calling it. An idempotent body reads its arguments again at every
attempt, so it binds none `mut` and takes no `&mut`, both refused at compile
time, and clones what an attempt consumes: a consumed argument is rustc's
`E0507`, whose help writes the clone.

**Every `Err` counts as the dependency failing**, for the retry and for the
breaker. An answer the dependency gave — a declined card, a parcel it does not
know — belongs in the call's `Ok`: return `Ok(Err(declined))`, and it is neither
attempted again nor counted. An error whose chain carries a `Problem` with a
`Retry-After` — an upstream's `429` passed on — holds its retry back that long.
A fallback is the `Result` you get back: `.or_else(|_| cached())`.

**No attempt outlives its unit.** Each attempt ends at its timeout or at the
deadline of the unit it runs in — the request timeout on HTTP, a message's on a
socket, a job's on the queue — whichever comes first, and no retry starts whose
wait would end past that deadline. An attempt the deadline ended counts as a
timeout, in the breaker too.

A call that is part of a method, or that needs its attempt's
`CancellationToken`, takes the policy's own `run` or `run_idempotent`:
`self.upstream.run_idempotent(|cancel| async move { … }).await`. The token is
cancelled when the policy gives the attempt up, and reaches work the call handed
to another task, which dropping the attempt's future does not.

## What the client is told

A refusal of the policy is a `ResilienceError` every edge answers `503`,
`UNAVAILABLE`:

| Variant | When | Retry-After |
|---|---|---|
| `TimedOut` | the last attempt ended at its timeout or at the unit's deadline | none |
| `Open` | the breaker is open; the call was not sent | the time until it lets a call through, rounded up |
| `Full` | every slot of the bulkhead stayed taken for as long as the call waits | none |
| `Failed` | the call answered its own error on its last attempt | what that error's `ToProblem` says, else a `Problem` its chain carries; opaque `500` otherwise |

The call's error says what its own failure tells a client, so it implements
`ToProblem` — answering nothing, for a failure no client should read:

```rust title="crates/features/src/posts/error.rs"
use nest_rs::core::{Problem, ToProblem};

#[derive(Debug, thiserror::Error)]
#[error("the upstream failed")]
pub struct UpstreamError(#[source] reqwest::Error);

impl ToProblem for UpstreamError {
    fn to_problem(&self) -> Option<Problem> {
        None
    }
}
```

A route, a resolver, a gateway's message or a tool then returns
`ResilienceError<UpstreamError>` as it is. A domain error of your own wrapping
it hands its problem on with `self.0.to_problem()`, and a queue job failing on an
open breaker waits at least its `Retry-After` before its next attempt.

## The circuit breaker

The breaker counts the latest `BREAKER_WINDOW` attempts. Once `BREAKER_FAILURES`
of them failed, it opens: every call is refused at once, unsent, for
`BREAKER_OPEN_SECS`. Then one call probes the dependency while the others are
still refused; its success closes the breaker, its failure opens it again.

On the defaults, the tenth failure among the latest twenty attempts opens it. For
thirty seconds each call is refused unsent, its client answered `503` at once,
its `Retry-After` counting down from `30`, instead of after a five-second
timeout; then one call probes, and the breaker closes or opens for thirty more.

Each transition is a `warn` on `nest_rs::resilience`, naming the instance and the
state it entered. A retry is a `debug` on the same target, and so is a call a
full bulkhead refused; from a decorated method, each names its `host` and its
`method`. Once telemetry exports, every policy counts, by
`nestrs.resilience.instance`:

| Counter | One per |
|---|---|
| `nestrs.resilience.breaker.transitions` | transition, by `nestrs.resilience.breaker.state`: `open`, `half_open`, `closed` |
| `nestrs.resilience.retries` | call sent again |
| `nestrs.resilience.refusals` | run ending on the policy's refusal, by `nestrs.resilience.refusal`: `timed_out`, `open`, `full` |

## Your reqwest client

`ResilienceMiddleware` runs every request your own reqwest client sends under a
policy, so a method calling through that client takes no `#[resilient]` of its
own. It sends again only a request its method declares idempotent (`GET`,
`HEAD`, `PUT`, `DELETE`, `OPTIONS`, `TRACE`, `QUERY`) or one carrying an
`Idempotency-Key`, and only when its body can be sent twice.

```rust title="crates/features/src/posts/client.rs"
use std::sync::Arc;

use nest_rs::reqwest::ReqwestMiddleware;
use nest_rs::resilience::{ResilienceMiddleware, ResiliencePolicy};

use crate::posts::upstream::Upstream;

pub fn upstream_client(
    policy: Arc<ResiliencePolicy<Upstream>>,
) -> reqwest_middleware::ClientWithMiddleware {
    reqwest_middleware::ClientBuilder::new(reqwest::Client::new())
        .with(ResilienceMiddleware::new(policy))
        .with(ReqwestMiddleware::new())
        .build()
}
```

A transport failure, a timeout, and a `408`, `429`, `500`, `502`, `503` or `504`
are attempted again and count in the breaker; any other answer is the
dependency's. A `429`'s or a `503`'s `Retry-After` is waited whole — in seconds,
or an HTTP-date counted from the answer's own `Date`, so no clock skew enters —
and one past `BACKOFF_CEILING_MS` ends the run with that answer. The last answer
comes back as it came; a refusal is a `reqwest_middleware::Error::Middleware`.

<Aside type="caution">
The resilience middleware goes before `ReqwestMiddleware`: each attempt is then
a client span of its own, numbered by `http.request.resend_count`. Added after
it, it refuses every request, unsent, with an error saying so.
</Aside>

## Test it

`nest_rs::testing::HttpsPeer` stands in for the upstream: an HTTPS peer on
loopback presenting a `TestAuthority` certificate, answering each request from a
script — `PeerAnswer::status(503).header("retry-after", "1")`, then
`PeerAnswer::status(200)` — and keeping every request's head, so a test asserts
what was sent again and what each attempt carried.

What your client is told while the dependency is down takes one failure, not ten:
the test's root pins the policy to open on the first, and the next call is
refused unsent.

```rust title="crates/features/tests/integration/posts/service.rs"
use features::posts::{PostsModule, PostsService, Upstream};
use nest_rs::core::module;
use nest_rs::resilience::{ResilienceConfig, ResilienceError, ResilienceModule};
use nest_rs::testing::HeadlessApp;

#[module(imports = [
    ResilienceModule::for_root((Upstream, ResilienceConfig {
        retries: None,
        breaker_window: Some(1),
        breaker_failures: 1,
        ..ResilienceConfig::default()
    })),
    PostsModule,
])]
struct OpeningOnOneFailure;

#[tokio::test]
async fn an_open_breaker_refuses_the_call_unsent() -> anyhow::Result<()> {
    let app = HeadlessApp::builder().module::<OpeningOnOneFailure>().build_headless().await?;
    let posts = app.container().get::<PostsService>().expect("provided");
    let nowhere = "https://127.0.0.1:1/";

    assert!(matches!(posts.preview(nowhere).await, Err(ResilienceError::Failed(_))));
    assert!(matches!(posts.preview(nowhere).await, Err(ResilienceError::Open { .. })));
    Ok(())
}
```

## Configuration

Each key is read under `<PREFIX>_RESILIENCE__` for the default instance and
`<PREFIX>_RESILIENCE__<INSTANCE>__` for a named one, or pinned through
`ResilienceConfig`'s field of the same name.

| Key | Meaning |
|---|---|
| `TIMEOUT_MS` | how long one attempt waits for its answer, the unit's deadline permitting — default `5000`; from `1` to `600000` (ten minutes) |
| `RETRIES` | how many times an idempotent call is attempted again — default `2`; from `1` to `10`, `0` for none |
| `BACKOFF_FIRST_MS` | about how long the first retry waits; each after it waits twice the last, jittered by ±20 % — default `200`; from `1` to `300000`, at most `BACKOFF_CEILING_MS` |
| `BACKOFF_CEILING_MS` | the longest a retry waits, and the longest `Retry-After` honoured — default `2000`; from `1` to `300000` (five minutes) |
| `BREAKER_WINDOW` | how many of the latest attempts the breaker counts — default `20`; from `1` to `10000`, `0` for no breaker |
| `BREAKER_FAILURES` | how many failed attempts in the window open it — default `10`; from `1` to `BREAKER_WINDOW` |
| `BREAKER_OPEN_SECS` | how long it refuses every call before one probes — default `30`; from `1` to `3600` |
| `CONCURRENCY` | how many calls run inside the policy at once, the bulkhead — default none; from `1` to `65536`, `0` for none |
| `CONCURRENCY_WAIT_MS` | how long a call waits for a free slot before it is refused, the unit's deadline permitting — default `0`, refused at once; up to `60000` |

A value out of its range fails the boot naming the variable, and so do two that
cannot work together: a first wait above the ceiling, or more failures than the
window holds.

## Limits

- **The state lives in the process.** Each replica keeps its own breaker and
  bulkhead: a breaker opens on the failures its own replica saw, and a
  dependency failing for one replica is refused by that one alone.
- **One probe at a time.** While it runs, every other call is refused, told to
  wait one timeout.
- **A decorated method answers the policy's error.** One answering an error of
  its own — `Result<T, PostsError>` — calls a decorated method and maps its
  error.
- **An `async fn` under `#[async_trait]` is a `fn` by the time `#[resilient]`
  reads it**, and is refused: write the trait's method as a native `async fn`.
- **A scheduled tick answers `anyhow::Result<()>`**, so it calls a decorated
  method, its `?` converting the error, rather than being one.
- **A GraphQL field writes its `Result` out.** `#[operations]` reads a field's
  `Result` by its spelling, so a decorated field answers
  `Result<T, ResilienceError<E>>`, not an alias of it.
