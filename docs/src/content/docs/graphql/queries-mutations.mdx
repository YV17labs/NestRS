Every top-level operation is an async method on an `#[operations]` impl
block, tagged with `#[query]` or `#[mutation]`. An operation that answers
more than once is a [`#[subscription]`](/graphql/subscriptions/) and
follows the same shape. The method signature
is the wire contract: parameters become GraphQL arguments, the return
type becomes the response shape, and an error short-circuits with a
GraphQL error envelope. There is no separate "schema definition" step —
the registry composes one root `Query` and one root `Mutation` from
every decorated method in the running app.

## A simple query

```rust title="crates/features/src/users/graphql/resolver.rs"
use nest_rs::graphql::{operations, resolver};

#[resolver]
pub struct UsersResolver;

#[operations]
impl UsersResolver {
    #[query]
    #[public]
    async fn user_count(&self) -> i32 {
        42
    }
}
```

`#[public]` is the operation's **access posture**: every `#[query]` /
`#[mutation]` declares one of three, and a method with none does not
compile:

- `#[public]` — a caller with no credential is admitted, and the operation reads
  nothing a grant guards.
- `#[authorize(Action, Subject)]` — ability gate + automatic response
  masking, for a caller a principal backs.
- `#[public(Action, Subject)]` — the same gate and mask on the ability a caller with
  no credential has: [what a visitor reads](/security/authorization/public-reads/).

The posture is **always** one of these visible attributes — a parameter
type is never a posture. A bound mutation acts on a row named by id: it
still carries `#[authorize(Action, Subject)]`, then loads the
`Authorized<A, E>` subject in its body. See
[Database / CRUD](/database/crud/#bound-mutations).

The toy examples on this page are `#[public]`; the service-backed ones at
the bottom carry `#[authorize]`.

On the wire this reads as:

```bash frame="terminal"
$ curl -sX POST http://localhost:3000/graphql \
    -H 'Content-Type: application/json' \
    -d '{"query":"{ userCount }"}'
{"data":{"userCount":42}}
```

The method name is camelCased by async-graphql's own rule: a new word starts
after each `_` **and after a digit**, and a capital after a lowercase letter is
kept — `user_count` is `userCount`, `get_2fa` is `get2Fa`, `userID` stays
`userID`. The framework states that name on the field itself, so the name a
duplicate is checked under is the name served: two methods the rule reads as one
field (`a1_b` and `a_1b` are both `a1B`) are a compile error rather than one body
answering for the other. `#[graphql(name = "…")]` overrides it. Primitive returns map to their GraphQL scalar (`i32` → `Int`,
`String` → `String`, `bool` → `Boolean`).

## Arguments

Add typed parameters and they become required GraphQL arguments;
`Option<T>` makes one nullable.

```rust title="crates/features/src/users/graphql/resolver.rs"
#[operations]
impl UsersResolver {
    #[query]
    #[public]
    async fn label(&self, id: String, locale: Option<String>) -> String {
        let locale = locale.as_deref().unwrap_or("en");
        format!("user {id} in {locale}")
    }
}
```

```bash frame="terminal"
$ curl -sX POST http://localhost:3000/graphql -d \
    '{"query":"{ label(id: \"42\", locale: \"fr\") }"}'
{"data":{"label":"user 42 in fr"}}
```

Validation happens at deserialization: a missing required arg returns
a parse error, a wrong scalar returns a coercion error. Both come back
with no resolver call.

Beyond shape checks, an argument whose type declares `validator` rules is
held to them, and a custom transform binds a [pipe](/fundamentals/pipes/)
per parameter, `Piped<P>`, whose input the SDL shows. A rejection surfaces
in the response's `errors`, under `extensions.code: "INVALID_ARGUMENT"` —
the resolver body never runs.

```rust title="crates/features/src/users/graphql/resolver.rs"
use async_graphql::InputObject;
use nest_rs::core::input;

#[derive(InputObject)]
#[input]
pub struct NameInput {
    #[validate(length(min = 1))]
    name: String,
}

#[query]
#[public]
async fn named(&self, input: NameInput) -> async_graphql::Result<String> {
    Ok(input.name)
}
```

## Returning a typed entity

For anything beyond a scalar, define a `SimpleObject` (output) and
optionally an `InputObject` (input):

```rust title="crates/features/src/users/graphql/resolver.rs"
use async_graphql::SimpleObject;
use nest_rs::graphql::{operations, resolver};

#[derive(SimpleObject)]
pub struct User {
    id: String,
    name: String,
    email: String,
}

#[resolver]
pub struct UsersResolver;

#[operations]
impl UsersResolver {
    #[query]
    #[public]
    async fn user(&self, id: String) -> User {
        User { id, name: "Ada".into(), email: "ada@example.com".into() }
    }
}
```

Every field of `User` is queryable independently:

```bash frame="terminal"
$ curl -sX POST http://localhost:3000/graphql -d \
    '{"query":"{ user(id:\"1\") { name email } }"}'
{"data":{"user":{"name":"Ada","email":"ada@example.com"}}}
```

When you `#[expose]` an entity, the wire DTO is generated for you and
plugs into this slot directly — no second `SimpleObject` to maintain
([Relations](/graphql/relations/)).

## A mutation

`#[mutation]` is the same shape as `#[query]`; the marker swaps the
operation root.

```rust title="crates/features/src/users/graphql/resolver.rs"
use async_graphql::{InputObject, SimpleObject};
use nest_rs::graphql::{operations, resolver};

#[derive(InputObject)]
pub struct NewUserInput {
    name: String,
    email: String,
}

#[derive(SimpleObject)]
pub struct User {
    id: String,
    name: String,
    email: String,
}

#[resolver]
pub struct UsersResolver;

#[operations]
impl UsersResolver {
    #[mutation]
    #[public]
    async fn create_user(&self, input: NewUserInput) -> User {
        User {
            id: "u-001".into(),
            name: input.name,
            email: input.email,
        }
    }
}
```

```bash frame="terminal"
$ curl -sX POST http://localhost:3000/graphql -d \
    '{"query":"mutation { createUser(input: {name: \"Ada\", email: \"ada@example.com\"}) { id name } }"}'
{"data":{"createUser":{"id":"u-001","name":"Ada"}}}
```

`InputObject` makes a struct usable as an argument type; `SimpleObject`
makes one usable as a return type. Both come from `async-graphql`
(re-exported by `nest-rs-graphql`).

Each operation runs as a unit of work of its own: a query on the pool, a
mutation in one transaction. Its root fields resolve one after the other, each
in a savepoint, so a field that answers `null` for an error rolls back what it
wrote — and drops the events it emitted — while the other fields of the
operation commit; a Non-Null one's `null` reaches `data`, and the whole
operation rolls back with it ([GraphQL: one unit per operation](/database/transactions/#graphql-one-unit-per-operation)).

## Reading the request context

A resolver method takes an optional `ctx: &Context<'_>` first
non-receiver argument, the entry point to typed batch loaders. What the
request needs beyond the document is a parameter, as on a route, and no
schema argument:

- **What a guard attached** is `Ambient<T>` — the principal the endpoint's
  guards verified, or what a guard bound on the field derived from it. Absent,
  the field answers the opaque internal error and the type is filed at
  `error`: the guard that attaches it did not run there.
- **A request-scoped provider** is `Scoped<T>`, and the boot checks its
  provider like an `#[inject]`ed one — see
  [Providers](/fundamentals/providers/).

The caller's `Ability` is neither: the field's unit carries it, the one its
class gate checked, and its mask and every read under it see that one.

```rust title="crates/features/src/profile/graphql/resolver.rs"
use nest_rs::core::Scoped;
use nest_rs::graphql::{operations, resolver};

#[query]
#[public]
async fn visits(&self, counter: Scoped<crate::VisitCounter>) -> u32 {
    counter.bump()
}
```

```rust title="crates/features/src/posts/graphql/resolver.rs"
use nest_rs::authz::Update;
use nest_rs::core::ambient;
use nest_rs::graphql::operations;
use nest_rs::seaorm::Authorized;

use crate::Claims;
use crate::posts::{Entity as PostEntity, Post, PostAuthorGuard, PostError, PostsService};

#[operations]
impl PostsResolver {
    #[mutation]
    #[authorize(Update, bind = PostsService)]
    #[use_guards(PostAuthorGuard)]
    async fn publish_post(&self, post: Authorized<Update, PostEntity>) -> Result<Post, PostError> {
        self.svc.publish(post.into_inner()).await
    }

    #[query]
    #[public]
    async fn greeting(&self) -> String {
        match ambient::<Claims>() {
            Some(claims) => format!("hello, {:?}", claims.sub),
            None => "hello, visitor".to_owned(),
        }
    }
}
```

`#[authorize]` refuses an anonymous caller before the method runs, and
`PostAuthorGuard`, bound on the field, reads the claims the endpoint's guards
verified (see [Endpoint guards](/security/authorization/endpoint-guards/)) and
refuses a token naming no user. A `#[public]` operation also admits
anonymous callers, for whom no guard attached any: it reads
`nest_rs::core::ambient::<Claims>()` and decides, as `greeting` does. A
`Ambient<Claims>` there would answer every anonymous call with the internal error.

## Returning a `Result`

A resolver method may return `T` or `async_graphql::Result<T>` — both
work, but a `Result` lets you short-circuit with a typed GraphQL
error:

```rust title="crates/features/src/users/graphql/resolver.rs"
use async_graphql::{Error, Result};

#[query]
#[public]
async fn user(&self, id: String) -> Result<User> {
    if id.is_empty() {
        return Err(Error::new("id must not be empty"));
    }
    Ok(User { id, name: "Ada".into(), email: "ada@example.com".into() })
}
```

The full error story (extensions, codes, mapping `ServiceError`) is
on its own page: [Errors](/graphql/errors/).

## Injecting a service

Reach the service through the resolver struct, then call into it —
this is the same shape every adapter uses:

```rust title="crates/features/src/users/graphql/resolver.rs"
use std::sync::Arc;
use async_graphql::Result;
use nest_rs::authz::{Create, Read};
use nest_rs::graphql::{operations, resolver};
use nest_rs::seaorm::{Authorized, Creatable, ServiceError};

use crate::authz::AuthzGuard;
use crate::users::{CreateUser, Entity as UserEntity, User, UsersService};

#[resolver]
#[use_guards(AuthzGuard)]
pub struct UsersResolver {
    #[inject]
    svc: Arc<UsersService>,
}

#[operations]
impl UsersResolver {
    #[query]
    #[authorize(Read, bind = UsersService)]
    async fn user(&self, user: Authorized<Read, UserEntity>) -> User {
        User::from(&*user)
    }

    #[mutation]
    #[authorize(Create, UserEntity)]
    async fn create_user(&self, input: CreateUser) -> Result<User> {
        let user = self
            .svc
            .create(input)
            .await
            .map_err(ServiceError::from)?;
        Ok(User::from(&user))
    }
}
```

`CreateUser`'s rules run before the body, as they do for the generated
`create_user`: the edge holds every argument it decodes to them, so
`Creatable::create` has nothing left to check. It takes the caller's org from
the `Create` grant that pins it, so the mutation reads no principal. The service stays the single audited choke point to the database.
The
resolver only translates between the wire shape and the service —
`#[authorize(Action, Entity)]` is each operation's access posture,
gating the call against the ambient ability and masking the returned
value automatically. The `#[use_guards(AuthzGuard)]` binding on the
struct scopes each operation to the caller's ability. Authentication runs
at the `/graphql` request, through the
[endpoint guards](/security/authorization/endpoint-guards/)
`AuthzGraphqlModule` declares, and `AuthnGuard` checks HTTP requests only,
so binding it on a resolver is a compile error rather than a check that
passes every operation. The feature's `UsersGraphqlModule`
imports `AuthzGraphqlModule`, which provides `AuthzGuard` (omit it and
boot fails naming the missing guard). See [Database / CRUD](/database/crud/)
for the service contract and [Security](/security/) for the guard wiring.
