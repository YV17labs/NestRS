One flag makes the transport compress responses when the client asks for
it. With `HttpConfig.compression` on, each request's `Accept-Encoding` picks
zstd, brotli, gzip or deflate, weighed as RFC 9110 §12.5.3 reads it, and the
response body is encoded with
[async-compression](https://docs.rs/async-compression) before it leaves the
process. Off by default — in
most deployments a reverse proxy already does this.

```rust title="apps/api/src/module.rs (from the demo, abridged)" {3}
HttpModule::for_root(HttpConfig {
    port: 3002,
    compression: true,
    ..Default::default()
}),
```

## Wire it in

Like every `HttpConfig` field, the flag is dual-path — pin it in code as
above, or set it in the environment:

```bash frame="terminal"
NESTRS_HTTP__COMPRESSION=true nestrs run dev api
```

A client that advertises support gets an encoded body; one that does not
gets plain bytes — the same route, negotiated per request:

```bash frame="terminal"
$ curl -sS -H 'Accept-Encoding: gzip' -D - -o /dev/null localhost:3002/api-json
HTTP/1.1 200 OK
content-type: application/json
content-encoding: gzip

$ curl -sS -D - -o /dev/null localhost:3002/api-json
HTTP/1.1 200 OK
content-type: application/json
```

## What it negotiates

- The coding weighed highest wins, `zstd` first among equals; `gzip;q=0`
  refuses gzip, and an `identity` weighed above every coding is answered
  unencoded. A client sending no `Accept-Encoding` gets plain bytes.
- Every response the layer could have encoded carries
  `Vary: Accept-Encoding`, so a shared cache keeps the encodings apart.
- A request body whose `Content-Encoding` names one of the four codings is
  decoded before the route reads it, still under the transport's body cap.

## Limits

- The layer sits inside CORS, so a preflight (`OPTIONS`, no body) is never
  compressed, and outside the handler, so what the handler returns is what
  gets encoded.
- An event stream is never compressed: an encoder would hold each event back
  until its buffer filled. Neither is a `204`, a `304`, nor a response already
  carrying `Content-Encoding`.
- A partial answer — a `206`, or any response carrying `Content-Range` — is
  sent as written: its range counts bytes before any encoding (RFC 9110 §14.4),
  so an encoded part would name offsets its body does not have.
- Turn it off (the default) when a proxy, CDN, or load balancer in front of
  the app compresses — doing it twice only burns CPU.
