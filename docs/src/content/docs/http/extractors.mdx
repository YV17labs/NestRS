An extractor pulls a typed value out of the request before the handler
runs. `Path<T>`, `Query<T>`, `Json<T>` and `Form<T>` cover the request line,
query string, JSON body and form body; beside them sit the framework-specific
extractors:
the validated `Valid<E>`, the typed header reader `Header<T>`, the
raw-body reader `RawBody`, the spoofable but observation-grade
`ClientIp`, the request-scoped DI resolver `Scoped<T>`, the
guard-attached context reader `Ctx<T>`, and the route metadata a guard reads
through `cx.reflector()`, declared with `#[meta(...)]`.

This page is the reference: one extractor, one example, one rule. The
[Guards](/fundamentals/guards/) for `Ctx<T>` and
[Providers](/fundamentals/providers/) for `Scoped<T>` — tell the story.

## `Json<T>` — typed JSON in and out

Parses the request body into `T`; rejects malformed JSON with `400`.
Works as a return type too — serializes `T`, sets
`Content-Type: application/json`, and feeds the OpenAPI document with
the same schema:

```rust title="crates/features/src/posts/http/controller.rs"
use nest_rs::http::{Json, input};

#[input]
struct CreatePost { title: String }

#[input]
struct Post { id: Uuid, title: String }

#[post("/posts")]
async fn create(&self, Json(body): Json<CreatePost>) -> Json<Post> {
    Json(self.svc.create(body.title))
}
```

For validated bodies, wrap it in `Valid<Json<T>>` (covered next).

## `Valid<E>` and `Piped<P, E>` — validate or transform at the edge

`Valid<E>` runs [validator](https://docs.rs/validator) on whatever the
inner extractor produced. The `E` is usually `Json<T>`, but `Path<T>`
and `Query<T>` work the same way — every extractor that exposes
`IntoInner` is composable:

```rust title="crates/features/src/users/http/controller.rs"
use nest_rs::http::{Json, Valid, input};

#[input]
struct CreateUser {
    #[validate(length(min = 1))]
    name: String,
    #[validate(email)]
    email: String,
}
```

`#[input]` carries `Serialize`, `Deserialize`, `Validate` **and** `JsonSchema`,
so a DTO behind it needs no second derive — not for validation, not for the
OpenAPI document, and not to come back out as `Json<T>`. A DTO derived by hand
carries all four itself; adding one of them *next to* `#[input]` is a
conflicting impl (`E0119`).

```rust title="crates/features/src/users/http/controller.rs"
#[post("/users")]
async fn create(&self, Valid(body): Valid<Json<CreateUser>>) -> Json<User> {
    Json(self.svc.create(body))
}
```

A validation failure returns `400` with a structured field-level error
list — no manual checks in the handler.

`Valid<E>` is the ergonomic shortcut for the more general `Piped<P, E>`:
apply any [transport-agnostic pipe](/fundamentals/pipes/) to whatever
the inner extractor produced. `Valid<Json<T>>` is exactly
`Piped<ValidationPipe<T>, Json<T>>`:

```rust title="crates/features/src/posts/http/controller.rs"
use nest_rs::http::{Path, Piped};
use nest_rs::pipes::ParseUuid;
use uuid::Uuid;

#[get("/posts/{id}")]
async fn show(&self, id: Piped<ParseUuid, Path<String>>) -> Json<Post> {
    let id: Uuid = id.into_inner();
    Json(self.svc.find(id))
}
```

Reach for `Piped` when a reusable pipe exists for the job; `Valid` when
the job is `validator::Validate`.

## `Header<T>` — typed request headers

The header-map twin of `Query<T>`: one struct field per header,
`#[serde(rename = "…")]` spelling the wire name, and an `Option<_>`
field marking the header optional. Lookup is case-insensitive, as HTTP
header names are, and values are parsed into the field's type — a
`u32` field is an integer, not a string you parse in the handler.

```rust title="crates/features/src/notify/http/controller.rs"
use nest_rs::http::{Header, SseStream};
use serde::Deserialize;
use schemars::JsonSchema;

#[derive(Deserialize, JsonSchema)]
struct StreamResume {
    #[serde(rename = "Last-Event-ID")]
    last_event_id: Option<u32>,
}

#[sse("/events")]
async fn events(&self, resume: Header<StreamResume>) -> SseStream {
    self.svc.stream_from(resume.into_inner().last_event_id)
}
```

A missing required header, or a value that does not parse, is rejected
with the same RFC 9457 `application/problem+json` `400` a validation
failure carries. **The rejection names the header and never quotes its
value** — a header is where credentials travel, and a `400` body is
logged, cached and proxied.

Each property becomes an `in: header` parameter in the
[OpenAPI document](/openapi/), `required` following the schema. It
composes like every other extractor: `Valid<Header<T>>` validates the
DTO, `Piped<P, Header<T>>` pipes it.

## `RawBody` — exact bytes, with a size cap

Some handlers need the exact byte string before any parsing — a proxied
protobuf body, a document stored as it was sent. `RawBody` reads the whole body
into [`Bytes`](https://docs.rs/bytes), capped at the transport's
`max_body_bytes` (`RawBody::DEFAULT_LIMIT`, 2 MiB, by default). Past the cap the
request is answered `413 Payload Too Large` — never silently truncated, never
buffered unbounded. Like every extractor it reads after the guards, so a
refused request never had its body read.

```rust title="crates/features/src/posts/http/controller.rs"
use nest_rs::http::{Path, RawBody, Result};
use uuid::Uuid;

#[put("/{id}/source")]
async fn replace_source(&self, id: Path<Uuid>, body: RawBody) -> Result<()> {
    self.svc.replace_source(*id, body.into_inner()).await
}
```

A webhook's signature is a credential, so it is verified in a guard that reads
the same bytes and hands them on, never in the handler — see
[Read the body in a guard](/fundamentals/guards/#read-the-body-in-a-guard).

For a tighter cap on a specific route, take the body and read it under
your own:

```rust title="crates/features/src/posts/http/controller.rs"
use nest_rs::http::{Body, Path, Result};
use uuid::Uuid;

#[put("/{id}/summary")]
async fn replace_summary(&self, id: Path<Uuid>, body: Body) -> Result<()> {
    let summary = body.into_bytes_limit(16 * 1024).await?;
    self.svc.replace_summary(*id, summary).await
}
```

Anything that can deserialize through `Json<T>` should use that instead —
`RawBody` is for handlers that genuinely care about the bytes.

## `ClientIp` — best-effort, observation-grade

```rust title="crates/features/src/users/http/controller.rs"
use nest_rs::http::ClientIp;

#[get("/whoami")]
async fn whoami(&self, ip: ClientIp) -> String {
    format!("you look like {} (forwarded={})", ip.ip, ip.forwarded)
}
```

`ClientIp` resolves against the **transport peer**, and only believes a
forwarding header when that peer is a proxy you listed:

1. No peer address at all (a unix socket, or a proxy that hides it) ⇒
   `0.0.0.0`, `forwarded = false`. The extractor never fails.
2. The peer is **not** in `<PREFIX>_HTTP__TRUSTED_PROXIES` ⇒ that peer is the
   client, `forwarded = false`, and the headers are not read.
3. The peer **is** a trusted proxy ⇒ the client is the **rightmost** hop that
   is not itself a trusted proxy, read from `Forwarded` (RFC 7239) first, then
   `X-Forwarded-For`, then `X-Real-IP`; `forwarded = true`. Hops parse as a bare
   IP, `IP:port`, or a bracketed IPv6 (`[ip]`, `[ip]:port`); a `Forwarded`
   node of `unknown` or an obfuscated `_id` names no address and is skipped.

With no trusted proxy configured — the default — step 2 always wins, so
`forwarded` stays `false` and a header a caller sets changes nothing.

```bash frame="terminal"
# The deployment's ingress, named once. Read by ClientIp *and* the throttler.
NESTRS_HTTP__TRUSTED_PROXIES=10.0.0.1,10.0.0.2
```

**Rightmost, not leftmost.** A proxy appends the address it received the request
from to the right of the chain, so the genuine client is the last hop your
infrastructure wrote; a caller can only prepend, and a prepended entry lands to
the left of it. Keying on the leftmost hop is the spoofable rule.

<Aside type="caution">
Treat the result as **observational** (geolocation hints, sampling keys),
never as an authn or authz input — and as personal data: the framework writes it
on no line and no span, and a line of yours holding it holds personal data. The peer is trustworthy; the hop behind
it is only as trustworthy as the proxy that wrote it — list an ingress here only
if it strips and rewrites the client's own forwarding headers.

The [throttler](/rate-limiting/) resolves the client through this same
mechanism, from this same list, so a request is never rate-limited as one
address and handed to a handler as another.
</Aside>

## `Scoped<T>` — resolve a request-scoped provider

A `#[injectable(scope = request)]` provider is built once per request —
useful for anything that should not outlive the response (a SQL
transaction handle, a per-request audit batch, a user-specific cache).
`Scoped<T>` is how a handler reads it back:

```rust title="crates/features/src/posts/http/controller.rs"
use nest_rs::core::injectable;
use nest_rs::http::Scoped;

#[injectable(scope = request)]
pub struct PerRequestAudit { /* ... */ }

#[get("/posts")]
async fn list(&self, audit: Scoped<PerRequestAudit>) -> Json<Vec<Post>> {
    audit.note("list_posts");
    Json(self.svc.list())
}
```

Two contracts hold:

- `Scoped<T>` falls back to a singleton if no scoped factory exists for
  `T` — convenient, but a singleton should still be reached via plain
  `#[inject]` on the controller. Reserve `Scoped<T>` for genuinely
  request-scoped state.
- The framework installs the request scope as the outermost HTTP wrap
  (before guards and interceptors). A provider the request still cannot
  reach — the scope not installed, or `T` offered by no module — answers
  an opaque `500`, and the type goes to an `error` line on
  `nest_rs::http`, never to the client.

See [Providers](/fundamentals/providers/) for the scope rules — a
request-scoped provider may inject singletons, never the reverse, never
another request-scoped one.

## `Ctx<T>` — read context a guard attached

A guard runs before the handler, can short-circuit with a response, and
can attach a typed value for the rest of the request. `Ctx<T>` is how the
handler reads that value back:

```rust title="crates/features/src/posts/http/controller.rs"
use nest_rs::http::Ctx;
use crate::Claims;

#[post("/posts")]
async fn create(
    &self,
    auth: Ctx<Claims>,
    body: Valid<Json<CreatePost>>,
) -> Json<Post> {
    Json(self.svc.create_in_org(body.into_inner(), auth.org_id))
}
```

`Ctx<T>` rejects with `500` if `T` is absent — a missing context means
the guard that should have set it never ran on this route (a wiring bug,
not a client error). `T` implements `AmbientValue` and `Clone`; the value is
cloned out of the ambient context, so a large one goes in a newtype holding an
`Arc` (`struct Catalog(Arc<Entries>)`), which implements `AmbientValue` itself.

The canonical use is the authenticated principal: `AuthnGuard` runs the
strategy, then attaches a `Claims` (or whatever the resource server's
principal is). Every authenticated handler reads it as `auth: Ctx<Claims>`.
On a `#[public]` route reached with a credential the strategy rejected,
`Ctx<Claims>` answers the `401` that credential earned rather than a `500`.

See [Guards](/fundamentals/guards/) for how to attach a value, and for
the design rule (guards gate and attach; handlers read).

## `#[meta(EXPR)]` — typed route metadata

A route can carry typed metadata a guard reads at decision time —
the cleanest case is a rate-limit guard reading the route's quota. The
decorator declares; the reader picks it up by type.

Declare metadata on the route, or on its `#[controller]` for every route it
serves:

```rust title="crates/features/src/authn/http/controller.rs"
use nest_rs::throttler::{Throttle, ThrottlerGuard};

#[post("/login")]
#[use_guards(ThrottlerGuard)]
#[meta(Throttle::per_minute(10))]
#[api(response = AccessTokenResponse)]
async fn login(&self, body: Valid<Json<LoginDto>>) -> Result<AccessTokenResponse> {
    Ok(self.issuer.grant_password(&body.email, &body.password).await?)
}
```

### Advanced: reading `#[meta]` from a guard

Everything below is for the **guard author**, not the handler — a
handler only declares metadata; the guard reads it back at decision
time:

```rust title="crates/features/src/authn/guard.rs"
async fn check_http(&self, cx: &mut UnitContext<'_>) -> Result<(), Denial> {
    let throttle = cx
        .reflector()
        .get::<Throttle>()
        .copied()
        .unwrap_or(self.default_throttle);
    // ...
}
```

Three rules pin the contract:

- The value type must be `Send + Sync + 'static`. The expression is
  evaluated once, when the route mounts, and every request reads that one
  value through a pointer — never cloned, never shadowed by what a guard
  attaches. The reader resolves by `TypeId`: wrap values of one underlying
  shape in distinct newtypes when they need to coexist, and declare each
  type once per level. A second would be read by nothing, so the compiler
  refuses it when each expression names its type, and the boot when one
  hides it (`Throttle::per_minute(10)`), naming the type and where.
- The method's value of a type wins over its controller's, and a
  controller's value of another type still reads through.
- Scope does not change what a guard reads. The pool executes
  post-routing in the route's guard stage, which carries the route's
  declaration, so a guard bound with `use_guards_global` reads the
  route's `#[meta]` exactly as a `#[use_guards]` one does — see
  [the request lifecycle](/fundamentals/request-lifecycle/).

`#[meta]` is declared the same way on a resolver, a gateway, an MCP host and
their operations, and on a processor's, scheduled tasks' or listeners' impl
block and its methods. Each site keeps both levels in its one declaration, and
a guard's `check` reads a resolver's, a message's or a tool's through
`cx.reflector()` exactly as `check_http` reads a route's.

## `#[public]` — the only universal marker

`#[public]` declares the route's posture, the framework's only universal
route marker. Guards read it through `cx.reflector().posture()`, which
answers `Posture::Public` for it, and decide whether to honor it. The framework itself does *not* act on the
marker — `AuthnGuard`, for example, still runs the strategy on a `#[public]`
route, but lets an anonymous request through instead of returning `401`.
It admits one on `/graphql`, `Posture::InBand`, the same way.

```rust title="crates/features/src/authn/http/controller.rs"
#[post("/login")]
#[public]
#[use_guards(ThrottlerGuard)]
async fn login(&self, body: Valid<Json<LoginDto>>) -> Result<AccessTokenResponse> {
    // ...
}
```
