## The part you cannot forget

A controller that looks like any controller — the security is in what you
*don't* write. Two declarations, and every route is authenticated, tenant-scoped
and field-masked.

<div class="rs-steps">

**Two guards on the struct.** Every route below requires a valid token and an
ability — forgetting one is a boot error, not a 3am incident.

**The handlers are generated.** No security code inside — rows are filtered and
fields masked on the way out, automatically.

**Policy lives in one place.** Which rows, which fields, for whom — one ability
rule, applied to every transport.

</div>

## A modular monolith, deployed per workload

Entities, services and policy live once in a shared `features` crate; each app
under `apps/*` is a thin composition root importing only the transports it
serves. Every workload scales on its own signal, and one app importing them all
is a plain monolith: microservice scaling without the distributed-systems tax.
