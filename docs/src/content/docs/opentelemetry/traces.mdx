Traces come from `tracing` spans. Because `OpenTelemetry::init` links
[`tracing-opentelemetry`](https://crates.io/crates/tracing-opentelemetry) to
the OTel SDK at boot, every framework span is **exported under the trace id the
kernel already decided** — the SDK adopts it rather than minting a second one, so
a log line and the exported span name one request by one value. Every other span
automatically gets a `trace_id`
and exports through OTLP when an endpoint is configured.

## Span targets

**Targets are dotted, lowercase, framework-prefixed.** One target per concern
per crate.

| Layer | Target |
|---|---|
| HTTP request span | `nest_rs::http` — opened by the transport, not by this crate |
| Operation log, one line per unit of work | `nest_rs::operation` — the only target naming a *kind of line* rather than a subsystem; see [The operation log](/opentelemetry/operation-log/) |
| ORM queries | `nest_rs::orm` |
| Relation dataloaders | `nest_rs::loader` |
| Authentication | `nest_rs::authn` |
| Authorization | `nest_rs::authz` |
| WebSocket events | `nest_rs::ws` |
| GraphQL execution and subscriptions | `nest_rs::graphql` |
| MCP operations | `nest_rs::mcp` |
| Queue jobs | `nest_rs::queue` |
| Scheduled jobs | `nest_rs::schedule` |
| Module registration | `nest_rs::module` |
| Lifecycle hooks (`#[hooks]`) | `nest_rs::lifecycle` |
| Application spans | `<crate>::<feature>` (e.g. `features::users`) |

## Custom spans

```rust title="crates/features/src/users/http/controller.rs"
#[get("/{id}")]
#[tracing::instrument(skip(self), fields(user_id = %id.0))]
async fn read(&self, id: Path<Uuid>) -> Result<Json<User>> {
    let user = self.svc.find(id.0).await?;
    Ok(Json(user))
}
```

`#[tracing::instrument]` opens a span that stays current for the *whole* async
fn, across every `.await`. Inside it, use `tracing::info!` for an event.
Always prefer `field = %value` to `format!("{}", value)` — structured fields
serialize cleanly to OTLP and stay filterable in the backend.

<Aside type="caution">
Never hold an entered span guard across an `.await`
(`let _g = span.enter(); something.await`). The guard is thread-local; when the
future yields and resumes on another worker thread the span goes wrong. Use
`#[tracing::instrument]` (above) or `future.instrument(span).await` instead —
both scope the span to the future, not the thread.
</Aside>

## W3C propagation

`traceparent` propagation is automatic on incoming HTTP requests — **behind a
trusted proxy**. The transport, not this crate, decides whether an inbound
`traceparent` may be believed: it is continued when the direct peer is in
`<PREFIX>_HTTP__TRUSTED_PROXIES`, and the trace is **restarted** otherwise, which
is what the specification defines a front gate to do. Without that gate any
client could file its request into a trace of its choosing and set the `sampled`
flag on traffic it generates. The response carries `traceresponse` so a caller
can match a span in their backend to a span in yours.

The W3C propagator is installed even when no OTLP endpoint is set — useful when
a sibling service in your monorepo *does* export and you want the connection
preserved across the hop.

## Sampling

`ParentBased(TraceIdRatioBased(ratio))` — children inherit the parent's
sampling decision, so a request either samples end-to-end or not at all. The
deployment picks the sampler with the specification's own variables, read as
the SDK reads them:

```bash
OTEL_TRACES_SAMPLER=parentbased_traceidratio
OTEL_TRACES_SAMPLER_ARG=0.1
```

A sampler the SDK does not build (`jaeger_remote`, `xray`, a misspelling,
`Always_On` — the names are lowercase) and an argument that is not a number
between 0 and 1 fail the boot naming the variable, where the SDK would sample
every trace in their place. An argument beside a sampler that takes none is
ignored and said at `warn`.

Or pinned, in `main`, under those variables:

```rust title="apps/api/src/main.rs"
let _otel = OpenTelemetry::init_with(OpenTelemetryConfig {
    trace_sample_ratio: 0.1,
    ..OpenTelemetryConfig::from_env()?
})?;
```

The sampler decides which traces leave, and `RUST_LOG` does not: every
unit's span is exported whatever the console writes, so `RUST_LOG=warn`
quiets the console without emptying your traces. A span of your own, or a
library's, is exported where `RUST_LOG` writes it.

The sampler comes from
[`opentelemetry_sdk::trace::Sampler`](https://docs.rs/opentelemetry_sdk).
A pinned ratio outside `[0.0, 1.0]` fails `init_with`, naming
`OpenTelemetryConfig::trace_sample_ratio`.

## The request span

`OpenTelemetry::init` seeds what this crate adds onto the framework's span
constructor, which every edge opens its unit through — there's nothing to
mount, and no per-request interceptor. It does **two** things, and both are
things nothing else can supply:

1. **Links the remote parent** when the transport continued an upstream trace,
   so the exported span is a child of the caller's rather than a second root. A
   *restarted* trace has no parent by definition, and none is invented.
2. **Writes the sampler's decision back** onto the trace context, so an outbound
   `traceparent` — into a queue envelope, back to the caller — reports what this
   deployment actually kept.

Everything else belongs to the transport and exists whether or not this crate is
installed: the span itself, its W3C trace context, the `traceresponse` response
header, and the access log. The span carries the OTel HTTP semantic-convention attributes:
`http.request.method` (a method the conventions know or a route registers,
spelled exactly, or `_OTHER`), `url.path` (the addressed path), `url.scheme`
(`https` or `http`: the client's own, forwarded by a proxy
`<PREFIX>_HTTP__TRUSTED_PROXIES` lists, else the listener's),
`http.route` (the
**matched template**, so a backend groups on something low-cardinality),
`http.response.status_code`, `http.response.body.size` and
`user_agent.original`. It carries no `client.address`, which the conventions
recommend: a client's address is personal data, and a collector keeps what it
receives — no access line carries it either.

**The span is the one place a value the client chose is kept, and only what
the conventions ask for.** `url.path`, `user_agent.original` and — for a
method outside the known set — `http.request.method_original` are the client's
to write. The conventions require or recommend them and the span goes to your
own collector, so it keeps them: a stated exception to the rule that no line
and no reply quotes a client's value, which the
[access line](/opentelemetry/operation-log/#access-log) follows. A header the span
records beyond that set is one that parsed under its grammar: a `traceparent`
the transport did not continue is recorded as the four hex fields it parsed
to, and an `X-Request-Id` from a trusted proxy only in the shape a proxy mints
it — a UUID, or 16 to 64 hex digits, as nginx's `$request_id` is. Anything
else is not recorded. The shape is all the span can check: behind a proxy
that forwards a client's `X-Request-Id`, hex text the client wrote — a secret
minted as hex or as a UUID included — is recorded as a minted id would be.

It is named `{method} {route}` through `otel.name`. `tracing` fixes a span
name to a literal, and one literal for every route makes a trace list
unreadable. A request the router's fallback
answers is named for its mount's catch-all, `GET /{*path}` at the root. A
request neither a route nor the fallback claims is named by its method alone,
never by the URL, and a method outside the known set reads `HTTP` there, as
the conventions spell it.

Body size and duration are measured at **end-of-body**, not at handler return, so
a half-streamed response and a client disconnect both still produce one access
line and one complete span.

The request span and the access event both belong to `nest-rs-http`, and exist
whether or not this crate is installed. What this crate adds is the parent
from an inbound `traceparent` and the sampler's verdict, seeded onto the span
constructor: no interceptor, and no header the access line reads.
Toggle the line with `<PREFIX>_HTTP__ACCESS_LOG=false`; nothing about propagation
or OTLP export changes.

## Statements and commands

Once traces or metrics export, every statement the app's Postgres pool sends and
every command a Redis connection sends is a **client operation**, as the
database conventions name it: a `client` span under the unit that sent it, and
a point in `db.client.operation.duration`.

| Sent | Span name | Attributes |
|---|---|---|
| a Postgres statement | its summary, `SELECT posts` | `db.system.name` (`postgresql`), `db.namespace`, `db.operation.name`, `db.collection.name`, `db.query.summary`, `server.address`, `server.port` |
| a Redis command | the command, `GET` | `db.system.name` (`redis`), `db.namespace` (the database index), `db.operation.name`, `server.address` and `server.port` on one server |
| a Redis pipeline | `BATCH`, or `BATCH GET` when every command is one | the same, and `db.operation.batch.size` |

- **What a statement does, never what it says.** The summary is read off the
  SQL's operation and the first table it names, skipping its literals, comments
  and quoted text; `db.query.text` is not exported, since a hand-written
  statement may carry a value in its text. A Redis command is named by its
  first word, never a key or an argument.
- **A failure says its class.** A Redis refusal records its code (`ERR`,
  `NOSCRIPT`, `WRONGTYPE`) as `error.type`; a failed statement records `_OTHER`,
  since sea-orm reports a failure without its error.
- **A span only under a unit.** An operation sent outside every traced unit —
  a queue worker's poll, the outbox relay's claim — records its duration and no
  span, so a backend is not handed a root trace per poll.
- **Nothing is timed where nothing records.** With traces and metrics both off,
  no driver reads the clock.

sea-orm times what it sends through `execute`, `query_one` and `query_all`,
which is every statement `Repo` sends; `execute_unprepared` and `stream` go
untimed, so a savepoint is not seen. A blocking Redis read
(`XREADGROUP … BLOCK`) is timed for as long as it waited: read its
`db.operation.name` apart.

## An app's own HTTP client

`ReqwestMiddleware`, added to the reqwest client an app builds
([Calling another service](/fundamentals/correlation/#calling-another-service)),
records each request it sends as the HTTP conventions' client operation: a
`client` span named for its method (`GET`, `HTTP` for a method the conventions do
not know) and a point in `http.client.request.duration`, keyed by
`http.request.method`, `server.address`, `server.port` and
`http.response.status_code`; a `4xx` or `5xx` records its status as `error.type`,
a request that never answered `timeout` or `_OTHER`. The `traceparent` it sends
names that span, so the service it called hangs under it.

**Neither the path nor the query is recorded**, where the conventions ask for
`url.full`: a webhook's secret sits in its path, a signed URL's in its query, and
a span is kept by a backend no one audits for them.
