import { Steps, Aside } from '@astrojs/starlight/components';

A queue driver connects the queue port to a storage — a broker, a stream, a
database table. The port owns what consuming a job *is*: the attempt, its
retry budget and backoff, the trace, each method's permits, the lease's
renewal, the drain. Its `QueueWorker` runs all of it on every backend, so a
driver only moves records and keeps leases. At the end of this page your
backend runs every `#[process]` method an app declares, and the port's
behaviour kit proves it keeps the contract. You need a crate,
`nest-rs-<storage>`, depending on `nest-rs-queue`, with `nest-rs-testing` and
its `queue` feature as a dev-dependency.

Every excerpt below is lifted from `nest-rs-queue`'s in-memory test backend or
from the Redis binding, so each compiles and runs in the framework's suite.

<Steps>

1. **Declare the backend.** One `QueueBackend` constant names your storage — its
   OpenTelemetry `messaging.system` — and each optional capability it honours,
   one at a time, never `Capabilities::ALL`:

   ```rust title="from nest-rs-queue's test backend"
   pub(crate) static DELAYING: QueueBackend = QueueBackend::new(
       "memory",
       Capabilities::NONE
           .with(Capability::DelayedPush)
           .with(Capability::Checkpoint),
   );
   ```

   The retry budget, one transaction per attempt and a method's `concurrency`
   are not capabilities: the port keeps all three on every backend. Checkpoint:
   a method declaring `throttle(..)` on this backend fails the boot, naming the
   capability and the backend.

2. **File jobs.** Implement `JobProducer`. The port has refused every option
   your backend does not declare, minted each job's id and sealed each
   envelope; store the record as the bytes it gives you, keyed by
   `envelope.id()`, and never read inside it:

   ```rust title="from nest-rs-queue's test backend, abridged"
   #[async_trait]
   impl JobProducer for Memory {
       fn backend(&self) -> &'static QueueBackend {
           self.inner.backend
       }

       async fn enqueue(
           &self,
           queue: &QueueName,
           envelopes: Vec<Envelope>,
           options: &PushOptions,
       ) -> Result<(), QueueError> {
           // …
           for envelope in envelopes {
               let entry = state.entry(envelope.into_json().to_string().into_bytes());
               // …
           }
           // …
       }
   }
   ```

   A backend declaring `Cancellation` implements `remove`, and `remove_unique`
   beside `UniquePush`. The port waits `BACKEND_TIMEOUT` — twenty seconds — for
   each call, then gives up on it: bound your own round trips well inside that,
   so an outage reaches the caller as your error, with its cause. Checkpoint: a
   push answers a receipt naming the job.

3. **Hand jobs over under a lease.** Implement `JobConsumer`. The worker asks;
   your storage answers in the backend's own words:

   | Call | What it owes |
   |---|---|
   | `prepare` | Ready the storage for the methods, once, at boot, and say how long a call takes to answer at most. |
   | `receive` | At most `ask.max` deliveries, waiting at most `ask.wait` for the first — each **leased in the step that hands it over**, with its delivery count: 1 the first time, one more each time it is handed over again. |
   | `renew` | Extend each lease still yours, **without counting a delivery**; one `LeaseHold` per lease, in order. |
   | `settle` | End one delivery as its `Disposition` says, **in the step that checks the lease is still yours** — and answer `Lost`, writing nothing, when it is not. |
   | `maintain`, `close`, `checkpoint` | Optional: upkeep while nothing runs (a delayed record falling due), letting go at the end of the drain, and a checkpoint store for a backend declaring `Checkpoint`. |

   The fence on `settle` is the heart of it. A worker whose lease lapsed — frozen,
   or cut off from the storage — must write nothing once another delivery holds
   the job:

   ```rust title="from nest-rs-queue's test backend, abridged"
   async fn settle(
       &self,
       _method: &'static ProcessMethod,
       lease: &MemoryLease,
       disposition: Disposition<'_>,
   ) -> Result<LeaseHold, QueueError> {
       let mut state = self.memory.lock();
       if !state.queue(&lease.queue).holds(lease) {
           return Ok(LeaseHold::Lost);
       }
       // …
       match disposition {
           Disposition::Complete => { /* … */ }
           Disposition::Retry { after, record, .. } | Disposition::Defer { after, record, .. } => {
               refile(&mut state, record, after);
           }
           Disposition::Requeue { record, .. } => refile(&mut state, record, Duration::ZERO),
           Disposition::DeadLetter { reason, record, .. } => { /* … */ }
           other => panic!("a disposition the in-memory backend was not written for: {other:?}"),
       }
       // …
       Ok(LeaseHold::Held)
   }
   ```

   `Complete` and `DeadLetter` end the job: let every record of it go — its
   unique key and its checkpoint with it — and keep a dead letter with the
   value-free `reason`. `Retry`, `Defer` and `Requeue` file the record given,
   due once `after` passed, and a record filed again starts its delivery count
   over. A backend without `DelayedPush` is never handed a wait: the port waits
   in process. `Disposition` is non-exhaustive, and a variant added later goes
   only to a backend declaring the capability that names it. Checkpoint: a
   delivery the worker never settles comes back once its lease lapses, with its
   count one higher.

4. **Bind both in one module.** `<Vendor>QueueModule` binds the producer as
   `Arc<dyn JobProducer>` and the consumer as `BoundConsumer`, each a
   **declaration** carrying `BACKEND_REMEDY`, so a second backend imported beside
   yours fails the boot naming both:

   ```rust title="from nest-rs-redis's queue binding, abridged"
   builder
       .provide_declared_factory_after::<Arc<dyn JobProducer>, RedisQueueProducer, _, _>(
           BACKEND_REMEDY,
           |container| async move {
               // …
           },
       )
       .provide_declared_factory_after_both::<BoundConsumer, RedisConnection, RedisQueueConfig, _, _>(
           BACKEND_REMEDY,
           |container| async move {
               // …
               Ok(BoundConsumer::new(RedisQueueConsumer::new(conn, config.lease)))
           },
       )
   ```

   The worker renews a lease a third of the way in, so a lease no renewal fits
   in lapses while your storage still answers: refuse it at boot with
   `nest_rs_queue::lease_fits_renewal(lease, answer_bound)`, naming the settings
   that lengthen the one or shorten the other.

   An app running jobs imports `QueueModule::for_root(None)` beside your module;
   one only pushing does not. Checkpoint: the worker app's boot logs
   `attached module-contributed transport transport="QueueWorker"`.

5. **Run the behaviour kit.** Implement `KitBackend` — an app reaching your
   storage, the lease it holds deliveries for, and three hooks on the storage —
   and let `queue_kit!` write one test per case:

   ```rust title="from nest-rs-queue's suite, abridged"
   impl KitBackend for MemoryKit {
       fn app(&self) -> nest_rs_testing::TestAppBuilder {
           let producer: Arc<dyn JobProducer> = Arc::new(self.memory.clone());
           TestApp::builder()
               .provide(BoundConsumer::new(self.memory.consumer()))
               .provide_dyn(producer)
       }

       fn lease(&self) -> Duration {
           LEASE
       }

       async fn purge(&self, queue: &QueueName) -> anyhow::Result<()> {
           // …
       }

       async fn lapse(&self, queue: &QueueName) -> anyhow::Result<()> {
           // …
       }

       async fn take(&self, queue: &QueueName) -> anyhow::Result<()> {
           // …
       }
   }

   mod delaying {
       use super::MemoryKit;

       nest_rs_testing::queue_kit!(MemoryKit::delaying());
   }
   ```

   `purge` empties a queue, `lapse` makes every lease on it lapse with its
   holder and count unchanged, and `take` hands every delivery to another holder
   that lapses at once — what a frozen worker meets. Checkpoint: eleven tests
   pass, among them a worker dying mid-attempt, a lease taken under a running
   attempt, the stall limit and the drain.

</Steps>

<Aside type="caution">
**Delivery is at least once, and no driver promises more.** A storage that loses
no job delivers some twice — a lease that lapsed under a frozen worker, an
acknowledgement lost — and a `#[process]` handler is idempotent.
</Aside>

## What fails if you get it wrong

- **A settle that does not check its lease** lets two outcomes land for one job:
  the kit's case for a lease taken under a running attempt fails.
- **A renewal that counts a delivery** spends the stall limit on a job that
  answered every time: once its worker dies after a few renewals, the next
  delivery is past `STALL_LIMIT` and dead-letters it without running.
- **A receive handing over more than it was asked** keeps no permit for the
  extra: the worker hands them back and says `queue backend handed over more
  deliveries than asked; …` at `error`.
- **A second backend imported** fails the boot, its message ending in
  `BACKEND_REMEDY`.
- **A capability declared and not honoured** passes the boot and fails the kit:
  a delayed push the backend files at once runs before its delay.
