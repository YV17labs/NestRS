The third layer of authorization runs after the handler returns — and the
80% of this page is one sentence: **declare `#[authorize(Action, Entity)]`
on the route and masking runs automatically after every successful
response**. Fields the caller cannot read are stripped, rows they cannot
see are dropped, and a body that cannot be verified fails **closed** (500)
rather than shipping unmasked. The route never calls `mask` itself.

## Declare it — `#[authorize]`

`#[authorize(Read, user::Entity)]` declares the route's posture, and
`#[routes]` reads it as the type `Authorize<A, S>`, which gates the route and
arms the shaper:

```rust title="crates/features/src/users/http/controller.rs"
use nest_rs::authz::Read;

#[get("/")]
#[authorize(Read, user::Entity)]
async fn list(&self) -> Result<Json<Vec<User>>> {
    Ok(Json(self.svc.directory().await?))
}
```

`directory` is a service method returning `Result<Vec<User>, ServiceError>` —
the `Model` → `User` conversion lives there, so the handler declares a posture
and delegates.

That type, `Authorize<Read, user::Entity>`, does two things:

1. **Class-level gate.** Right after the route's guards, refuses with 403
   unless the ability's `can_class(Read, TypeId::of::<user::Entity>())` is
   true — before any interceptor or filter the route declares, so a cache
   never answers the caller it refuses.
2. **Shaper trigger.** The `RouteResponseShaper` impl wraps the
   handler in `with_ability(ability, inner)` (so `Repo::scoped`
   reads the right ability) and runs `mask_entity_response::<user::Entity>`
   on the way out.

<Aside type="caution">
Write the extractor by hand only where the decorator cannot go: a
`#[public]` route, whose posture is the opposite one
([Public reads](/security/authorization/public-reads/)). There the parameter
is load-bearing even bound as `_authz` — deleting the "unused" parameter
disarms masking for that route.

How you *spell* it does not matter. `#[routes]` hands each parameter type to
the compiler and asks whether it is a `RouteResponseShaper`, so an alias
(`use ... as Foo`), a re-export or any module qualification arms the route
exactly like the canonical name.

One shape stays invisible to that question: an extractor reached **indirectly**
— nested inside another extractor, or run by a hand-rolled `FromRequest`. Such
a route arms nothing, and rather than ship an unmasked body it **fails closed**
— a `500` for every caller — with an `error` on `nest_rs::http` naming the
route and the fix:

```text
ERROR nest_rs::http: a masking extractor ran but no response shaper armed on
  this route — declare it as a handler parameter (a nested or hand-rolled
  extractor is invisible to the type-directed arm); failing closed
  route="get /aliased"
```

Nothing ships unmasked, so this is a wiring error to fix, not an exposure to
audit. Declare the extractor as its own parameter.
</Aside>

The GraphQL analog is `#[authorize(Action, Entity)]` on a
`#[query]`/`#[mutation]` — same declaration, same automatic mask, with
one difference the schema forces: the masked value has to come back as
the operation's own type. A stripped column masks to `null` where the
field is nullable; where it is `String!` — what `#[expose]` emits for a
non-nullable column — it cannot, so an operation that **selects** such a
field is refused and one that does not select it is served. Row dropping
applies either way.

The refusal carries `extensions.code = "FORBIDDEN"` and `extensions.fields` —
a **list** of the column names it refused:

```json
{"data":null,"errors":[{"message":"forbidden","path":["users"],
  "extensions":{"code":"FORBIDDEN","fields":["email","name"]}}]}
```

MCP takes the same declaration beside a `#[tool]` / `#[prompt]`, and pushes the
schema constraint one step further: an operation returns one fixed Rust type to
a model, with no selection set to excuse a stripped **required** field, so such
a mask fails the operation closed. Leave a maskable column `Option` on the
entity, or — when the tool deliberately answers with a projection narrower than
every grant — declare `#[authorize(Action, Entity, unmasked)]` and let the
projection be the field restriction. The gate and the row filter stay either
way.

## What you get

- **Field masking.** Restricted keys are stripped from the object (their
  key is removed, not set to `null`) per the ability's `.fields([...])` grants.
- **Row dropping.** In collection responses, rows the caller cannot read
  drop out entirely.
- **Two-layer defense.** The wire DTO decides what may *ever* ship
  (column-level allowlist — no `#[expose]`, no wire); the `Ability`
  decides what may ship *to this caller*. A column on neither list never
  leaves — even an unrestricted grant cannot leak an unexposed column
  like `password_hash`.
- **Fail-closed.** A successful body that cannot be reconciled with the
  entity's `Model` yields 500 rather than shipping unmasked. A
  misconfigured route surfaces as a 500 in prod; the alternative —
  shipping unmasked data — is worse.

Non-2xx, non-JSON, and scalar responses pass through untouched.

Pair every masked route with a
[negative-path test](/testing/negative-path/) that pins the masked body
shape — a regression surfaces immediately, not after an audit.

## What the mask cannot see

The mask runs on the value the handler returned, rebuilt into a `Model`.
What the value does not carry is missing from it: a relation, a column
`#[expose]` keeps off the wire, and an exposed column the value's own type
leaves out, which the rebuild would otherwise read as `None`. A rule that
reads any of them — `p.related(…)`, a predicate on a hidden `deleted` flag
or on an `archived_at` the DTO omits — is decided by where the value came
from.

- **A reply** — what an `#[authorize]` operation returns — was read through
  `Repo` under the same ability, and that read's SQL already applied every
  rule. The mask trusts it: a row a relational grant admitted stays, a
  relational denial has already left out the rows it names, and a row's
  fields come from the grants the mask can decide on the row.
- **A push** — a [subscription](/graphql/subscriptions/) item, a
  `masked_reply` value — went through no read. A grant the mask cannot decide
  grants nothing, and such a denial denies, so the item does not ship. The
  first refusal per entity and action logs one `warn` on `nest_rs::authz`
  with `reason = "undecidable_on_push"`.

A rule on a column the value does carry is decided on the spot, so a feed
scoped by `org_id` keeps working: expose the column the rule reads,
read-only, and pushed rows are decided like any other.

`masked_reply` masks for the caller whose ability is ambient — the right
answer for a reply to that caller. A push to *other* connections
(`WsServer::emit`, `broadcast`) is not masked per recipient: send only what
every recipient may read.

## How it works (internals)

<Aside type="note">
Everything below is the mechanism, not the surface — first-time builders
can stop here and come back when they hit a hidden column `#[expose]`
cannot default or want to audit the fail-closed path.
</Aside>

### The pipeline after a 2xx

```text
Handler returns Json<UserWire>
       │
       ▼
  body in bytes
       │
parse JSON → Value
       │
wire_to_model::<S>     ← fill unexposed columns via WireModelDefaults
       │
ability.mask::<S>      ← typed: filters by row, masks by field
       │
retain_wire_keys       ← drop anything not on the wire DTO
       │
serialize → response body
```

Each step has a defined failure mode:

- **Parse fails** (the body was not JSON) → 500. Fail closed.
- **`wire_to_model` fails** (object shape does not match `Model`) →
  500. Fail closed — and the same for a failure on any array element,
  or a re-serialize failure.
- **`Ability::mask` runs** — any row the caller cannot read drops
  out (collection responses) and every restricted key is stripped from
  the object (`map.retain` keeps only the permitted keys).
- **`retain_wire_keys`** — strips back any field the wire DTO never
  carried.

### `Ability::mask` — what it strips

```rust title="nest_rs::authz::Ability::mask"
pub fn mask<E>(&self, action: Action, model: &E::Model) -> serde_json::Value
```

Serializes the model, then keeps only the fields permitted by the
matching grants. The rule shape (`.fields([cols])`) decides; the
union across matching grants wins.

```rust title="nest_rs::authz::Ability::mask_many"
pub fn mask_many<'m, E>(
    &self,
    action: Action,
    models: impl IntoIterator<Item = &'m E::Model>,
) -> Vec<serde_json::Value>
```

For a collection read through `Repo` for the same action: drops the
models the caller cannot see, masks the rest. A rule the row cannot
decide counts as that read counted it — where `Ability::can`, which
knows of no read, refuses on such a denial. The `retain_wire_keys` step
runs per item afterwards.

A grant with no `.fields` returns `FieldSet::All` — every column is
permitted. A grant with `.fields([Id, Name])` returns
`FieldSet::Only({"id", "name"})`. The masker unions:
`FieldSet::Only(union_of_grants)` unless any matching grant is
`FieldSet::All`, which clears the restriction. A grant the mask cannot
decide on the row widens nothing; when only such grants admitted a row
read through `Repo`, it keeps the fields every one of them permits.

### `retain_wire_keys` — the defense in depth

After `Ability::mask` produces a `serde_json::Value`, the shaper keeps
only the keys the body carried among those `#[expose]` lists for the
entity — `WireModelDefaults::wire_keys`. A key the body left out never
comes back with the value the rebuild gave it.

Why this step exists: an `Ability` grant with no `.fields` permits
every column on the `Model`. If the `Model` carries a
`password_hash` field (server-only, never carries `#[expose]` so it is
absent from the wire DTO), an unrestricted grant would have it pass `Ability::mask`
untouched. `retain_wire_keys` then drops it, even from a handler that
returned the raw `Model`.

### `WireModelDefaults` — filling the gaps

To run `Ability::mask` the shaper needs a typed `S::Model`. The wire
body, by design, omits every unexposed column. `WireModelDefaults`
fills them with placeholder values so deserialization succeeds, and
says which columns it filled:

```rust title="nest_rs::authz::WireModelDefaults"
pub trait WireModelDefaults: EntityTrait {
    fn fill_wire_defaults(_map: &mut Map<String, Value>) {}
    fn wire_keys() -> Option<&'static [&'static str]> { None }
    fn is_placeholdered(_column: Self::Column) -> bool { false }
    fn wire_key(column: Self::Column) -> Option<&'static str> { /* its name, if a wire key */ }
}
```

The `#[expose]` macro emits the impl: every unexposed scalar column gets
a JSON default (`""`, `0`, `false`, `null`), `is_placeholdered` names
exactly those columns, and `wire_key` names the key each exposed column
crosses the wire under, so a rule is never decided on a placeholder or
on a column the body left out
([What the mask cannot see](#what-the-mask-cannot-see)).
The defaults are discarded again by `retain_wire_keys` before the body
ships — they never reach the wire.

A hidden column of any other type — a non-`Option` `Uuid` or timestamp,
a `Decimal`, a custom enum — has no automatic placeholder, so the
round-trip fails closed. Give it one with `#[wire_default]`, the type's
`Default`, or `#[wire_default(expr)]`:

```rust title="crates/features/src/users/entities/user.rs"
#[wire_default]
pub role: UserRole,
```

A handler returning a body that does not deserialize even with
defaults yields 500 with `"response masking failed: body did not
match the authorized subject type"`. The test bench is the right
home for noticing this — a unit test that runs the shaper against
the handler's `Json<T>` shape pins it.
