Every `nest-rs-*` crate ships at one version, and no 7.x release breaks what
you build on: your code compiles, your configuration boots, and your log
filters and alerts keep matching. A minor adds, a patch fixes, and a break
waits for 8.0. This page is that contract — what it covers, what it leaves
out, and how a package of your own depends on NestRS.

```toml title="Cargo.toml"
[workspace.dependencies]
nest-rs = { version = "7.2", features = ["http", "config", "seaorm"] }
```

`7.2` is the oldest release the workspace accepts, and every later 7.x builds
it unchanged; `cargo update` takes the newest.

## What 7.x keeps

A break is a change to something a program or an operator matches. Everything
in the middle column holds until 8.0:

| What you build on | Kept until 8.0 | Not covered |
|---|---|---|
| Rust items | every public item of every published crate, reached through no `__private` module, no `__`-prefixed item and no hidden item | the `__private` tier (below), and `nest-rs-cli`'s library, whose binary is the product |
| Decorators | every key and what it means — refusing a program that used to compile is a break | the wording of a compile error |
| Configuration | every `<PREFIX>_<NAMESPACE>__<KEY>` variable, its spellings and its default, and every `#[config]` field name | a literal naming every field of a config (below) |
| Wire and storage | `nest_rs::queue::Envelope` and its `WIRE_FORMAT_VERSION`, the `nest_rs::http::ProblemDetails` body, the `nest_rs::ws::WsEnvelope` frame, every `nestrs:` key, and every header NestRS reads or writes, among them the W3C's `traceparent`, `tracestate`, `traceresponse` and `Server-Timing`, the IETF's `Deprecation`, `Forwarded`, `Link`, `Retry-After` and `WWW-Authenticate`, and `X-Forwarded-For`, `X-Real-IP` and `X-Request-Id` behind a trusted proxy | — |
| Observability | span targets, unit names, the operation line's field names and its outcome words, and the words a field such as `cause` takes | the prose of a log message |
| Features and the CLI | the umbrella's feature names, and every `nestrs` command and flag | what `nestrs new` and `nestrs generate` write, which follows the release |

A new refusal is a break too: a program that compiled keeps compiling, and an
app or a configuration that booted keeps booting. Only its message stays
outside, on purpose: a refusal that misleads is reworded in a patch, never kept
for the whole line.

## What a release may change

**A minor adds.** It may add:

- a public item, a decorator key, a variable, a feature or a unit;
- a variant to a `#[non_exhaustive]` enum, or a field to a `#[non_exhaustive]`
  struct or to one with a private field;
- a field to a `#[config]` struct, or to a `Default` struct nested in one;
- a name to `nest_rs::prelude`;
- a third-party library's minor;
- the minimum supported Rust version, named in the changelog.

**A patch fixes.** It corrects behaviour that disagrees with these docs, and
may change anything in the `__private` tier. It never raises the minimum Rust
version: a project held to its toolchain takes a patch without reading it.

## Build a config the way it grows

A `#[config]` struct gains fields in a minor, so name the fields you set and
end on `..Default::default()`:

```rust title="apps/auth/src/module.rs (from the demo, abridged)"
HttpModule::for_root(HttpConfig { port: 3001, ..Default::default() }),
```

A literal naming every field stops compiling when a field arrives, and 7.x
does not cover it. This is the one place the policy departs from Cargo's
SemVer reference, which counts a new public field as a break: a config is the
one struct you write as a literal, and freezing it would freeze every module's
settings for the whole line.

## The `__private` tier

A framework crate whose items its macro expansions or its sibling crates call
holds them in a hidden module named `__private`. It is not API, and it may
change in any release. It stays safe only because every `nest-rs-*` crate
requires its siblings at exactly its own version. Never name it — not
directly, and not as `nest_rs::<concern>::__private` either.

## Writing a package

A package — a driver, a guard, a decorator crate — depends on the umbrella, at
the minor it builds against, with the default features off:

```toml title="crates/yourpackage/Cargo.toml"
[dependencies]
nest-rs = { version = "7.2", default-features = false, features = ["http"] }

[dev-dependencies]
nest-rs = { version = "7.2", default-features = false, features = ["http", "testing"] }
```

- **Name the capabilities your code uses.** The umbrella's defaults are `http`
  and `config`, and Cargo only ever adds features: a package taking them
  compiles HTTP into every app that links it, a headless worker included.
- **Depend on no `nest-rs-*` crate but the umbrella.** The others are
  compilation units, and their `__private` tiers are what moves between
  releases.
- **A decorator crate is the one exception.** A `proc-macro` crate depends on
  `nest-rs-codegen` and uses its root items alone. The code it emits names
  public paths only: your package, built against 7.2, runs in an app on a later
  7.x, where `__private` may differ.
