import { Steps } from '@astrojs/starlight/components';

8.0 is a major release: it takes the designs 7.0's compatibility held back,
whatever they break. An attribute on a GraphQL operation applies to the method
you wrote, a `Problem` is the one thing an edge reads in a handler's error, a
`SafeLink` names the type it says, and a data driver says what each handle holds.
This page is the order to take the changes in; the
[changelog](https://github.com/YV17labs/NestRS/blob/main/changelog/8.0.md) says
why each was made. 8.0 is not released yet, and this page holds the breaks of
its line so far.

You need the 7.0 project building. Most steps are compile errors, so the
compiler finds every site; a step that changes behaviour alone says so, and
[What fails if you get it wrong](#what-fails-if-you-get-it-wrong) lists what the
boot, a log or the wire shows when one is missed. An app on SeaORM with no
`SafeLink` of its own takes steps 1 to 3 alone.

<Steps>

1. **Move the manifest.** In the root `Cargo.toml`, the `nest-rs` requirement
   under `[workspace.dependencies]` goes from `7.0` to `8.0`:

   ```toml title="Cargo.toml"
   # before
   nest-rs = { version = "7.0", features = ["graphql", "seaorm"] }
   # after
   nest-rs = { version = "8.0", features = ["graphql", "seaorm"] }
   ```

   The umbrella's `full` now takes `resilience`, so an app on `full` declaring a
   `#[config]` of its own in the `resilience` namespace fails its boot, its type
   and the framework's both claiming it: give yours another `namespace`, or list
   the features you use in place of `full`. A module of a named instance is
   written as its type, `RedisModule<Cache>`: `RedisModule::<Cache>`, the
   spelling 7.0 taught, is refused at its `::`, naming the type to write.

2. **Read each attribute on a GraphQL operation as the method's.**
   `#[operations]` takes off a method only what it consumes — its role, its
   posture, its layers, `#[meta]` and async-graphql's `#[graphql(…)]` — and
   leaves every other attribute on the method you wrote, as a route's handler
   does ([Attributes on an operation](/graphql/queries-mutations/#attributes-on-an-operation)):

   | On an operation in 7.0 | In 8.0 |
   |---|---|
   | `#[tracing::instrument]` naming the field's parameters, spanning the guards and the pipes | it spans the method's body, after the guards, the gate and the pipes, which the request's `graphql.field` span covers; skip the method's own parameters with no `Debug` — `skip_all`, or its `Scoped<T>`, `Piped<P>` and `&Context` by name — and its `err` records the method's own error |
   | Rust's `#[deprecated]` | `#[graphql(deprecation = "…")]`, which the schema and its introspection show |
   | `#[graphql(…)]` inside a `#[cfg_attr]` | written plain, the condition on the method as a `#[cfg]` |
   | a `deny` or `warn` lint level, plain or under a `#[cfg_attr]`, which held the field | it holds the method's body, so a lint it denies there fails the build |

   `cargo check` then compiles every operation, an instrument reading the
   method's own `self` included.

3. **Say which decode failures are your client's.** A handler whose error
   chain holds a serde error now answers `INTERNAL`, its chain filed at
   `error`, on every edge: GraphQL, WebSocket and MCP answered
   `INVALID_ARGUMENT` and filed nothing, so a partner's answer that did not
   decode was blamed on the client. A handler decoding its client's own text
   says so where it decodes,
   `serde_json::from_str(&text).map_err(|e| Problem::from(DecodeError::from(e)))?`,
   which answers `400` under `INVALID_ARGUMENT` without the value.
   `DecodeError::in_chain` is gone. The rest of this step changes behaviour
   alone:

   - a `PipeError` a handler returns, bare or wrapped in its own error,
     answers `400` `INVALID_ARGUMENT` on HTTP too, where an `anyhow` handler
     answered `500`;
   - an HTTP interceptor failing with the framework's `DecodeError` — a
     `QueueError::Serialize` — answers `500`, where it answered `400`;
   - on MCP, a `Problem` under `INVALID_ARGUMENT`, a `422` included, answers
     `invalid_params` (`-32602`), where it answered `invalid_request`
     (`-32600`).

   A test asserting `INVALID_ARGUMENT` for an upstream's unreadable answer
   now reads `INTERNAL`.

4. **Name the type a `SafeLink` says.** `SafeLink::new(say)` over
   `fn(&dyn Error) -> Option<String>` is gone: a sayer takes its own type,
   `fn say(error: &AcmeError) -> Option<String>`, and is submitted by
   reference, `nest_rs_core::inventory::submit! { nest_rs_core::SafeLink::of(&say) }`
   — one entry per type, with no downcast and no `link_as`, since the
   framework reads your type behind every pointer for you
   ([Binding a database driver](/database/binding-a-driver/#when-the-backend-fails)).
   A type has one sayer: an app that submitted its own over `reqwest::Error`
   drops it, or claims an error type of its own holding reqwest's as its
   `#[source]`.

5. **A data driver of your own answers what each handle holds.**
   `nest_rs::database::Executor` is one method, `holds()`: `Holds::Pool` over a
   type implementing `HeldPool`, or `Holds::Transaction` over one implementing
   `HeldTransaction`, every method required
   ([Writing a database driver](/database/writing-a-driver/#the-executor)):

   | 7.0's `Executor` | 8.0 |
   |---|---|
   | `as_any` | `executor.holds().downcast_ref::<T>()`, through every wrapper |
   | `after_commit(work) -> Option<Deferred>` | `HeldTransaction::after_commit(work)`, which holds the work; on the pool the port runs it at once |
   | `atomic` | `HeldPool::transaction` and `HeldTransaction::savepoint`, which a resilience policy's attempt runs in too |
   | `write_outbox` | `Outbox::write`, the outbox `HeldTransaction::outbox` answers |
   | `remove_outbox`, `remove_outbox_unique` | `OutboxKept::remove`, `remove_unique`, on what either handle's `outbox` answers |
   | `non_transactional` | nothing: a subscription socket, like every continuation, runs on a pool unit of your binding |

   An app changes nothing here: `atomic`, `after_commit`, `Jobs::push` and
   `cancel`, `#[resilient]` and `Repo` keep their signatures.

</Steps>

## What fails if you get it wrong

- **A data driver's handle that does not say what it holds** does not compile:
  `E0046` names `holds`, and a `HeldPool` or `HeldTransaction` leaving out a
  method names that one.
- **`SafeLink::new`** is rustc's `E0599`, a function 8.0 no longer has, and a
  sayer over `&dyn Error` is `E0277` at `SafeLink::of`.
- **Two sayers of one error type** refuse the boot, naming the type and both
  functions: `contested safe link: … is claimed by two sayers`.
- **Rust's `#[deprecated]` on an operation** is refused where it is written,
  as Rust code whose only caller is the framework, the error naming
  `#[graphql(deprecation = "…")]`. So is a `#[graphql(…)]` inside a
  `#[cfg_attr]`, which no macro would read.
- **An instrument on an operation naming a parameter with no `Debug`** is
  rustc's `E0277` at that parameter.
- **A `#[config]` of your own in the `resilience` namespace, on `full`**,
  refuses the boot, naming the namespace and both types that declare it
  (`ConfigError::SharedNamespace`).
- **A client branching on `INVALID_ARGUMENT` for an upstream's unreadable
  answer** reads `INTERNAL`, and the operator's log gains its chain at `error`;
  **an MCP client reading `-32600`** for an argument refused reads `-32602`.
