title: Upgrading from 6.x to 7.0
description: "The order that moves a 6.1 project to 7.0 — the manifest, the environment, the HTTP vocabulary, the layers, the data port, the deployment — and what fails when a step is missed."

import { Steps } from '@astrojs/starlight/components';

7.0 is a major release, and the foundation every 7.x builds on: HTTP speaks the
`http` crate's types on a server of nestrs's own, every edge runs one pipeline
whose layers read the unit they wrap, a queue is pushed through its type and
kept on Redis Streams, a resource opens once per named instance, and every edge
runs its work through one unit-of-work port. This page is the order to take
the changes in: a 6.1 workspace goes in, a 7.0 one comes out, and each step
ends on something you can check. The
[changelog](https://github.com/YV17labs/NestRS/blob/main/changelog/7.0.md) says why each
change was made; this page says what to do about it.

You need the 6.1 project building, and — for a queue on Redis — its 6.x workers
left running until they drain the 6.x jobs (step 18). Most steps are compile
errors, so the compiler finds every site; a step that changes behaviour alone
says so, and [What fails if you get it wrong](#what-fails-if-you-get-it-wrong)
lists what the boot, a log or the wire shows when one is missed.

<Steps>

1. **Move the CLI and the manifest.** `nestrs update` installs the 7.0 CLI,
   whose scaffolds, `lint` and `doctor` follow the release. In the root
   `Cargo.toml`, the `nest-rs` requirement under `[workspace.dependencies]` goes
   from `6.1` to `7.0`, and a few features move with it — the umbrella counts
   30 capabilities:

   | 6.1 | 7.0 |
   |---|---|
   | `interceptors`, `exception-filters` | nothing: `nest_rs::core::{Interceptor, ExceptionFilter, interceptor}` |
   | `filters` | nothing: an exception filter whose `Exception` is `dyn Error + Send + Sync` (step 10) |
   | `worker` | nothing: `queue` and `schedule` carry what a job needs; the job deadline is `nest_rs::core::JOB_TIMEOUT` |
   | `redis`, for a queue on Redis | `redis-queue` — `redis` alone is now the connection |
   | `graphql`, with `#[authorize]` on a resolver | `graphql` and `authz` |
   | `testing`, with `TestApp` and no other HTTP feature | `testing` and `http`, or `HeadlessApp` |
   | `oauth-server` | unchanged; it now enables `authn` too, since its guard runs an authn `Strategy` |

   ```toml title="Cargo.toml"
   # before
   nest-rs = { version = "6.1", features = ["queue", "redis"] }
   # after
   nest-rs = { version = "7.0", features = ["redis-queue"] }
   ```

   `redis-schedule` is new, and only a job firing once across replicas needs
   it (step 14). Then, in the same pass:

   - **Drop `poem`** from `[workspace.dependencies]` and from every member that
     declares it, a test's `[dev-dependencies]` included: nothing a nestrs
     application writes names it (step 8).
   - **Move `testing` off the root line** that a pre-7.0 `nestrs new` wrote, onto
     each app's `[dev-dependencies]`
     (`nest-rs = { workspace = true, features = ["testing"] }`), so no release
     binary links the harness.
   - **Deny the discarded `Result`** that a pre-7.0 `nestrs new` left open: add
     `[workspace.lints.clippy] let_underscore_must_use = "deny"` to the root
     manifest and `[lints] workspace = true` to each member, which inherit nothing
     otherwise.
   - **Without `seaorm`**, a `Uuid` or a chrono `DateTime` on a GraphQL type or
     operation of yours needs `features = ["uuid", "chrono"]` on your own
     `async-graphql` line, and a chrono type you serialize needs `serde` on your
     own `chrono` line. With `seaorm`, nothing changes.
   - **Raise the libraries you name beside nestrs to the floors 7.0 builds
     on**: `tokio` 1.54, `uuid` 1.29, `rmcp` 3.8 and `redis` 1.8. The framework
     pins `redis` at `=1.8`, so a `redis = "=1.7"` line of yours no longer
     resolves; a requirement such as `1.7` takes 1.8 with no edit.
   - **A library the framework re-exported for its own expansions** —
     `nest_rs::core::{serde, validator, schemars}`,
     `nest_rs::http::{serde, validator}`, `nest_rs::queue::serde_json` — is a
     dependency of your own where your code names it, but for `validator`, which
     your code names at `nest_rs::pipes::validator`; `#[input]`, `#[expose]` and
     `#[config]` still need none.
   - **A script running `nestrs g resource <name>` then `nestrs g migration
     create_<name>`** drops the second line: the resource writes its table's
     migration, from the columns it now takes (`nestrs g resource posts
     title:string body:text`). A later change to the table takes a migration
     of its own name, `add_<column>_to_<table>`.
   - **A script running `nestrs g migration create_<name>` before `nestrs g
     resource <name>`** drops the first line, for the same reason: a resource
     whose table a registered migration creates is refused. Over a migration
     you keep, write the feature and its entity alone, `nestrs g feature
     <name>` then `nestrs g entity <name>`.

   Take the patched rustls while the lockfile moves — 0.23.44 carries
   RUSTSEC-2026-0285:

   ```bash frame="terminal"
   nestrs update
   cargo update -p rustls
   cargo check --workspace
   ```

   The check now fails on the calls steps 4 to 14 change. A refusal beyond them
   names the rule it applies: 7.0 judges every decorated method by one grammar,
   and the [changelog](https://github.com/YV17labs/NestRS/blob/main/changelog/7.0.md)
   lists what it refuses.

2. **Declare each process's environment, and let `main` load it.** A process
   that declares no `<PREFIX>_ENV` runs as **production**, where 6.x took it for
   development: it reads `.env.production` rather than `.env.development`,
   serves no development surface, and refuses what production refuses. A local
   run outside `nestrs run dev` — `cargo run`, an IDE's run configuration, a
   script — declares `<PREFIX>_ENV=development` on the process; the variable
   cannot live in `.env`. A deployment that never set it sets
   `<PREFIX>_ENV=production`, which silences the boot's
   `no environment declared; running as production` line.

   | 6.x | 7.0 |
   |---|---|
   | `#[tokio::main]` on a binary's `main` — an app, a `migrate` or `seed` tool | `#[nest_rs::main]`, and the `tokio` line a crate carried only for it dropped (its tests keep theirs as a dev-dependency) |
   | `let _environment = Environment::init();` on `main`'s first line | delete the line and its `use`: `#[nest_rs::main]` publishes the `.env` cascade before `main` runs; a binary without it calls `nest_rs::config::load_cascade(dir, Environment::from_env())` first thing |
   | `Environment::default()` or `Environment::from_env()` expected to be `Development` when `<PREFIX>_ENV` is unset | `Production`; branch on `Environment::declared()` to tell an undeclared process apart, or on `is_deployed()` for a development convenience |
   | `!matches!(Environment::from_env(), Environment::Production \| Environment::Staging)` in a `Config::defaults()` of your own | a `Surface` field, read with `is_open()` (step 6); `!Environment::from_env().is_deployed()` where you branch on the profile yourself |
   | a scaffolded project's URLs in `.env` | move them to `.env.development` and `.env.test`; export `<PREFIX>_ENV := "development"` in `db.just` |
   | a development or test run reaching Redis on `redis://127.0.0.1/`, or storage on `https://rustfs:9000` with the `nestrs` pair, with no variable set | name them in `.env.development` and `.env.test` — `<PREFIX>_REDIS__URL`, `<PREFIX>_STORAGE__URL`, `ENDPOINT`, `ACCESS_KEY`, `SECRET_KEY`: no profile names an address or a credential |
   | `<PREFIX>_GRAPHQL__PLAYGROUND=true`, `<PREFIX>_GRAPHQL__DISABLE_INTROSPECTION=false` or `<PREFIX>_LOG_FORMAT=text` in `.env.development` | delete the lines: a declared development or test profile serves the playground, answers introspection and writes text logs; a deployment writes JSON |
   | a scaffolded project's `.env` holding `<PREFIX>_AUTHN__SECRET=dev-only-insecure-secret-change-me-32b` | delete that line; put `<PREFIX>_AUTHN__SECRET=` and the output of `openssl rand -hex 32` in `.env.local` (and another in `.env.test` if your suites sign tokens), and your own in every deployed environment |
   | a scaffolded project's `.env.test` naming `redis://localhost:6379` | `redis://localhost:6379/1`, so the suites never push on the database the development app drains |

   `#[nest_rs::main]` builds the same runtime as `#[tokio::main]` and ends the
   process within the shutdown budget: under `#[tokio::main]`, the runtime's
   drop waits for every blocking call still running, so a hook abandoned while
   it waited on one held the exit past every bound. A second `SIGINT` or
   `SIGTERM` during the way down now exits at once, with code 130 or 143.

3. **Rename the variables that moved.** A crate in a family puts the family
   first in its namespace, so the OAuth client and resource server read
   `<PREFIX>_OAUTH__CLIENT__*` and `<PREFIX>_OAUTH__RESOURCE__*` — the same string as
   their paths, `nest_rs::oauth::client` and `nest_rs::oauth::resource`. Rename
   them wherever the deployment sets them: the `.env` files, the chart's values,
   the platform's secrets.

   | `<PREFIX>_LOG`, in a `.env` file or the deployment | `RUST_LOG`, unprefixed: the console's filter is the ecosystem's variable alone, and a real `RUST_LOG` outranks one a committed file writes |
   | `<PREFIX>_OPENTELEMETRY__SERVICE_NAME` | `OTEL_SERVICE_NAME`, unprefixed — or nothing: the service is named after the binary |
   | `<PREFIX>_OPENTELEMETRY__SERVICE_VERSION`, `SERVICE_ENVIRONMENT`, `SERVICE_INSTANCE_ID` | `OTEL_RESOURCE_ATTRIBUTES=service.version=…,deployment.environment.name=…,service.instance.id=…` — the version defaults to the binary's |
   | `<PREFIX>_OPENTELEMETRY__OTLP_ENDPOINT` | `OTEL_EXPORTER_OTLP_ENDPOINT` |
   | `<PREFIX>_OPENTELEMETRY__SAMPLE_RATIO=0.1` | `OTEL_TRACES_SAMPLER=parentbased_traceidratio` and `OTEL_TRACES_SAMPLER_ARG=0.1` |
   | `<PREFIX>_OPENTELEMETRY__METRIC_INTERVAL_SECS=5` | `OTEL_METRIC_EXPORT_INTERVAL=5000`, in milliseconds |
   | `<PREFIX>_OPENTELEMETRY__TLS_CA_CERT`, `TLS_CERT`, `TLS_KEY` (or their `_FILE`) | `OTEL_EXPORTER_OTLP_CERTIFICATE`, `OTEL_EXPORTER_OTLP_CLIENT_CERTIFICATE`, `OTEL_EXPORTER_OTLP_CLIENT_KEY`, each a path to the PEM file |

   OpenTelemetry's are the specification's own, so they take no prefix: no
   `ACME_` renames `OTEL_*`, nor `RUST_LOG`. Under a prefix of your own, the rest holds with
   `ACME_` for `NESTRS_`. Every
   one of them — every namespaced variable, in fact — can now be given as a file
   instead, through its `_FILE` spelling; see the
   [ConfigService API](/configuration/#configservice-api). A name you miss is not
   silent: the boot names it and its new spelling, as shown
   [below](#what-fails-if-you-get-it-wrong).

4. **If you write decorators on `nest-rs-codegen`**, depend on it from a
   `proc-macro` crate only, and use its root items alone, the kit semver
   covers. Read a decorator's arguments through `Grammar`: a `key = value`
   grammar is one `const G: Grammar = Grammar::new("attr", &["key", …])`, and
   `G.parse2(args, |arg| …)` refuses an unknown key and a repeated one before
   the closure sees a key; the closure reads the key's value through `Arg`,
   which refuses a bare key that needs one, and reads a key that takes no
   value through `arg.input()`. Collect an item's refusals in `Refusals` and
   report them at once; read a duration with `duration_millis`, derive a name
   with `pascal_case` or `snake_case`, take a marker attribute off an item
   with `take_flag_attr`, `take_single_attr` or `take_path_list`, and pass
   the finished expansion through `reroot`. Emit a framework path as
   `::nest_rs_<concern>::<item>`, an item the docs show, and your own as
   `::<your_crate>::…`. Everything else in `nest_rs_codegen` moved to
   `__private` and is not API — the job and pair tables, `JobDecorator`,
   `job_key`, `transactional_value`, `CrudDeclaration`, `RoutePath`,
   `MountPath`, `VersionedEdge` among them. The repository's `clippy.toml`
   refuses `syn::meta::parser`, `syn::Attribute::parse_nested_meta` and
   `syn::MetaList::parse_nested_meta`; copy those three entries if your crate
   should hold the same line.

5. **Follow the remaining renamed types and signatures.** Each row is a compile
   error, so the compiler finds every site:

   | 6.x | 7.0 |
   |---|---|
   | an exhaustive `match` on a framework enum (`ApiVersioning`, `Action`, `WsReply`, …) | the same ending in `_ =>`, its arm the default your code means |
   | `nest_rs::resource::{expose, wire_enum}` | `nest_rs::seaorm::expose`, `nest_rs::core::wire_enum` |
   | `nest_rs::resource::{PkLoadable, RelatedTo, RelationKey, RelationPage, SoleForeignKey}` | `nest_rs::seaorm::graphql::{…}` |
   | `nest_rs::resource::sea_orm` | `nest_rs::seaorm::sea_orm` |

   | `nest_rs::resource::{serde, validator, schemars, chrono, uuid, serde_json, tracing, async_trait}`, `nest_rs::resource::graphql::{async_graphql, dataloader}` | `nest_rs::pipes::validator`, `nest_rs::graphql::{async_graphql, dataloader}`, or a dependency of your own on any other |

6. **Import a module bare to read its environment, pin a config as a struct
   literal, and open an instance by its type.** Every module owning a config is
   imported bare to read its variables, and `for_root` takes only the value it
   pins — never `None`. A module's config is one value, pinned through
   `for_root` as a struct literal over its base: every `with_*` helper is gone. A config's
   `Default` is its one base — no loopback URL, no development credential, and what
   a development run opens a `Surface` left to the profile, closed in a deployment —
   and a pinned config reads the process environment, never `.env`. A struct
   gaining fields within 7.x keeps a literal ending in `..Default::default()`

   **Lifecycle hooks and the way down**

   | 6.x | 7.0 |
   |---|---|
   | hosts named so their hooks run in the wanted order (`AaFirst`, `ZzLast`) | inject the provider whose hooks must run first: its hooks then run before yours at init and after yours at shutdown |
   | a hook reaching another provider through `Container::get` and relying on that provider's hook having run | inject that provider, so the graph orders the two |
   | `app.init().await?` on a `TestApp` | delete it: `TestApp::builder().build()` already ran the init phases, which run once per app |
   | a shutdown hook that `expect`s what its init filled | `if let Some(..)`: it now also runs after a failed or interrupted init |
   | a one-shot command reaching the pool around the container, its teardown skipped | `let app = App::builder()…build().await?; app.init().await?;` … `app.close().await;` |
   | a test that could not run the shutdown hooks | `TestApp::close()`, `HeadlessApp::close()`, `WsApp::close()` |
   | a module ending its resource in a `Drop` | `builder.provide_close::<T, _, _>(\|t\| async move { … })` beside the factory |
   | a provider injecting `Arc<DatabaseConnection>` only for a lifecycle hook | go through its service and `Repo`: the hook runs in a unit of work, its writes committing together on its `Ok` |
   | an emit from a task spawned at construction, relied on to be dropped silently | emit from an `#[on_module_init]` hook or later: the listeners are live before the first hook |
   | a test matching a factory's error at the top of a boot error | the boot error is `FactoryFailedError`; find `E` in its chain (`err.chain()`) or read `{err:#}` |
   | an `impl Transport` written by hand | the same with `fn stop_bound(&self) -> Duration` — its drain window plus `SHUTDOWN_SETTLE_TIMEOUT`, at most `MAX_STOP_BOUND` (a day) — and `async fn listen(&mut self) -> anyhow::Result<Listening>` binding its socket, which `serve` then serves on |

   `App::run` and `App::close` need a runtime with its time driver, as
   `#[nest_rs::main]` and `#[tokio::test]` build it. A `#[nest_rs::main]`
   program that built an app and never serves it (a one-shot command) keeps
   running at the first `SIGTERM`, its app `Draining`: read
   `AppLifecycle::stopping()` to stop, or a second signal exits it.

8. **Write HTTP code on nestrs's HTTP vocabulary.** 6.x's HTTP surface was
   poem's; 7.0's is `nest_rs::http` — `Request`, `Response`, `Body`,
   `HttpError`, `Endpoint`, the extractors — over the `http` crate's head
   types, which it re-exports, and the server underneath is nestrs's own on
   hyper. A route's path is OpenAPI's path templating. Each row is a compile
   error unless it says otherwise:

   **Routes and handlers**

   | 6.x | 7.0 |
   |---|---|
   | `#[get("/:id")]` | `#[get("/{id}")]` |
   | `#[get("/files/*rest")]` | `#[get("/files/{*rest}")]` |
   | `#[get("/@:handle")]` | `#[get("/@{handle}")]` |
   | `#[get("/:id<\\d+>")]` | `#[get("/{id}")]` with `Path<u64>`, or a pipe |
   | `#[controller(path = "/orgs/:org")]` | `#[controller(path = "/orgs/{org}")]` |
   | a root catch-all (`/*rest`) that also served `/` | the catch-all (`/{*rest}`) and a route at `/` beside it (`#[get("/")]`) — not a compile error: `/` otherwise answers the fallback's `404` |
   | a handler reading an empty parameter: `/a//b` matched `/a/{x}/b` with `x` empty | nothing reaches it — `/a//b` answers the fallback's `404`; a value that may be absent travels in the query string |
   | `use poem::web::{Json, Path, Query}` in a controller | `use nest_rs::http::{Json, Path, Query}` — and `Form`, `Multipart`, `Header<T>`, `ClientIp`, `RawBody` |
   | `-> poem::Result<T>`, `poem::Error::from_status(s)` | `-> nest_rs::http::Result<T>`, `HttpError::from_status(s)` |

   | `req: &poem::Request` as a handler parameter | `req: &nest_rs::http::Request`, or the extractor for what it reads |
   | `poem::web::Data<&T>` | an `#[inject]` field on the controller, or `Scoped<T>` for a request-scoped provider |
   | `use nest_rs::http::poem::…` | `nest_rs::http::{Request, Response, Json, IntoResponse}`; `ProblemDetails` answers through `nest_rs::http::ResponseError` / `IntoResponse` |
   | `field.into_byte_stream()` through `nest_rs::http::PartExt` | `Field::into_byte_stream()` on `nest_rs::http::Multipart`'s field |

   | `body: Valid<Json<T>>`, `Valid(input): Valid<Json<T>>` — and over `Query`, `Form`, `Path`, `Header` | `Json(input): Json<T>`: every extracted value is held to the rules its type declares, with nothing to wrap |

   | `impl nest_rs::http::IntoInner for MyExtractor<T>` | `impl nest_rs::pipes::Source for MyExtractor<T>` (`type Value`, `into_value`), and `nest_rs::pipes::validator::Validate` when `T` declares rules |
   | `SseEvent::retry(ms)` | `SseEvent::message("").retry(Duration::from_millis(ms))` |
   | `match event { SseEvent::Message { .. } => … }` | none: an event is written, never read back |
   | `SseEvent::message(serde_json::to_string(&payload)…)`, with a fallback body when it fails | `SseEvent::json(&payload)`: a payload that does not serialize sends no event — its chain is filed and the stream ends there |
   | `SseSettings::respond(stream)`, answering poem's `SSE` | the same, answering a `Response` marked to end at the shutdown signal |
   | `PATCH /<resource>/{id}` on a `#[crud]` controller | `PUT /<resource>/{id}` — a wire change, no compile error |
   | `impl RouteResponseShaper` / `ResponseShaping` on `poem::Request`, `poem::Response`, `poem::Result` | the same impl on `nest_rs::http::{Request, Response, Result}` |
   | `challenge::stamp_bearer_error` on a `poem::Response` | the same call on `nest_rs::http::Response` |

   surface setting a security header or `Server` — now wins over the
   deployment's `<PREFIX>_HTTP__*` default, which fills only a response that

9. **Follow the error and authentication types.** An error nobody meant for
   the client is answered opaquely and its chain logged, on every edge: a
   client reads a sentence only from a deliberate client error — a
   `ToProblem` type, `WsError`, a `Problem` — and every failure names its class
   by one `code`. An error carries its cause as a source chain rather than a
   `format!`ted string.

   | 6.x | 7.0 |

10. **Move every layer onto the unit context.** One pipeline runs every unit
    on every edge, and every layer reads it through `UnitContext` — see
    [Execution context](/fundamentals/execution-context/) and
    [the request lifecycle](/fundamentals/request-lifecycle/). Each row is a
    compile error unless it says otherwise; work through them in this order,
    guards first, since an interceptor or a filter often reads what a guard
    attached.

    **Guards**

    | 6.x | 7.0 |
    |---|---|
    | a guard's `async fn check_http(&self, req: &mut Request)` | `async fn check_http(&self, cx: &mut UnitContext<'_>)`: the request through `HttpView::of(cx)?.request()` — `request_mut()` to read the body and set it back — and the route's `#[meta]` and posture through `cx.reflector()` |
    | a guard's `check_graphql`, `check_ws_message` or `check_mcp` | one `async fn check(&self, cx: &mut UnitContext<'_>)`: the field, message or operation through `cx.switch_to::<GraphqlView>()`, `WsView` or `McpView`, its name through `cx.handler().address()` |

    operation, a WebSocket message, an MCP operation, a job, a tick, a
    listener, a lifecycle hook — runs its work through one port,

    app reaching a `#[crud]` host, a route or field under `#[authorize(A, bind
    = S)]`, or the service a GraphQL-exposed entity names (`#[expose(service =
    S, graphql)]`) imports `SeaOrmDatabaseModule`, which imports the

    **Readiness waits on every resource the app opens.** 6.x checked the pool
    only beside `SeaOrmHealthModule`, and no Valkey or store; an app importing
    `HealthModule` now answers `/health/ready` and `/health/startup` `503` while
    its own or a feature's database, any Valkey instance or the store is down,
    so the orchestrator takes the replica out of rotation until it is back.
    Each of those probes sends `SELECT 1`, a `PING` per instance and one page
    of the bucket's listing — a request a store billing per request bills.

    **A GraphQL operation is a unit of work**, and each mutation root field a
    savepoint settled on the answer that field gives: a failed nullable root
    field answers `null` and rolls back alone; a Non-Null root field's `null`
    reaching `data` rolls the whole operation back and runs no later root
    field; a mutation naming one root field twice is refused. Return
    `Result<Option<T>>` from a mutation whose work must stand beside a
    sibling's failure, and put the writes that stand or fall together in one
    field. A batch's operations no longer share one transaction. A driver whose
    executor offers no atomic block answers every GraphQL mutation `INTERNAL`.

13. **Push through the queue's type, on the port's handle.** A feature injects
    `Arc<nest_rs::queue::Jobs>`, which the backend's binding registers, where it
    injected the backend's producer. `push_to::<Q>(job)` and the string-taking
    `push(name, job)` are gone: a push names the queue's `#[queue]` marker and
    answers with a `PushReceipt` naming the job's id; `push_with` takes
    `PushOptions` for a delay or a unique key:

    ```rust title="crates/features/src/audio/service.rs" del={1,4} ins={2,5}
    queue: Arc<dyn JobProducer>,
    jobs: Arc<Jobs>,
    // …
    self.queue.push_to::<AudioQueue>(TranscodeCommand { file }).await?;
    self.jobs.push(AudioQueue, TranscodeCommand { file }).await?;
    ```

    The queue section lists every call a producer changes, `push_many` and
    `push_json` included, under
    [Your code](/queue/upgrading/#your-code). `QueueName` is now the checked name a
    backend receives, so a queue's type is `Queue`:
    `<AudioQueue as QueueName>::NAME` becomes `<AudioQueue as Queue>::NAME`. A
    `push_many` that fails after the backend accepted part of it answers
    `QueueError::PartiallyQueued`, carrying the receipts of the jobs already
    queued: a caller that retries the whole batch on any error leaves those out.

    **A push inside a transaction is filed after its commit.** On an app binding
    `seaorm` and a queue backend, a push in a mutating request, a GraphQL
    mutation, a message or an attempt is written into the transaction and filed
    once it commits — never lost, never left behind by a rollback. That table,
    `nestrs_outbox`, is the framework's migration, created by
    `nestrs g migration nestrs_outbox` then `nestrs run db up` (or
    `Box::new(nest_rs::seaorm::queue::OutboxMigration)` in your migrator's
    `migrations()`). An event whose listener pushed only to wait for the commit
    pushes in the service, inside the transaction. A push meeting a unique key
    another job holds answers `Ok` and is dropped at `info` after the commit,
    where it answered `UniqueKeyHeld`. See
    [Producing jobs](/queue/producing-jobs/).

14. **Check what each consumer declares.** A `#[process]` method compiles as it
    did, and these read differently now:

    - `retries = N` runs a failed attempt again **after a backoff** — one second
      after the first failure, doubling, at most five minutes — where 6.x ran it
      again at once. A `Problem` carrying `with_retry_after(n)` holds it back `n`
      seconds when that is longer, at most an hour, where 6.x read no such wait.
      See [Retries and failure](/queue/retries-and-failure/).
    - **A job failing with a client's error dead-letters at once.** A
      `JobError::abort(…)`, or a `ServiceError` or a `Problem` with a `4xx`,
      dead-letters on its first attempt, where 6.x retried it until the budget
      was spent; return `JobError::retry` where a later attempt may succeed — a
      row the producer has not committed yet.
    - **A delivery whose process died has a limit of its own.** An OOM kill or a
      pod killed mid-job still spends no retry: the job runs again at the same
      attempt, as in 6.x. But a job whose deliveries end that way three times in
      a row is dead-lettered without running, where 6.x ran it again every
      time. See
      [Crashes, and the stall limit](/queue/delivery/#crashes-and-the-stall-limit).
    - **A job a newer release pushed is handed back, not failed.** During a
      rolling deploy, a 7.0 worker meeting a job sealed by a later wire format
      runs nothing, spends no attempt and puts it back as stored, due a minute
      later, with a `warn`; 6.x failed such a job and spent its retries. A job
      still unread a day after its first hand-back — a rollout that stopped — is
      dead-lettered, naming both versions.
    - **A job ends within its `timeout`**, ten minutes by default: a
      `#[process]`, `#[every]`, `#[cron]` or `#[after]` method running longer
      declares `timeout = "…"` covering its longest run, up to `"24h"`. An attempt
      past its timeout is cut and fails retryably; a job whose commit does not
      answer within the database's statement budget plus a second is
      dead-lettered rather than retried, since its writes may have landed.
    - `concurrency = N` is accepted again, per method and per replica, and so are
      `throttle(limit, window)` and a `Checkpoint<S>` parameter; see
      [Concurrency and scaling](/queue/scaling/). A `#[process]` method may take
      an `Attempt` — the job's id and attempt — beside its job.
    - **The tenant travels with every job**, like the actor: a tenant id threaded
      by hand into every payload becomes `fn tenant_id(&self) -> Option<String>`
      on the claims' `PrincipalIdentity`, read with
      `nest_rs::core::current_tenant_id()` in the service, in the request and in
      every job it pushes.
    - **Delivery is at least once, so a handler stays idempotent.** On Redis a
      job runs again only once a delivery's lease lapses — its worker crashed,
      froze, or was cut off past the lease — and what the first delivery writes
      after that lands nowhere. See
      [At least once, and the fence](/queue/delivery/#at-least-once-and-the-fence).
    - A queue name is checked: 1 to 128 of `[A-Za-z0-9_.-]`. A name holding `:`
      or whitespace no longer compiles, so that queue takes a new name, and its
      6.x jobs are drained in step 18 under the old one.

    A scheduled job that should fire on one replica rather than all of them can
    now say so with `replicas = "one"`, beside `RedisScheduleModule`: each
    occurrence fires once across the replicas, and a run that outlasts its period
    overlaps the next one, fired by another replica. A job is its crate, its type
    and its method, so renaming one of them starts a new job — two, for the
    rolling deploy that ships the rename — unless `key = "…"` pins the identity
    its boot line names. See
    [Firing once across replicas](/schedule/#firing-once-across-replicas).

    **An event emitted inside a transaction waits for it.** `EventBus::emit` in a
    mutating request, a GraphQL mutation, a WebSocket message, an MCP operation, a
    queue attempt, a scheduled tick or a lifecycle hook runs its listeners once
    the transaction commits — outside it, each listener in a transaction of its
    own, under the emitter's scope and ability — and never when it rolls back;
    6.x ran them inline, inside it. A listener that relied on writing inside the
    emitter's transaction now writes in its own, and code that opens a
    transaction itself emits after its own commit. See
    [What waits for the commit](/database/transactions/#what-waits-for-the-commit).

    | 6.x | 7.0 |
    |---|---|
    | an `#[on_event]` method logging its own failure and returning `()` | return `Result<(), E>`: the bus rolls the call back and reports the error with its chain |
    | a listener relying on its writes landing one statement at a time | `#[on_event(transactional = false)]` |
    | a listener running past ten minutes | `#[on_event(timeout = "…")]`, at most `"24h"`, or a queue job it pushes |
    | a cross-cutting concern around jobs written inside every `#[process]` method | an interceptor bound with `#[use_interceptors]` on the `#[processor]` block, reading `QueueView` (step 10) |
    | `ListenerMethod::wire(container, bus)` | none: only the boot runs a discovered entry |

    A GraphQL operation returning a bare value — `i32`, `Vec<T>`, an
    `impl Stream` subscription — now runs its resolver's guards and the app-wide
    ones, where 6.x served it past a deny-all `#[use_guards]`. An operation that
    answered only because of that gap now needs the posture its guards ask for.
    An operation returning a renamed `Result` — `use async_graphql::Result as
    GqlResult`, or a type alias — is read as one, so its error is a field error
    where 6.x served it as data.

15. **Boot every app, and read its first lines.** A 7.0 boot names what it cannot
    use rather than falling back in silence. No `nest_rs::config` warning means
    no variable under a namespace the app reads went unread, none sits in a
    `.env` file beside a config the app pins in code, and none spells such
    a namespace with other separators, in another case or one misspelled segment
    away; a namespace nowhere near any the app reads is taken for another
    binary's and stays silent, so check the names the app should read against
    the [env-var reference](/configuration/env-reference/). Every resource the
    framework opens is proved at boot, each attempt a `warn`: a Postgres not
    listening yet, starting or full is waited for within
    `<PREFIX>_SEAORM__CONNECT_TIMEOUT_SECS`, a refused login fails at once naming
    the host and the SQLSTATE; a bucket that does not exist fails the boot
    naming `<PREFIX>_STORAGE__URL`, a key the store rejects fails it naming the
    credential variables, and any other `403`, most often a policy refusing the
    listing, leaves one `warn`. A deployed profile reaching a backend in plaintext off
    this machine is one `warn` per opening and the connection opens all the same: `Redis
    is reached in plaintext outside a dev profile`, `Postgres is reached in plaintext
    outside a dev profile` and `a signal is exported over plain HTTP outside a dev
    profile`; write `rediss://`, `sslmode=verify-full` or `https://` to close it. A
    provider declaring a `#[liveness]`, `#[readiness]` or `#[startup]`
    indicator in an app that does not import `HealthModule` is a `warn` too —
    `host not served: the health probes are not mounted`, with the host, its
    module and the import that serves it, and so is a host seeded or registered by a
    hand-written module with nothing importing what its edge runs on — `host not served:
    its edge's transport is not attached`, with the host and the import — or an instance
    of a controller, gateway or MCP host, which those edges do not mount whatever is
    imported — `host not served: its edge does not mount an instance`, with the host and
    a hint to list it. A host the app links but never reaches — a scheduled method, a
    `#[process]` method, a listener, a lifecycle hook, a health indicator — is a
    `warn` naming its `cause` and the remedy when it is this app's own code, and
    a `debug` line when it belongs to a dependency (`cause="dependency"`). A
    configuration refusal's first line names the variable it refuses —
    ``invalid value for <PREFIX>_HTTP__PORT: …`` — and a validation failure lists
    each field beside its variable.
    The boot's last line is `app ready` at `info`, naming the addresses bound.
    An HTTP route no guard covers and no `#[public]` opens, which 6.x served
    after one `unguarded routes detected` warning, now stops the boot naming
    every such route: bind a guard on its controller, the route or the app's
    global pool, or mark it `#[public]` where it is open on purpose. A guard counts
    only if it identifies or authorizes, by its `phase()`. A WebSocket message and an MCP
    operation take the same rule, and a `#[public]` message or MCP operation behind
    a guard that authenticates stops the boot, the word having nothing to open.

16. **Regenerate every client from the 7.0 document**, and move what it read off
    the wire:

    - **Every problem document names its class** in `code` — `INVALID_ARGUMENT`,
      `UNAUTHENTICATED`, `FORBIDDEN`, `INSUFFICIENT_SCOPE`, `NOT_FOUND`, `CONFLICT`,
      `RATE_LIMITED`, `UNAVAILABLE`, `INTERNAL` and the classes of `405` to `426` — and its
      `type` is `about:blank`. An opaque `5xx` carries `code` and no `detail`,
      where it said `"internal error"`; read the code. On WebSocket, the class
      sits beside the field map: `data.code`, `data.reason`,
      `data.requiredScopes`, `data.retryAfterSeconds` where they were under
      `data.errors`, which is now the field map alone; on MCP, a pipe's field
      map is under `error.data.errors`, its class at `error.data.code`; GraphQL
      reads `extensions.code`.
    - **A GraphQL field error names a field as the schema spells it**:
      `extensions.errors.orgId`, where it read `org_id`, at every depth, under
      the rename rule the input declares. HTTP, WebSocket and MCP keep the name
      serde reads.
    - **A value that does not decode is answered naming where**, never what was
      sent: ``query parameter `p`: …``, ``form field `p`: …``,
      ``JSON body at `p`: …``, and the same place in a WebSocket frame, an MCP
      argument refusal and a job's dead-letter reason. A client matching poem's
      or serde's sentence meets the framework's.
    - **A failed GraphQL field is present as `null`** beside its error, whose
      `path` names it; a Non-Null field's `null` climbs to its nearest nullable
      parent, `data` itself from a root field. A client branching on a missing
      key reads `null`.
    - **A refusal never hands a client's value back**: a GraphQL error names the
      argument and the type, an MCP `unknown task` names no id.
    - **A paginated `#[crud]` list links its next page** in
      `Link: </posts?first=20&after=…>; rel="next"` (RFC 8288), where 6.x sent
      the cursor alone in `x-next-cursor`; follow the link, or read `after` off
      its query. The last page has no `Link`. A stale or mangled cursor answers
      `400` (a field error on GraphQL) instead of the first page.
    - **A `#[crud]` update is `PUT /{id}`**, where it was `PATCH`.
    - **A route's document lists what its guards answer**: `401` and `503` on an
      authenticated route, `403` where an ability can refuse, `429` under a rate
      limit, and `security` read off the guards.
    - **A route's default tag is its controller's token** — `posts`, not
      `PostsController` — and a `#[crud]` route no longer takes its entity's
      name (`Post`). A generator grouping by tag renames its classes or files;
      keep a name with `tags("…")`.
    - **An `#[expose]`d timestamp reads `…Z` at UTC**, where an unmasked route
      wrote `+00:00`: one instant, now spelled as a masked route already spelled
      it. A client parsing RFC 3339 sees no change; one comparing strings does.
    - **Sockets close by their standard**: a frame past the cap closes `1009
      Message Too Big` on a gateway and on graphql-ws, where it closed `1011`; an
      admitted upgrade an in-process test drives answers `426`; a handshake
      offering no graphql-ws subprotocol answers `400` naming the two it accepts.
      A WebSocket envelope is the object `{ "event": …, "data": … }`; an array is
      refused as no envelope.
    - **The GraphQL path answers `405` with `Allow`** — `POST` for a plain `GET`
      with the playground off, `POST, GET, HEAD` for another method — and a
      sub-path of it is `404`.
    - **MCP**: a session shared across principals answers `404`, as does a
      `DELETE` of a session the endpoint does not hold; sessions stored before
      7.0 are refused on restore, so their clients open new ones once; a body
      that is no JSON-RPC message answers `400` with `-32700` or `-32600`, where
      it answered `415`, a message carrying a stray `result` or `error`, or a
      repeated `id`, among them; an unknown tool answers `-32602` under
      `NOT_FOUND`. A request naming no session that is no `initialize` answers
      `400`, where it answered `422`; a JSON-RPC response sent with no session
      answers `400` with `-32600`, where it was accepted `202`. A tool or prompt
      asking its client for input at `2026-07-28` answers an
      `InputRequiredResult`: the peer's `elicit` and `create_message` are refused
      at that revision.
    - **A token endpoint answers RFC 6749 §5.2's JSON**: `401 invalid_client`
      with a `Basic` challenge for a client refused over the `Authorization`
      header, `400 invalid_client` for one that sent its credentials in the body
      or none, `400 invalid_request` for a request that does not parse, and
      `400 invalid_grant` for a rejected password; a `503` authentication answer
      carries `Retry-After: 1` at least.

17. **Update the deployment.**

    - **HTTP has bounds of its own.** A replica holds at most
      `<PREFIX>_HTTP__MAX_CONCURRENT_CONNECTIONS` open connections, 10 000 by
      default — WebSockets included: raise it, with the file limit (`ulimit -n`),
      for a replica holding more, and keep it at or above a proxy's upstream
      cap. An HTTP/2 connection runs at most 200 streams and a header list of at most
      16 KiB; on HTTP/1, a head past 64 KiB answers `431`. A connection that sends no complete head within
      `<PREFIX>_HTTP__HEADER_READ_TIMEOUT_SECS` (30 s) is closed; a kept-alive one
      idle past `<PREFIX>_HTTP__IDLE_TIMEOUT_SECS` (75 s) is closed — **behind a
      load balancer whose backend keep-alive is longer** (Google Cloud's is
      600 s), set it above the balancer's (`620`), or the balancer reuses a
      connection as it closes and answers `502`; a peer that stops reading is
      dropped after `<PREFIX>_HTTP__SEND_TIMEOUT_SECS` (60 s).
    - **A request runs 20 seconds by default**, down from 30
      (`<PREFIX>_HTTP__REQUEST_TIMEOUT_SECS`), counted from its arrival, its
      body's reading included; a body that stops arriving answers `408` after
      `<PREFIX>_HTTP__BODY_READ_TIMEOUT_SECS` (10 s), or that budget's `503` when
      it stops within the budget's last gap. A WebSocket message and an
      MCP operation are cut at 20 s too (`<PREFIX>_WS__MESSAGE_TIMEOUT_SECS`,
      `<PREFIX>_MCP__OPERATION_TIMEOUT_SECS`), and a WebSocket connection hook
      has `<PREFIX>_WS__CONNECT_TIMEOUT_SECS` and `DISCONNECT_TIMEOUT_SECS`.
      **Handlers longer than 20 s** raise their timeout, the window and the pod's
      grace period together. A Redis budget, a statement bound or a storage
      operation set at 18 s or more under an authentication guard, a queue or a
      rate limiter is refused at boot: keep it under the 18-second net.
    - **MCP sessions are capped**: 1 024 per endpoint
      (`<PREFIX>_MCP__MAX_CONCURRENT_SESSIONS`, about 110 KiB each), idling out
      after `<PREFIX>_MCP__SESSION_IDLE_TIMEOUT_SECS` (five minutes); a session
      is served to the principal that opened it alone, and a principal naming no
      subject opens none on a gated endpoint (`initialize` answered `403`). The
      graphql-ws socket waits 3 s for `connection_init`
      (`<PREFIX>_GRAPHQL__CONNECTION_INIT_TIMEOUT_SECS`, up to 60, for a client
      fetching a token first), and caps a message at 64 KiB and a socket at 100
      operations (`<PREFIX>_GRAPHQL__MAX_MESSAGE_BYTES`,
      `<PREFIX>_GRAPHQL__MAX_SOCKET_OPERATIONS`).
    - **A browser's `Origin` is checked** at both WebSocket upgrades and at
      `/mcp`, CORS on or off: a browser app on another origin is listed in
      `<PREFIX>_HTTP__CORS_ORIGINS`, and behind a proxy that terminates TLS or
      rewrites `Host`, a same-origin browser is refused until the proxy is
      listed in `<PREFIX>_HTTP__TRUSTED_PROXIES` and sends `Forwarded` or
      `X-Forwarded-Proto` and `X-Forwarded-Host`. With CORS origins set, the
      server's own origin is listed too. A `*` admits every origin; the list is
      read as origins, so `null`, a path, a trailing `/` or a Unicode host fails
      the boot at that entry — write the ASCII form, `https://xn--9ca.example`.
    - **Server-Timing is off outside development and test**: a staging dashboard or a
      synthetic check reading it sets `<PREFIX>_SERVER_TIMING__ENABLED=true`.
    - **OAuth and OpenTelemetry follow the outbound policy**: every
      `<PREFIX>_OAUTH__CLIENT__*_URL` of a provider is `https`, and
      `REDIRECT_URL` `https` — loopback `http` in a declared development or test
      profile alone; a provider or an `https://` collector signed by a private
      authority is trusted through `<PREFIX>_OAUTH__CLIENT__TLS_CA_CERT` or
      the file `OTEL_EXPORTER_OTLP_CERTIFICATE` names. A flow begun before the deploy that
      renames the OAuth transaction cookie to `__Host-oauth_tx` fails its
      callback once; the user signs in again.
    - **KEDA** reads the stream's length now: a `redis-streams` trigger on
      `nestrs:queue:{<queue>}:jobs`, with `streamLength` where a list trigger had
      `listLength`, counting the jobs waiting and running. A trigger
      naming the 6.x list reads zero forever. Keep `minReplicaCount: 1` on a queue
      that takes delayed pushes or retries — they wait off the stream, and only a
      running worker files them back; see
      [On queue depth, with KEDA](/queue/scaling/#on-queue-depth-with-keda).
    - **An ACL** confined to the framework's prefix now runs every Redis binding,
      and each page gives its rule whole — the commands a binding sends, those
      inside its Lua scripts included, since Redis checks them against the
      caller's ACL as well: [the queue](/queue/delivery/#where-a-queue-lives)
      under `~nestrs:queue:*`, [the rate limiter](/rate-limiting/#redis-shipped)
      under `~nestrs:throttler:*` and [a schedule's claims](/schedule/#the-keys)
      under `~nestrs:schedule:*`; an app running several gives one user each rule.
      A dashboard or an ACL written for the rate limiter's 6.x keys
      follows it to `nestrs:throttler:buckets:*`.
    - **The rate limiter on Redis** counts each bucket under a pseudonym keyed by
      `<PREFIX>_THROTTLER__PSEUDONYM_KEY`: set it, the same 32 bytes or more on
      every replica, or the boot refuses. 6.x's buckets, named by the client's
      address, expire with their window; see
      [Redis, shipped](/rate-limiting/#redis-shipped).
    - **TLS**: `rediss://` is verified against the URL's host, and a Valkey whose
      certificate chains to an authority only Mozilla's roots held needs it in
      the system's store or in `<PREFIX>_REDIS__TLS_CA_CERT`;
      `TLS_CERT` and `TLS_KEY` name a client certificate, each with its `_FILE`
      form, and `#insecure` fails the boot — see the
      [Redis variables](/configuration/env-reference/#redis--prefix_redis__).
      Postgres connects with `sslmode=verify-full` unless `sslmode=disable` in the
      URL, or libpq's `PGSSLMODE=disable` beside a URL naming no mode, turns it
      off: `allow`, `prefer`, `require` and `verify-ca` fail the boot, naming
      `PGSSLMODE` where it set one, and a server without TLS needs one of those two
      written. An authority named in libpq's `PGSSLROOTCERT`, which 6.x read, moves to
      the URL's `sslrootcert`: the variable now stands behind the system's
      authorities, and a server only it vouches for fails the boot.
    - **Shutdown** ends within bounds you can read. HTTP stops waiting for open
      connections once `<PREFIX>_HTTP__SHUTDOWN_TIMEOUT_SECS` runs out, 20
      seconds by default, where 6.x waited for every one: a request still running
      is dropped unanswered and a download is cut, while a stream with no end of
      its own — an `#[sse]` stream, an MCP session's `GET` stream — ends at the
      signal, a gateway's WebSocket closes with `1001 Going Away` after the
      message it is answering, and a graphql-ws socket completes each
      subscription, then closes the same way. A socket a hand-built self-mount
      upgraded ends with its handler or the process; half a second more lets
      what it stopped unwind. The worker hands back what still runs before its
      drain window closes — **20 by default, down from 30**, read from
      `<PREFIX>_QUEUE__SHUTDOWN_TIMEOUT_SECS` where 6.x read
      `<PREFIX>_REDIS__WORKER__SHUTDOWN_TIMEOUT_SECS`: the window is the queue
      port's now, so it survives a backend swap. A running attempt gets all of it
      but a reserve of one connection budget, so 10 seconds by default to finish
      where 6.x let it run the whole 30. A scheduled tick still running gets 5
      seconds and is then stopped. The shutdown hooks — `OnModuleDestroy`,
      `BeforeApplicationShutdown`, `OnApplicationShutdown` — then share one
      5-second budget, OpenTelemetry's final flush takes 3 seconds at most, and
      the console's 1: **29.5 seconds**, inside the 30 Kubernetes grants by
      default. A window you widen — HTTP's or the worker's — needs
      `terminationGracePeriodSeconds` at least 9.5 seconds above it **plus any
      `preStop` delay**, which Kubernetes counts inside the grace; a worker pod
      you gave 45 seconds for the old 30-second drain can keep its drain and its
      grace, or drop both to the defaults. See
      [the way down](/fundamentals/shutdown/#the-way-down).
    - **Deregistration** is the platform's: on Kubernetes, give each serving
      container a `preStop` hook with the `sleep` action (Kubernetes 1.30 or
      later) and raise its grace by as much, since the HTTP transport stops
      accepting at the signal and Kubernetes removes the endpoint at the same
      time. See
      [leaving the load balancer first](/fundamentals/shutdown/#leaving-the-load-balancer-first).
    - **Operation lines say how each unit ended.** A request dropped at the
      window, or by a client that reset its connection, files its `http.request`
      line with `outcome="cancelled"` and no `status` or `bytes`, a handler that
      panics `outcome="panic"` with `status=500`, and a stream ended at the
      signal `outcome="cancelled"` beside its `status`; every other edge files
      both words too, and an MCP tool that answered `isError: true` files
      `outcome="error"`. The request line names its `path` template
      (`/posts/{id}`), not the path; a method outside RFC 9110's is `_OTHER`; a
      WebSocket event no handler serves is `_OTHER`; `user_agent`,
      `operation_name` and an MCP operation's name moved to the spans
      (`user_agent.original`, `graphql.operation.name`, `mcp.operation.name`). A
      root field files `graphql.field`, an operation `graphql.operation`, a
      lifecycle hook `lifecycle.hook`. A `5xx` is filed once, by the edge:
      `service error surfaced as 500` and `token request failed` read
      `request failed` / `request unavailable` on `nest_rs::http`, a handler's
      `503` at `warn`. See the table in [Logs](/opentelemetry/logs/).
    - **A span says `Error` for the server's own failure alone.** A `ws.message`,
      a `graphql.operation`, a `graphql.field` and a `graphql.subscription` record
      no `error.type` and no status for a failure their caller earned, as an HTTP
      `4xx` does not; their line still files `outcome="error"`. An alert counting
      those spans in `Error` reads the server's failures alone, and one meant to
      count every failure reads the line. No compile error says so.
    - **A library's own lines are clamped.** rmcp's, h2's, rustls's,
      tungstenite's, sqlx-postgres's and the OTLP exporter's lines are written
      only once `RUST_LOG` names the library (`info,rmcp=info`), and that
      directive writes what the library quotes; see
      [the libraries the framework wires](/opentelemetry/logs/#the-libraries-the-framework-wires).
    - **Every duration has a range**, checked at boot whether it comes from the
      environment or is pinned in code, and a value outside it fails the boot
      naming the variable — the [env-var reference](/configuration/env-reference/)
      gives each one. Where `0` is off it still is; in code, off is `None`, and
      a pinned `Some(Duration::ZERO)` fails the boot. A value 6.x accepted — a
      worker drain window of `0` or above an hour, a zero connect timeout or
      window, a token lifetime past thirty days, a connection ceiling past a day
      — has to move.
    - **Valkey 9.1, on one server, Sentinel or Cluster** — Redis is no longer a
      supported server, and the scheme of `<PREFIX>_REDIS__URL` declares the
      topology: `rediss://`, `rediss-sentinel://` or `rediss-cluster://` (see
      [Valkey topologies](/queue/topologies/)). Run `noeviction` on a server
      holding the rate limiter or the schedule, whose keys carry an expiry; a
      server holding the queue alone may run a `volatile-*` policy, never
      `allkeys-*`, which can evict a job — see
      [Eviction](/queue/topologies/#eviction).

18. **Drain each Redis queue's 6.x jobs.** 6.x kept a queue's jobs at the root of
    the keyspace; 7.0 keeps them on a stream under `nestrs:queue:{<queue>}` and
    reads nothing 6.x left, so keep the 6.x workers running until those keys are
    empty — [Upgrading queues from 6.x](/queue/upgrading/).

</Steps>

## What fails if you get it wrong

- **A GraphQL client leaving a required variable out**, `$id: ID!` with no default,
  reads `Variable "$id" of required type "ID!" was not provided.`, and the operation
  runs nothing: it used to run, `@skip(if: $x)` keeping its selection,
  `@include(if: $x)` dropping it, and an argument's root field alone failing. Send the
  variable, or declare it a default. A client relying on `@skip` or `@include` ignoring
  a default now reads what its document says.
- **A GraphQL client sending `null` for a variable its type declares Non-Null**,
  `$hint: String!` sent `null`, or `[1, null]` for `$ids: [ID!]`, reads
  `Variable "$hint" of non-null type "String!" must not be null.` (or `… must not hold
  null at "ids[1]".`), and the operation runs nothing: a nullable argument read the
  `null`, and a mutation ran its root fields. Declare the variable nullable, or send a
  value.
- **A GraphQL document selecting an object twice at one place, a directive leaving one
  selection nothing to answer**, `{ org { name @skip(if: true) } org { id } }`, reads an
  `INVALID_ARGUMENT` refusal and runs nothing: `org` answered `null` whenever that
  selection finished first. Put the directive on the selection itself,
  `org @skip(if: true) { name }`. An object every selection of which a directive leaves
  out answers `{}` at a Non-Null position, where it answered `null`.
- **A GraphQL document spreading its fragments again past `max_complexity`** reads `Query
  is too complex.` before anything walks it, a `__typename` at the end of them included,
  which was answered; so does one whose arguments copy or scan more than twice what the
  request may carry, `max_body_bytes` on a `POST` and `max_message_bytes` on a graphql-ws
  socket, a key repeated with thousands of arguments among them. `max_complexity: None`
  leaves a fragment's repeats at ten million. Spread less, or raise the limit, which also
  holds a score under one that its repeats pass.
- **A GraphQL subgraph whose guards identify no caller**, `federation: true` under a rate
  limit alone or no guard at all, fails the boot, where it served its SDL through `_service`
  to anyone. List a guard identifying the router, an authentication or authorization guard in
  `GlobalGuards` or an `EndpointGuards<GraphqlView, …>`, or, for a subgraph only its router
  reaches on a private network, open it: `federation_sdl: Surface::Open`
  (`<PREFIX>_GRAPHQL__FEDERATION_SDL=true`).
- **A GraphQL document whose fields below a list read more than 4 KiB of arguments**,
  which each row reads again, `query($v: String) { rows { f(x: $v) } }` with a large
  `$v`, reads `Query is too complex.` and runs nothing, where every row copied the value.
  Read the value once, on a root field or one only objects stand above, or raise
  `max_list_argument_bytes` (`<PREFIX>_GRAPHQL__MAX_LIST_ARGUMENT_BYTES`), `None` or `0`
  to turn it off.
- **A GraphQL document holding a fragment no operation spreads** reads `Fragment "F" is
  never used` for the first in its text alone, where validation listed each beside the
  document's other errors. It was refused either way.
- **A `Data` type a resolver reads off its `Context` and its request does not hold**
  answers the opaque internal error, the type filed at `error`, where the client read
  ``Data `…` does not exist.`` A loader read so whose owner the app does not import
  moves to a `&DataLoader<L>` parameter, and its boot says which import.
- **A guard declaring a status outside `400` to `599` in `denial_statuses`** refuses the
  boot, naming the guard and the status: list what its `Err` paths answer, an error each.
- **A `(StatusCode, Json<T>)` route whose `T` has no schema** does not compile (`E0277`), as a
  bare `Json<T>` route does not: derive it with `#[output]`.
- **A client generated from `/api-json`** reads `2XX` where it read `200` on a route whose
  status the handler computes, new responses on every operation, and a text or bytes body where
  it read none: a generated type naming `200` for one moves, or the route says
  `#[http_code(200)]` where its status never varies.
- **`McpSetup::from(x)`, `StaticFilesSetup::from(x)`, `OAuthResourceSetup::from(x)`, or
  `.into()` to one of them,** does not compile (`E0277`): a setup has one way in, so
  write `McpModule::for_root(x)`, which takes the same value.
- **A lone Redis binding over a seeded `RedisConnection`** now reads the
  `RedisConfig` of the module it imports, so a suite with `<PREFIX>_REDIS__URL`
  unset is refused naming the variable: seed the `RedisConfig` beside the
  connection.
- **An import of `Scoped` from an edge, of rmcp's macros or types from `nest_rs::mcp`'s
  root, an `McpIdentity` setter, of `wire_enum` from `nest_rs::resource`, or of an item
  through a module `nest_rs::core` or `nest_rs::social` no longer opens** fails to compile
  (`E0432`, `E0599`): steps 5 and 12 list each with what replaces it. `#[wire_enum(graphql)]`
  or `#[expose(..., graphql)]` without the `graphql` feature fails naming the feature to add.
- **An `McpIdentity` stating a name with no version behind it, or a version, a title, a
  description, a website or icons with no name behind them**, refuses the boot in a process no
  `#[nest_rs::main]` started, naming the literal to write; the binary fills both anywhere else.
- **A bare `#[interceptor]`, or `stage = handler`,** does not compile:
  ``#[interceptor] declares what a module brings around the guards and takes `stage = unit` ``,
  then where the other goes. `#[injectable]` on the struct and
  `GlobalInterceptors<(I,)>` in the providers of the module `main` boots (step 10);
  one that must see a refusal or a `404` is `#[interceptor(stage = unit)]`.
- **A type in a pool no decorator makes a provider** does not compile:
  `` `X` is not a provider a module or an app-wide pool can register ``, where the
  pool names it. `#[injectable]` on it, or a `Discoverable` impl.
- **A singleton provider of the root injecting a layer only a pool lists** fails the boot with
  `UnbuiltProviderError`: ``only an app-wide pool's declaration lists it … list it in
  `AppModule`'s `providers` ``. A module injecting one fails the access graph, naming the
  root as the owner: list the layer in a module both reach.
- **A pool naming a layer whose module the root does not import** boots now, where it
  was refused: the pool registers the layer as the root's, from what the root reaches.
  Import the module when you meant its provider and its configuration.
- **A suite calling `app.bearer(…)` on an app booted without
  `.ephemeral_signing_key()`** panics naming the builder call; 7.0's `bearer`
  signs with a key of the test's own, never the app's. The key on an app that
  provides no `JwtService`, or one whose `JwtService` the suite seeded, refuses
  the boot.
- **A binary whose `main` installs no exporter, run where the deployment sets
  `OTEL_EXPORTER_OTLP_ENDPOINT`** (or a signal's own endpoint) — a platform
  injecting it into every pod included — fails `App::run` before serving,
  naming the variable and the line to add: 6.x booted it and exported nothing.
  Add `let _otel = OpenTelemetry::init()?;` to `main`, or set
  `OTEL_SDK_DISABLED=true` where that binary exports nothing. A suite, which
  boots without `run`, is never refused.
- **A `.env` file or a deployment still setting `<PREFIX>_LOG`** filters
  nothing: the console logs at `info`, or at what `RUST_LOG` says, and says
  once at `warn` on `nest_rs::app` that the variable is read by nothing
  (`variable read by nothing since 7.0`, `read_as` naming `RUST_LOG`). Rename it
  `RUST_LOG` (step 3).
- **`nestrs g migration create_posts` — or `create_post` — after `nestrs g
  resource posts`** writes nothing: ``a migration creates the table `post`
  already: `crates/migrations/src/m…_create_posts.rs` ``. The resource wrote
  it; a change to the table takes a name of its own.
- **`nestrs g resource posts` after `nestrs g migration create_posts`** writes
  nothing either: the same sentence, then the two ways through — that
  migration removed with its two registrations, or the feature and its entity
  written alone.
- **A deployment still setting `<PREFIX>_OPENTELEMETRY__*`** exports nothing
  through it: `OpenTelemetry::init` names each such variable once at `warn` on
  `nest_rs::opentelemetry` (`variable read by nothing since 7.0`, `read_as`
  naming the specification's variable that replaced it). Set the `OTEL_*` of
  step 3.
  An `OTEL_EXPORTER_OTLP_PROTOCOL` other than `http/protobuf` fails the boot
  naming it.
- **An `OTEL_TRACES_EXPORTER`, `OTEL_METRICS_EXPORTER` or `OTEL_LOGS_EXPORTER`
  naming an exporter nestrs does not build** — `console`, `zipkin`,
  `prometheus`, a misspelling — fails `OpenTelemetry::init` with `invalid value
  for OTEL_TRACES_EXPORTER: must name otlp, …`, naming the variable and never
  its value; so do `none` beside `otlp`, `otlp` named for a signal no
  endpoint reaches, and, in a binary built without the `otlp` feature, any
  value but `none`. 6.x read none of them: a deployment that set one for
  another service's sake unsets it, or sets `none`. `none` and
  `OTEL_SDK_DISABLED=true` are honoured, so a signal they switch off exports
  nothing, and the boot line says `off (OTEL_TRACES_EXPORTER=none)`.
- **An OpenTelemetry variable nestrs cannot honour** fails `OpenTelemetry::init`
  naming it and never its value: `OTEL_EXPORTER_OTLP_COMPRESSION` other than
  `gzip` or `none` (`zstd` included), `OTEL_PROPAGATORS` other than
  `tracecontext,baggage` (`b3`, `jaeger`, `none`, or one of the two alone),
  `OTEL_TRACES_SAMPLER` naming a sampler the SDK does not build (`xray`,
  `jaeger_remote`, a name not in lowercase), `OTEL_TRACES_SAMPLER_ARG` outside
  0 to 1, an `OTEL_EXPORTER_OTLP_METRICS_TEMPORALITY_PREFERENCE` other than
  `cumulative`, `delta` or `lowmemory`, and `OTEL_CONFIG_FILE`. 6.x read none
  of them: unset it, or set what the sentence accepts.
- **`OTEL_EXPORTER_OTLP_HEADERS` beside an `http://` endpoint on another
  host** fails the boot naming both variables, since the collector's
  credential would cross the network in clear; so does such an endpoint
  carrying a query, naming the variable that set it. Export over
  `https://`, or to a collector on loopback (`localhost`, `127.0.0.1`,
  `[::1]`), which keeps receiving both, dialled past any proxy the
  environment names.
- **A number the SDK reads that is not a whole number** — an
  `OTEL_BSP_*` or `OTEL_BLRP_*` setting (digits alone, as the SDK reads

- **A site gated on `Manage`** — `#[authorize(Manage, E)]`, `#[public(Manage, E)]`,

- **A token carrying `cnf`** is refused, `401 invalid_token`, reason
  `sender_constrained`, where it passed as a bearer with no proof of the key it is
  bound to. An external issuer minting bound tokens mints this audience plain ones.

  — a space, a `"`, an empty string — fails the boot on `clients[<id>].scopes`, where
  `"a b"` was granted whole when no scope was asked and refused when asked by name.
  List the two scopes.
- **`<PREFIX>_OAUTH__CLIENT__SCOPES`, `<PREFIX>_SOCIAL__GITHUB__SCOPES` or

- **A `.fields` on `Update`, `Create` or `Manage`** now holds a write to its list. A write
  setting another column answers `403`, `FORBIDDEN`, where it wrote the column: under `errors`

- **`Repo::update` of an active model setting nothing** answers `DbErr::RecordNotUpdated`, a

  reads with `Repo::find_by_id`.
- **`cannot(..).requires_scope(..)` or `cannot(..).fields(..)`** no longer

  found `RuleSpec<'_, E, Cannot>`).
- **`nest_rs::database::with_request_executor` or `with_job_executor`** no
  longer resolves (`E0425`), nor does an `Ability` passed to `with_ambient` or

  service test through `app.unit(ability, || …)` or `app.system_unit(|| …)`,

- **A job unit opened inside a request** — `run_unit` with
  `ExecutorScope::Job` — or work a job captured and a request re-enters runs
  as the request: with no ability its `Repo` reads match no row, at the same
  `warn`. System work runs in a queue attempt or a tick of its own.
- **A stale or mangled page cursor** — an `after` no page issued — is refused
  where 6.x served the first page: a `#[crud]` list answers `400`, its problem
  ``query parameter `after`: not a cursor this endpoint issued`` under
  `INVALID_ARGUMENT`, and GraphQL a field error, `Invalid value for argument
  "after", not a cursor this endpoint issued`. Neither quotes the cursor; an
  empty `after` is still the first page. Follow the `Link` header's `next`.
- **A health probe or dashboard keyed on `db` or `db_ready`** reads nothing:
  the key is `seaorm`, beside `redis[:<instance>]` and `storage`. A readiness
  method named `seaorm`, `redis` or `storage` in an app that opens that
  resource fails the boot.
- **An import of `SeaOrmHealthModule`** fails to compile, rustc naming the
  item `nest_rs::seaorm` no longer has, as does one of `RedisHealthModule` or
  `StorageHealthModule`. Delete the import: the module opening each resource

- **A replica out of rotation while its database, a Valkey or the store is
  down** — where 6.x kept it serving, unless `SeaOrmHealthModule` checked the
  pool — is that resource's check: an app importing `HealthModule` checks every
  resource it or its features open (step 11). The `503`'s `error` names it:
  `seaorm`, `redis[:<instance>]` or `storage`.
- **A log query on a renamed line or field** finds nothing: the 6.x line
  `shutdown signal received` is `app draining`, `transport listening` at `info`
  is `app ready`, `running lifecycle hook` is the `lifecycle.hook` line, a
  WebSocket deadline's `message_timeout_secs` is `timeout_ms`, `cause="framework"`
  or `cause="another_app"` is `cause="dependency"`, and an authentication line's

- **A tool that scrapes stderr for `panicked at`** finds nothing under
  `#[nest_rs::main]`: read the `error` events on `nest_rs::app`, or the unit's
  own line for a panic it contains.
- **A secret field given a `String`** fails to compile, `expected Secret<String>,
  found String`, and one read as a string `no method named … found for struct
  Secret`: add `.into()`, or read it with `.expose_secret()`. An `#[expose]` left

  which never crosses the wire``.
- **A serde derive left on an `#[expose]`d entity** fails to compile at the
  derive: ``#[expose]: `Model` derives `Serialize`, which writes every column,

  decorator**, fails with `E0119`, `conflicting implementations of trait
  Serialize for type Model`, its note naming `AModelCrossesNoWire`: the same goes

**At boot, the refusals not named above**, each a sentence ending on its remedy:

- **Two factories waiting on each other** fail the boot with `FactoryCycleError`:
  `factory cycle: … — each waits on a factory output that a member of this set …
  would provide`. Drop one `_after` declaration.
- **A module imported in a `collect` alone**, the shape a hand-written `impl Module`
  takes, fails with `UnregisteredModuleError`: `` `…` was imported in a collect phase
  alone, so none of its providers registered``. Import it through
  `ContainerBuilder::import` in its importer's `register` too.
- **A factory queued in `register`, or a seed its module's check refuses**, answers
  `ContainerError::LateFactory` or `ContainerError::SeedRefused` from a container built by
  hand: queue it in `collect`, and seed a value that passes the check a read one passes.
- **A transport of your own stating a stop bound past a day** fails with
  `UnboundedTransportError`: `a transport's stop is bounded: declare its drain window`.
- **`App::init` or `App::run` called again after an init that failed** answers
  `InitFailedError`, `the app's init failed earlier: it does not run again`: build a new
  app.
- **A resource's budget at or past the net of a port waiting on it** fails with
  `BudgetPastNetError`: ``…'s budget (…) must be shorter than …'s net (…)``, naming the
  setting to lower.
- **One variable read by two configuration types** fails with `ConfigError::ContestedVariable`:
  `` `…` is read by two configuration types``. Give one its own key or namespace.
- **A named instance reading a namespace another declaration holds** fails with
  `ConfigError::SharedInstance`: ``the instance `…` reads the namespace `…`, which … also
  claims``. Rename the instance.
- **A `ClientTls` or other shared vocabulary under a field of another name** fails with
  `ConfigError::MisnamedField`, ``name the field `…` ``: its refusals name its variables by
  that field's key.
- **A duration read through a `ConfigService` reader** fails with
  `ConfigError::UnboundedDuration`: `` … is a duration, and a duration is read through the
  `DurationBounds` its field names``. Declare the field with `#[config(bounds = …)]`.
- **A Redis URL asking for RESP3 (`protocol=resp3`)** fails the boot naming the variable to
  remove it from: nestrs does not speak RESP3 to Redis.
- **A queue lease not above one and a half times the Redis budget** fails the boot: ``the
  Redis queue lease (…) must be more than one and a half times the Redis budget (…)``, since a
  renewal sent a third into the lease may wait out the whole budget. Raise the lease or lower
  the budget.
- **`replicas = "one"` with no occurrence lock bound** fails the boot naming the job: import
  `RedisScheduleModule`. A job attached by hand as a `CronJobMeta` fails it too for a `key`
  without `replicas = "one"`, or a one-shot declaring it, the two mistakes a decorator refuses
  at compile time.
- **Two scheduled jobs sharing one name** fail the boot (`scheduled jobs share one name: …`):
  rename one host, or fold the two methods. **Two jobs firing once under one identity** fail
  it too (`scheduled jobs firing once claim under one identity: …`): give each its own `key`.
- **A `#[process]` declaration its backend cannot honour, a throttle window under a
  millisecond, or two methods draining one queue** fail the boot, one error naming every
  offender at once.
- **`memory:///` in a deployed or undeclared profile** fails the boot: `names memory, a store
  in this process that loses every object at a restart`. Name an `s3://` store. **An S3 setting
  beside `memory:///`** fails it too (`is set beside …, which names memory`): unset it.
- **A GraphQL schema keying an entity without `GraphqlConfig::federation`** fails the boot:
  `` `…` keys an entity … but this schema is not configured as a subgraph``. Set
  `<PREFIX>_GRAPHQL__FEDERATION=true` and serve it behind the router it names, or drop the key.
- **An `McpIdentity` naming a server no `#[mcp]` host serves** fails the boot, as do two hosts
  on one path declaring one prompt.
- **`HttpTransport::from_config` refuses values a transport built in code passed**: a duration
  or a `version_header` outside what its variable accepts, naming the variable and the field; a
  body-read gap at or past the request timeout files one boot `warn`.
- **A protected resource's URI carrying userinfo**, or loopback `http` in production, fails the
  boot.
- **A refused credential or a missing database fails the boot**, where the first request met
  it: the sentence names the resource and the variable.

**At run time, what now answers differently:**

- **An MCP session an earlier release stored** is refused: the client opens a new one. A
  session stays its principal's, and a principal naming no subject answers `403`.
- **The app's interceptors and exception filters now run around every job, tick, listener
  call, GraphQL root field, MCP operation and WebSocket message**, and the class gate runs
  before a message's pipes. One written for a request reads the edge from `cx.edge()`.
- **A `Result` renamed on import or behind an alias fails as a `Result` does**, on the line and
  to the client, where its error reached the client as data and its line filed `ok`.
- **`/graphql/anything` answers `404`**, and the graphql-ws handshake's `HEAD` answers `400`.
  Point a client at `/graphql` itself.
- **A `Path<T>` signature mistake answers `500`**, where it answered `400`: a route template's
  parameters and the handler's type are a programmer's, never a client's.
- **A statement past 15 s is cancelled by Postgres**, answering `503` with its wait. A long
  report raises `<PREFIX>_SEAORM__STATEMENT_TIMEOUT_SECS`, or runs as a job with its own `timeout`.
- **The OAuth client refuses a plain `http` endpoint**, and an answer past 64 KiB fails as the
  provider's.
- **`requiredScopes`, and a challenge's `scope`**, name the narrowest grant's scopes alone: a
  client reading the whole list reads that one.
- **A fall-back day fires more** under a zone that repeats the hour: read a daily job's `#[cron]`
  beside the zone.
- **A suite logs what its console allows**: `with_test_telemetry` kept it to `warn`, and a
  project scaffolded before sets `RUST_LOG=warn` in `.env.test`, as `nestrs new` now writes.

  `#[inject]`; an instance with fields, generics, a reserved word or the name `Unnamed`; a subject with
  fields, generics or arguments, or a rule that denies or narrows it (`has no rows to deny or
  narrow`); a claims type with no `actor`, or two; `main` on a sync function.
