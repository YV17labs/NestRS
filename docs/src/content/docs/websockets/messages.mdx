Every frame in and out of a gateway rides one shape:

```json
{ "event": "history", "data": [{ "author": "ada", "text": "hi" }] }
```

`event` is a string, `data` is whatever JSON the handler asks for.
That's it — no separate ack channel, no second protocol for errors,
no per-event wire format to negotiate. One envelope handles
fire-and-forget, request/response, server pushes, and error replies.

The envelope is a JSON object, and only an object: an array is never read
by position, so `["message", {…}]` is no `message`. A frame that is no
envelope is answered on the `error` event, saying where it failed, or what
kind of value it was and what was expected, and never what it held:

```json
{ "event": "error", "data": { "error": "invalid envelope at `event`: missing", "code": "INVALID_ARGUMENT" } }
{ "event": "error", "data": { "error": "invalid envelope: invalid type: a sequence, expected an object with `event` and `data`", "code": "INVALID_ARGUMENT" } }
```

A message past `max_message_bytes` closes the socket `1009 Message Too Big`, at
the protocol layer, before anything reads it. A binary frame carries no
envelope, and a text frame that layer let through at the boundary is not read:
each is answered on the `error` event under the class HTTP names for the same
refusal, as RFC 6455's close codes 1003 and 1009 name it:

```json
{ "event": "error", "data": { "error": "binary frames are not supported", "code": "UNSUPPORTED_MEDIA_TYPE" } }
{ "event": "error", "data": { "error": "message too large", "code": "CONTENT_TOO_LARGE" } }
```

Each is a message all the same: its `ws.message` line files `outcome="error"`
under `event="_OTHER"`, since no handler declared what it named. An event no
handler serves is answered on the event it sent, `unknown event` under the
`NOT_FOUND` class.

What a route's `404` runs, each of these runs too: the
[unit stage](/fundamentals/interceptors/) and the app's exception filters, around
that answer and under the message's deadline, so an audit interceptor reads the
frame that goes out and a catch-all shapes it. Nothing there is a handler's, so no
guard, no handler-stage interceptor and no unit of work run, nor what the gateway
binds for its messages. A layer reads `_OTHER` as the event, never the client's
word.

## A handler signature

`#[subscribe_message("event")]` binds a method to that event name in the
envelope:

```rust title="crates/features/src/chat/ws/gateway.rs"
#[messages]
impl ChatGateway {
    #[subscribe_message("message")]
    async fn on_message(&self, msg: SendMessageDto) -> ChatMessageDto {
        self.svc.record(msg)
    }
}
```

The macro reads five things from the signature:

- **The event name** — the literal in `#[subscribe_message(...)]`.
- **The payload type** — the one argument that is neither `&WsClient`, a
  `Scoped<T>` nor an `Ambient<T>`. Deserialized from `envelope.data` with `serde`.
- **The request-scoped providers** — each `Scoped<T>` argument, resolved from
  the message's own scope (below).
- **What a guard attached** — each `Ambient<T>` argument, read from what the
  upgrade's guards and the message's own attached, as a route reads it; a
  `#[public]` message reading the principal a guard of its chain produces
  refuses a caller that guard did not identify `UNAUTHENTICATED`.
- **The return type** — drives the reply, per the contract below.

A `&WsClient` parameter is the [per-connection handle](/websockets/rooms/);
it can appear in any position alongside the payload. The macro tells the four
apart by their shape — a reference, a type named `Scoped`, a type named
`Ambient`, anything else — since it reads tokens, not types; a `Scoped` or an `Ambient`
of another crate does not compile.

### Request-scoped providers

A message is a request of its own: an `#[injectable(scope = request)]` provider
is built once per message and shared by everything that message runs, and a
handler takes it as a parameter:

```rust title="crates/features/src/chat/ws/gateway.rs"
use nest_rs::core::Scoped;

#[subscribe_message("seq")]
async fn seq(&self, seq: Scoped<RequestSeq>) -> u64 {
    seq.value()
}
```

`Scoped<T>` is part of the boot's access contract, as an `#[inject]` field is:
a `T` no module the gateway's module imports offers fails the boot, naming it.
With no request-scoped provider anywhere in the app, every message shares one
scope, which has nothing to build.

## A message's posture

A message takes HTTP's grammar, because a socket authenticates where a route
does, before any message runs. A message under its gateway's `#[use_guards]`, the
app's pool or a guard of its own **needs no posture**: the guards decide, as they
do on a route. Where it declares who may call it beyond them, it does so with
`#[authorize]`:

```rust title="crates/features/src/chat/ws/gateway.rs"
#[gateway(path = "/ws")]
#[use_guards(AuthnGuard, AuthzGuard)]
pub struct ChatGateway { /* ... */ }

#[messages]
impl ChatGateway {
    #[subscribe_message("history")]    // covered by the upgrade's guards
    async fn history(&self) -> Vec<ChatMessageDto> { /* ... */ }

    #[subscribe_message("message")]
    #[authorize(Create, Posting)]      // a gate, on a capability no table holds
    async fn on_message(&self, msg: SendMessageDto) -> Result<(), WsError> { /* ... */ }

    #[subscribe_message("users.list")]
    #[authorize(Read, users::Entity)]  // class gate + reply mask, both emitted
    async fn list(&self) -> Result<Vec<User>, ServiceError> {
        Ok(self.svc.list().await?.iter().map(User::from).collect())
    }
}
```

**The boot reads the rest.** A message no guard identifying a caller covers says
`#[public]` or fails the boot, which names every such message on the gateway and each
remedy; a macro reading an `impl` cannot see the app's pool, so this is where it can
be said. A rate limit identifies no one, so it covers nothing, and a guard of your own
declaring no `phase()` is read the same way. A gateway running no such guard at its
upgrade and with no `#[public]` message fails the same way, whatever guards its
messages bind: a message's guard runs on that message, while any caller connects, its
hooks run and what the server emits reaches the socket.

**`#[public]` means a caller with no credential is admitted**, the word's one
meaning on every edge. It is the line a gateway open on purpose writes, and a
reviewer greps for:

```rust title="crates/features/src/ticker/ws/gateway.rs"
#[gateway(path = "/ticker")]
pub struct TickerGateway;

#[messages]
impl TickerGateway {
    #[subscribe_message("latest")]
    #[public]
    async fn latest(&self) -> Price { /* ... */ }
}
```

Behind an upgrade whose guards establish or read who the caller is, one declaring
`GuardPhase::Authentication` or `Authorization`, no visitor ever reaches the
message, so `#[public]` could open nothing, and the boot refuses it, naming the
guard. A guard of the app's pool runs at every upgrade, so a gateway opens beneath
it only by moving that guard onto the hosts it should cover. A guard that identifies
no one — a rate limit — leaves it standing: a visitor does reach the message, and the
word is true.

**A bare `#[public]` reads nothing a grant guards.** A ticker keeps the bare word and
pays nothing for it. A message serving rows to a visitor names them, with
`#[authorize]`'s arguments and its mask:

```rust title="crates/features/src/posts/ws/gateway.rs"
#[gateway(path = "/feed")]
pub struct FeedGateway;

#[messages]
impl FeedGateway {
    #[subscribe_message("latest")]
    #[public(Read, post::Entity)]
    #[use_guards(AuthzGuard)]
    async fn latest(&self) -> Result<Vec<Post>, WsError> { /* ... */ }
}
```

The guard beside it builds the rules
[`define_visitor`](/security/authorization/public-reads/) writes, since no ability
reached a message under an upgrade no guard ran at: those rules answer every caller
of such a socket.

**`#[authorize(Action, Entity)]` emits two things you would otherwise
write by hand.** Right after the message's guards, before any interceptor,
exception filter or pipe, a class-level gate asks the caller's ambient
`Ability` whether it may perform `Action` on `Entity`; a refusal is an error
frame and nothing else runs. After the handler returns, the reply is masked —
rows the ability refuses are dropped, columns a field grant withholds are
stripped. **You write no masking call**, and the mask reads the reply by its type,
as the frame does: a bare value, a `Result` and a `Result` behind an alias
(`type ServiceResult<T> = Result<T, MyError>`) all mask the value they answer.

### What the mask does, and what it does not

The mask acts on the **serialized** reply. A withheld column is
absent from the frame — the same thing the HTTP response shaper does to a
body, because a WS envelope promises no schema that a missing key would
violate. This is where WebSockets differ from GraphQL and MCP, which
reconstruct the operation's return type and fail the operation when a
stripped key was required.

Two cases stay fail-closed, and both are wiring or data faults rather
than policy: **no ambient ability** (nothing decided what the caller may
read; a gated message no ability guard reaches refuses the boot, so this is
the last line behind that refusal), and a body that cannot be reconciled with
the entity at all. Both answer an error frame and log a `warn` on
`nest_rs::authz`.

The reply is what the handler read through `Repo` under the caller's
ability, so a rule the frame cannot show — a relation, a hidden column — is
the read's to have decided. A frame pushed to *other* connections is not a
reply and is not masked for them; see
[Server-side push](/websockets/server-push/#a-push-is-not-masked).

## The payload

Whatever you put in `data` arrives in your handler typed, and held to the
rules its type declares. The macro decodes it through the edge's own reader under the
hood:

```rust title="crates/features/src/chat/ws/gateway.rs"
#[input]
struct SendMessageDto {
    text: String,
}

#[subscribe_message("message")]
async fn on_message(&self, msg: SendMessageDto) { /* ... */ }
```

The payload carries what the client decides, and nothing the server
already knows: who sent the message is the caller the upgrade authenticated,
read as an `Ambient<Claims>` parameter, never an `author` field the client could
fill with someone else's name. `#[input]` refuses a field the
type does not declare, so such a payload is an error frame.

A malformed payload (wrong shape, missing fields) is treated as a
dispatch error: the connection stays open, the client receives an error
frame on the same event name (see below), naming where the payload failed
and never its value — ``invalid payload for `message` at `text`: missing``. A
payload type declaring `validator` rules is held to them as it decodes, and a
custom transform binds a [pipe](/fundamentals/pipes/) on the payload argument,
`Piped<P>` — either rejection is an error frame, and the handler body never
runs.

```rust title="crates/features/src/chat/ws/gateway.rs"
#[subscribe_message("trim")]
async fn trim_handler(&self, Piped(name): Piped<Trim>) -> String {
    name
}
```

A handler that takes no payload accepts `null` or a missing `data` key
— the envelope defaults `data` to `null` on deserialize:

```rust title="crates/features/src/chat/ws/gateway.rs"
#[subscribe_message("history")]
async fn history(&self) -> Vec<ChatMessageDto> {
    self.svc.history()
}
```

```text frame="terminal"
> {"event":"history","data":null}
< {"event":"history","data":[{"author":"ada","text":"hi"}]}
```

## The return contract

The handler's return type picks the reply behavior, read by the type itself:

| Return type | Wire effect |
|---|---|
| `()` | No reply frame. Fire-and-forget. |
| `T` | One frame: `{"event":"<event>","data":<T serialized>}`. |
| `Result<(), E>` | `Ok(())` → silent. `Err(e)` → error frame (see below). |
| `Result<T, E>` | `Ok(t)` → reply with `t`. `Err(e)` → error frame. |

The error frame is shaped like any other envelope:

```json
{ "event": "send", "data": { "error": "text must not be empty" } }
```

What it says is decided by the error's **type**, so a client reads only what
someone meant it to read:

- a `WsError` is sent whole — `WsError::new("text must not be empty")`, or a
  `String` through `?` into a `Result<T, WsError>`;
- an error implementing `ToProblem` answers the problem it says: its sentence,
  and its code beside it (`"code": "CONFLICT"`, plus `type` and `title` when it
  names a problem type of its own, `retryAfterSeconds` when it names a wait
  and `errors` when it carries a field map); `ServiceError` is one;
- the framework's own vocabulary found in the chain — a `Problem`, a pipe
  rejection, a decode failure said without its value
  (`invalid type: a string, expected u64 at line 1 column 24`) — answers in its
  own form, a decode failure under `code: "INVALID_ARGUMENT"` as a payload or
  an envelope that does not decode does;
- **anything else answers `"internal error"`** under `code: "INTERNAL"`, and
  its whole chain is filed once at `error` on `nest_rs::ws`.

That opaque frame is one shape whoever answered it — an unknown error, a
`ToProblem` saying `None`, `.opaque()`, a panic, a request-scoped provider the
message cannot reach:

```json
{ "event": "send", "data": { "error": "internal error", "code": "INTERNAL" } }
```

Every error frame the framework writes says its class in `data.code`, beside
`error`, with what a client acts on next to it: `reason` and `requiredScopes`
for a guard's denial, `retryAfterSeconds` for a wait. A frame a handler builds
itself with `WsError::new` carries no class, as a GraphQL `Error::new` carries
none.

A rejection that carries **structured** detail adds an `errors` member beside
its class — a payload breaking its type's rules names the offending fields,
the same way the HTTP body does:

```json
{
  "event": "validated",
  "data": {
    "error": "invalid payload for `validated`: validation failed",
    "code": "INVALID_ARGUMENT",
    "errors": {
      "text": [{ "code": "length", "message": "text must not be empty" }]
    }
  }
}
```

`errors` is the field map and nothing else, on every edge: the class a client
branches on is `data.code`, as HTTP's problem document carries `code` beside
its `errors`. A pipe's rejection with no field map is its sentence and
`"code": "INVALID_ARGUMENT"` alone.

Each entry is `{ code }`, with a `message` when the `#[validate]` rule sets
one. A rule's parameters never ride along — they can hold the rejected
**value**, so a too-short password never rides back out — and a client keys
its sentence on `code`.

`errors` is **absent**, not `null`, when the failure had nothing structured to
say, so a client can branch on its presence. Every refused dispatch files its
`ws.message` line `outcome="error"`, so a denied dispatch shows up in logs
without extra instrumentation, and says why beside it. What the gateway refuses
of what the client sent — a frame that is no envelope, a payload that does not
deserialize, a pipe rejection, an unknown event — is reported at `debug` on
`nest_rs::ws`, where it failed included: a client can send one per frame, and
none is a denial. A handler's `Err` answered as a refusal — its `WsError`, a
`4xx` problem, a pipe rejection, a decode failure — is the client's error too.
The message's line files it, with nothing beside it, as HTTP files a `4xx` on
its access line alone. A guard's denial is filed at `warn` on the guard's
target, `nest_rs::layers` when it declares none. An opaque failure is filed at `error` on `nest_rs::ws`
(`websocket message failed`), as is the chain behind a `5xx` problem. The
chain behind a `503`, the server unable to answer in time, is filed at `warn`
(`websocket message unavailable`). A handler's `Err` is filed once its answer
is final, by the status that answer says, whoever gave it: an
[exception filter](#interceptors-filters-and-pipes) that answers it as a
refusal files nothing, and one answering a `5xx` files the chain it withholds.

A type **alias** over `Result` behaves the same. `pub type ServiceResult<T> =
Result<T, MyError>` produces the identical error frame and the identical
line: the decision is made on the type, so however the return is spelled,
an `Err` never reaches the reply `data`.

<Aside type="caution" title="`Opaque` says it at the call site">
An error with no `ToProblem` is already answered opaquely, and one with it answers
its class: return a `ServiceError` and a cancelled statement reaches the client as
`UNAVAILABLE`. When a failure has no word for the client, say so where it happens:

```rust title="crates/features/src/chat/ws/gateway.rs (from the demo, abridged)"
#[subscribe_message("message")]
#[authorize(Create, Posting)]
async fn on_message(
    &self,
    caller: Ambient<Claims>,
    message: SendMessageDto,
) -> Result<(), WsError> {
    self.svc.record(caller.into_inner().sub, message).opaque()?;
    Ok(())
}
```

`.opaque()?` logs the real error at `error` on `nest_rs::ws` — the operator
loses nothing — and hands the client a constant. The same trait exists on
GraphQL and MCP, spelled the same way. A rejection the client *can* act on
is the opposite case and travels as itself.
</Aside>

## Three handler patterns

**Fire-and-forget** — record state, broadcast a derived event later,
no reply to the sender:

```rust title="crates/features/src/chat/ws/gateway.rs"
#[subscribe_message("typing")]
async fn typing(&self, msg: SendMessageDto, client: &WsClient) -> Result<(), WsError> {
    client.broadcast("typing", &msg).opaque()?;
    Ok(())
}
```

The handler answers `Ok(())`, so no envelope flows back to the sender on
this event. The `client.broadcast(...)` call pushes a server→client
event on a different event name — see [Rooms](/websockets/rooms/).

**Request/response** — the client asks, the server answers on the same
event:

```rust title="crates/features/src/chat/ws/gateway.rs"
#[subscribe_message("presence")]
async fn presence(&self) -> usize {
    self.svc.present()
}
```

```text frame="terminal"
> {"event":"presence","data":null}
< {"event":"presence","data":1}
```

The return value is serialized straight into `data`. Clients
correlate by event name; if you need multiple in-flight requests of the
same kind, include an `id` field in the payload and echo it in the
response.

**Explicit failure** — the operation can fail and the client needs to
see why, so the error says what the client may read through `ToProblem`:

```rust title="crates/features/src/chat/ws/gateway.rs"
use nest_rs::core::{Problem, ToProblem, code};

#[derive(thiserror::Error, Debug)]
enum SendError {
    #[error("text must not be empty")]
    Empty,
    #[error("rate limited")]
    RateLimit,
}

impl ToProblem for SendError {
    fn to_problem(&self) -> Option<Problem> {
        Some(match self {
            Self::Empty => Problem::new(422, code::INVALID_ARGUMENT)
                .with_detail("text must not be empty"),
            Self::RateLimit => Problem::new(429, code::RATE_LIMITED),
        })
    }
}

#[subscribe_message("send")]
async fn send(&self, msg: SendMessageDto) -> Result<ChatMessageDto, SendError> {
    if msg.text.is_empty() {
        return Err(SendError::Empty);
    }
    Ok(self.svc.record(msg))
}
```

```text frame="terminal"
> {"event":"send","data":{"text":""}}
< {"event":"send","data":{"error":"text must not be empty","code":"INVALID_ARGUMENT"}}
```

Without the `ToProblem` impl the same `Err` answers `"internal error"` under
`code: "INTERNAL"`: an error's `Display` is never what decides. The wire shape stays the same
envelope — clients branch on the presence of `data.error`, on `data.code` for
the class, and read the field entries under `data.errors` when they need to
point at a field.

## Interceptors, filters and pipes

A message runs through the same [pipeline](/fundamentals/interceptors/) a route
does, outermost first: the unit stage (`#[interceptor(stage = unit)]`), the
guard stage — the app's pool, the message's `#[use_guards]`, then the class
gate its posture declares — the exception filters (the message's, the
gateway's, the app's), the handler stage (the app's interceptors, the
gateway's, the message's), and last the message itself: its data pipes, its
payload's own pipe, the call and the mask.

Bound on the `#[gateway]` struct, a layer runs around every message of the
gateway; bound beside a `#[subscribe_message]`, around that one. Each runs once
per message, whichever scopes list it:

```rust title="crates/features/src/catalog/ws/gateway.rs"
use std::sync::Arc;

use nest_rs::ws::{gateway, messages};

#[gateway(path = "/ws/catalog")]
#[use_guards(AuthnGuard)]
#[use_interceptors(Timing)]
#[use_exception_filters(OutOfStockFilter)]
pub struct CatalogGateway {
    #[inject]
    svc: Arc<CatalogService>,
}

#[messages]
impl CatalogGateway {
    #[subscribe_message("buy")]
    #[use_pipes(StripUnknownFields)]
    async fn buy(&self, order: OrderDto) -> Result<ReceiptDto, OutOfStock> {
        self.svc.buy(order).await
    }
}
```

An exception filter reads the handler's error by its type and answers the
client in place of the frame the error would have answered — a
`Caught::Problem` as `{ "error": …, "code": … }`, or a reply it
writes through `WsView::respond`. The message still failed, so whatever it
wrote rolls back, and [its span](/opentelemetry/logs/) still says who failed. An
interceptor reads the message through `WsView` — its
connection, its event, its `data` — and the reply once the rest of the message
ran; one may answer the message itself with `WsView::respond` and skip the
rest.

The [global pipes](/fundamentals/global-pipes/) the app lists fold over every
message's `data`, after its guards and its gate; `#[use_pipes]` adds pipes for
one gateway or one message, each once. A rejection is an error frame, as a
payload's own pipe's is.

The connection hooks run no layer yet: `#[use_interceptors]` and
`#[use_exception_filters]` beside `#[on_connect]` are named compile errors, as
are a guard (the upgrade's guards admitted the socket), a pipe (a hook has no
payload), a `#[meta]` value (no layer would read it) and a posture (no mask shapes
what a hook sends, so it reads nothing a grant guards).

## The envelope itself

If you ever need to build or parse a frame by hand (a custom adapter,
a test harness), `nest_rs::ws::WsEnvelope` is the canonical shape:

```rust title="nest_rs::ws::WsEnvelope"
use nest_rs::ws::WsEnvelope;

let frame = WsEnvelope::encode("ping", &"pong")?;
let parsed: WsEnvelope = serde_json::from_str(&frame)?;
assert_eq!(parsed.event, "ping");
```

A missing `data` key decodes to `serde_json::Value::Null`, so older
clients sending bare `{"event":"ping"}` still hit handlers that take no
payload. Only an object decodes: `serde_json::from_str::<WsEnvelope>` refuses
an array as it refuses a string, rather than reading its items as the
fields.
